MULTIROUTE DOWNLOADER 4.2.0 — API ДЛЯ СТОРОННИХ ПРИЛОЖЕНИЙ
==================================================

1. АДРЕС И ЗАПУСК

Базовый адрес: http://127.0.0.1:8765/api/v1
Формат запросов и ответов: JSON, UTF-8.
Заголовок для запросов с телом: Content-Type: application/json.
Токен для создания и управления загрузками не требуется.

Приложение должно быть запущено.

Native-установщик 4.1.1: запустите MultiRoute Downloader через обычный ярлык.
API работает вместе с окном. Примеры Start-Windows.cmd ниже относятся к
portable-версии; это не команда запуска native-установки.
 Обычный Start-Windows.cmd запускает окно
и API. Для работы только API выполните из папки приложения:

    Start-Windows.cmd --headless

Проверка работы:

    GET http://127.0.0.1:8765/api/v1/health

Ожидаемый ответ:

    {"ok": true, "version": "4.1.1"}

Смена порта:

    Start-Windows.cmd --headless --port 8766

API доступен только на том же компьютере. Он подходит для локального
скрипта, сервиса или настольного приложения. Другой компьютер в LAN
напрямую подключиться к этому API не сможет. Запросы из веб-страницы
другого origin отклоняются; браузерная интеграция требует локального
серверного посредника. API не является веб-интерфейсом приложения.

2. ШЛЮЗЫ

В интерфейсе по умолчанию выбраны все четыре шлюза:

    192.168.1.1
    192.168.1.2
    192.168.1.3
    192.168.1.4

Пользователь может добавить или удалить шлюзы (от 1 до 32), изменить их IP
и выбрать один, несколько или все шлюзы. Четыре адреса выше — начальные настройки.
Новый ручной выбор сохраняется между запусками. Системное подключение
не добавляется как пятый шлюз.

В API шлюзы задания задаются явно в routes. Выбор галочек в интерфейсе
не подставляется автоматически в запрос стороннего приложения.
Для скачивания через все четыре передайте четыре элемента, как ниже.
Для одного или нескольких оставьте только нужные элементы routes.
Каждому выбранному элементу обязательно укажите enabled: true.
Адрес локального прокси, worker и токен указывать не нужно.

Текущие настройки виртуального адреса и шлюзов:

    GET /network

Если сеть ещё не настроена, можно настроить её в окне программы или:

    POST /network
    Content-Type: application/json

    {
      "virtual_ip": "192.168.1.70",
      "gateways": ["192.168.1.1", "192.168.1.2", "192.168.1.3", "192.168.1.4"]
    }

Виртуальный IP должен быть свободен в LAN. Приложение проверяет адрес;
таблица маршрутов и IP-адреса интерфейсов ОС не меняются.
Маршруты задания используют текущий настроенный виртуальный IP, если
virtual_ip не указан отдельно в каждом элементе routes.

3. ПЕРЕДАТЬ ССЫЛКУ И НАЧАТЬ СКАЧИВАНИЕ

Полный адрес запроса:

    POST http://127.0.0.1:8765/api/v1/jobs
    Content-Type: application/json

Тело запроса для HTTP/HTTPS-файла через четыре шлюза:

    {
      "url": "https://example.org/large-file.bin",
      "directory": "D:/Downloads",
      "chunk_mb": 20,
      "routes": [
        {"type":"gateway", "gateway":"192.168.1.1", "enabled":true},
        {"type":"gateway", "gateway":"192.168.1.2", "enabled":true},
        {"type":"gateway", "gateway":"192.168.1.3", "enabled":true},
        {"type":"gateway", "gateway":"192.168.1.4", "enabled":true}
      ]
    }

Замените url на настоящую ссылку, directory на нужную папку.
В JSON используйте прямые слеши, например D:/Downloads, либо
экранируйте каждый обратный слеш: D:\\Downloads.
Папка относится к компьютеру, на котором работает MultiRoute.

filename — необязательное имя результата HTTP, например model.gguf.
expected_md5 — необязательный эталон MD5 из 32 hex-символов.
expected_sha256 — необязательный эталон SHA-256 из 64 hex-символов.
expected_sha512 — необязательный эталон SHA-512 из 128 hex-символов.
Все заданные или найденные суммы должны совпасть после сборки файла.
Программа автоматически ищет опубликованные суммы у источника.
Локально вычисленные md5, sha256, sha512 без эталона не выдаются за
сверку с источником. MD5 не заменяет требования к безопасной докачке.
Ручные суммы целого файла допускаются при выборе одного файла.
Прежний expected_sha256 сохраняет совместимость.
chunk_mb — размер HTTP-сегмента от 1 до 64 МиБ, по умолчанию 20.
Шлюзы берут части из общей очереди по мере освобождения. Быстрый шлюз
может скачать больше частей; файл заранее не делится поровну между ними.
Зависшую HTTP-часть может забрать другой шлюз после остановки прежней
передачи этой части. Проверенные данные учитываются один раз.
При докачке прежнего задания его сохранённый размер частей не меняется.
Для torrent/magnet размер части задаётся метаданными раздачи;
chunk_mb его не меняет. Раздача также использует общую очередь частей.

HTTP 201 означает создание задания, а не окончание скачивания.
Ответ содержит id. Сохраните его в своём приложении:

    {"id":"012345abcdef", "status":"running", ...}

Задание помещается в очередь и стартует по её ограничениям и расписанию.
По умолчанию одновременно работают не более двух заданий.
За результатом следите через GET /jobs/id.
В некоторых случаях существующее совместимое задание возвращается
с reused: true; оно не запускается автоматически. Для продолжения
остановленного задания используйте POST /jobs/id/resume.

4. ПОЛУЧИТЬ СТАТУС И СКОРОСТЬ

Одно задание:

    GET /jobs/012345abcdef

Все задания:

    GET /jobs

Ответ списка имеет вид {"jobs": [...]}.
Снимок задания содержит:

    id              — идентификатор;
    status          — queued, running, retrying, verifying, paused,
                      failed, seeding (добровольная раздача) или complete;
    size            — размер результата в байтах; -1, пока неизвестен;
    downloaded      — проверенный объём сегментной загрузки; у целого
                      потока — записанные байты до окончательной проверки;
    progress_bytes  — сохранённый объём плюс HTTP-данные в текущих
                      сегментах; при повторе сегмента может уменьшиться;
    received_bytes  — реально полученные данные, включая повторную передачу;
    speed_bps       — общая скорость В БАЙТАХ/С, а не в битах/с;
    elapsed_ms      — время работы загрузки в миллисекундах;
    eta_seconds     — приблизительное оставшееся время в секундах или null;
    routes          — выбранные пути, их gateway, speed_bps, received_bytes,
                      bytes (проверенные данные), chunks и last_error;
    md5             — рассчитанная MD5 целого файла;
    sha256          — рассчитанная SHA-256 целого файла;
    sha512          — рассчитанная SHA-512 целого файла;
    checksum_sources — источники эталонов по md5/sha256/sha512;
    error           — причина ошибки, если она есть.

Для перевода speed_bps в Мбит/с: speed_bps * 8 / 1000000.
Рекомендуемый интервал опроса — около одной секунды. Вместо опроса
можно подписаться на SSE /events, как описано в разделе 12.
Скорость усредняется за последние три секунды. Во время паузы и после
завершения скорость равна нулю; время паузы не прибавляется к elapsed_ms.
ETA не включает окончательную проверку/сборку и может меняться.
Для torrent прогресс относится к выбранным файлам; суммы файлов
и результаты проверки частей находятся в files/pieces_verified.

status == complete означает успешное завершение.
status == failed означает ошибку: прочитайте error.

5. ПАУЗА, ПРОДОЛЖЕНИЕ, ШЛЮЗЫ И ПАПКА

    POST /jobs/012345abcdef/pause
    Content-Type: application/json
    {}

    POST /jobs/012345abcdef/resume
    Content-Type: application/json
    {}

Изменить папку остановленного задания, сохранив скачанные части:

    POST /jobs/012345abcdef/directory
    Content-Type: application/json
    {"directory":"E:/Downloads"}

Задание должно иметь status paused или failed. Смена папки сама
не запускает скачивание. После неё вызовите /resume.

ИЗМЕНИТЬ ШЛЮЗЫ У СОЗДАННОГО ЗАДАНИЯ

    PUT /jobs/012345abcdef/routes
    Content-Type: application/json
    {
      "routes": [
        {"type":"gateway", "gateway":"192.168.1.1", "enabled":true},
        {"type":"gateway", "gateway":"192.168.1.3", "enabled":true}
      ]
    }

Передавайте ПОЛНЫЙ желаемый набор, а не только добавляемый шлюз.
В примере продолжают работать .1 и .3; прочие шлюзы отключаются
для этого задания. Для возврата .2 передайте новый список .1, .2 и .3.
POST с тем же адресом и телом поддерживается как совместимый вариант.

В наборе должен быть хотя бы один и не более 32 разных включённых
шлюзов из текущих настроек GET /network. enabled:true обязателен;
выключенные элементы не включаются в набор. type:direct/worker
для изменения шлюзов задания не допускается. Если указан virtual_ip,
он должен совпадать с действующим адресом приложения. Локальный endpoint
и токен указывать не нужно. Приложение проверяет новые пути до применения;
некорректный запрос не заменяет прежний выбор задания.

Работающее задание продолжает загрузку. У снятого шлюза отменяются
текущие передачи, незавершённые части возвращаются в общую очередь
после освобождения записи. Добавленный шлюз получает части из этой очереди.
У остальных шлюзов работа продолжается. Проверенные части и суммы
сохраняются; общий объём не учитывается повторно. Прежние счётчики
отключённых шлюзов остаются в routes с enabled:false.

У paused/failed изменяется только набор: запрос сам не запускает задание;
для продолжения вызовите /resume. Во время финальной проверки, после
завершения, при обслуживании или остановке задания изменение отклоняется.
HTTP 200 возвращает обновлённый снимок Job; ошибка — HTTP 400 с error.
Изменение относится только к выбранному id; другие задания не меняются.

Через этот запрос выбираются уже настроенные шлюзы. Изменение IP роутеров
через POST /network при том же виртуальном IP поддерживает добавление
и удаление профилей во время работы. При удалении шлюза он отключается
во всех незавершённых заданиях; хотя бы один шлюз у каждого должен остаться.
Новые профили сами не включаются во всех старых заданиях: выберите их
через /jobs/id/routes. Для изменения виртуального адреса загрузки нужно
приостановить. Редактировать список с прежним IP можно и без работающего
сетевого компонента; проверка свободного адреса выполняется явно и при запуске.

ЗАВИСШИЕ ЧАСТИ

Если при передаче части 60 секунд не поступает ни одного нового байта,
попытка отменяется. Незавершённая часть освобождается для выдачи другому
выбранному шлюзу; правило действует и во время ожидания HTTP-заголовков.
Отсчёт начинается при назначении части и обновляется после новых данных,
а не по общей длительности передачи. Медленная передача с поступающими
байтами не считается минутным зависанием. Ожидание из-за установленного
ограничения скорости также не выдаётся за отсутствие сетевых данных HTTP.
Полные проверенные части
сохраняются; незавершённая часть может скачиваться заново.
Для torrent используются исходные части раздачи и их проверка хешей.

6. УДАЛЕНИЕ

Убрать запись из приложения, сохранив файлы и незавершённые части:

    DELETE /jobs/012345abcdef

Удалить запись, её готовые файлы и скачанные части:

    DELETE /jobs/012345abcdef?delete_files=true

По умолчанию delete_files=false. Это соответствует снятой галочке
«Удалить также файлы и скачанные части» в окне подтверждения.
Папка сохранения и посторонние файлы не удаляются.
Удаление файлов необратимо. Через API отдельного окна подтверждения нет:
клиент должен сам получить согласие своего пользователя перед true.
Удаление только записи сохраняет байты, но убирает сведения задания,
необходимые для автоматического продолжения этих частей.

Ответ содержит ok, id, removed, completed_files_kept,
unfinished_parts_kept, delete_files, kept_paths и deleted_files.
При сбое файловой системы удаление может быть выполнено частично;
сообщение error указывает проблемный путь и результат восстановления.

7. HUGGING FACE, TORRENT И MAGNET

Прямую ссылку на отдельный HTTP-файл или Hugging Face /blob/ либо
/resolve/ можно передать в POST /jobs, как в разделе 3.

Если дана папка/репозиторий Hugging Face, сначала получите список:

    POST /sources/inspect
    {
      "url":"https://huggingface.co/OWNER/REPOSITORY/tree/main",
      "route":{"type":"gateway", "gateway":"192.168.1.1"}
    }

Возвращаются revision и files с точными path, размером и суммами.
Передайте нужные пути из этого списка и полученный revision:

    POST /sources/download
    {
      "url":"https://huggingface.co/OWNER/REPOSITORY/tree/main",
      "revision":"<40-символьный коммит из ответа inspect>",
      "selected_files":["path/model.gguf"],
      "directory":"D:/Downloads",
      "routes":[
        {"type":"gateway", "gateway":"192.168.1.1", "enabled":true},
        {"type":"gateway", "gateway":"192.168.1.2", "enabled":true},
        {"type":"gateway", "gateway":"192.168.1.3", "enabled":true},
        {"type":"gateway", "gateway":"192.168.1.4", "enabled":true}
      ]
    }

Этот endpoint всегда возвращает пакетный ответ с массивом jobs,
а также total_size и source. Каждый id можно опрашивать отдельно.
reused=true и reused_count обозначают повторно использованные задания.
Для закрытых источников предварительно сохраните авторизацию через
/source-auth (раздел 14). Bearer привязывается к origin https://huggingface.co.
Доступ к закрытому или gated-репозиторию должен уже быть разрешён владельцем;
наличие токена не обходит ограничений самого источника.

Для torrent/magnet такой же порядок: POST /sources/inspect с url
(ссылка на .torrent, явный локальный путь .torrent либо magnet:?...) и
выбранным route. Затем POST /sources/download с url, routes,
directory и selected_files из ответа inspect. Для многосоставной
раздачи selected_files обязателен. filename не задавайте: имена берутся
из раздачи. Можно передать info_hash_v1/info_hash_v2 из inspect,
чтобы зафиксировать полученные метаданные. Если ссылка .torrent
не имеет расширения, задайте source_type: "torrent".

8. ГОТОВЫЙ ПРИМЕР PYTHON — БЕЗ ДОПОЛНИТЕЛЬНЫХ БИБЛИОТЕК

    import json
    import time
    from urllib.request import Request, urlopen
    from urllib.error import HTTPError

    BASE = "http://127.0.0.1:8765/api/v1"

    def api(method, path, body=None):
        data = None if body is None else json.dumps(body).encode("utf-8")
        request = Request(BASE + path, data=data, method=method,
                          headers={"Content-Type": "application/json"})
        try:
            with urlopen(request, timeout=120) as response:
                return json.load(response)
        except HTTPError as error:
            message = error.read().decode("utf-8", errors="replace")
            raise RuntimeError(f"API {error.code}: {message}") from error

    routes = [
        {"type": "gateway", "gateway": f"192.168.1.{i}", "enabled": True}
        for i in range(1, 5)
    ]
    job = api("POST", "/jobs", {
        "url": "https://example.org/large-file.bin",  # Замените ссылку.
        "directory": "D:/Downloads",               # Замените папку.
        "routes": routes,
        "chunk_mb": 20
    })
    job_id = job["id"]
    print("Создано задание:", job_id)

    while True:
        state = api("GET", "/jobs/" + job_id)
        speed = state["speed_bps"] * 8 / 1_000_000
        print(state["status"], state["progress_bytes"], "/", state["size"],
              f"{speed:.1f} Мбит/с", "осталось:", state["eta_seconds"])
        if state["status"] == "complete":
            print("Скачано:", state["filename"], "SHA-256:", state.get("sha256"))
            break
        if state["status"] in ("failed", "paused"):
            print("Остановлено:", state.get("error", ""))
            break
        time.sleep(1)

    # Примеры других действий, вызывайте только нужное:
    # Изменить набор у уже работающего задания (.1 и .3):
    # api("PUT", "/jobs/" + job_id + "/routes", {"routes": [
    #     {"type": "gateway", "gateway": "192.168.1.1", "enabled": True},
    #     {"type": "gateway", "gateway": "192.168.1.3", "enabled": True}
    # ]})
    # api("POST", "/jobs/" + job_id + "/pause", {})
    # api("POST", "/jobs/" + job_id + "/resume", {})
    # api("DELETE", "/jobs/" + job_id)  # Сохранить файлы.
    # api("DELETE", "/jobs/" + job_id + "?delete_files=true")

Пример предназначен для одной прямой HTTP-ссылки; для списков
репозитория/раздачи используйте раздел 7 и получайте id из jobs.

9. ОШИБКИ И ТЕХНИЧЕСКИЕ ГРАНИЦЫ

Ошибка обработки запроса обычно возвращается с HTTP 400:

    {"error":"Пояснение причины"}

Недопустимый Host или Origin возвращает HTTP 403.
Content-Length можно не указывать: допускается передача тела по частям.
Максимальное тело JSON-запроса — 1 МиБ (1048576 байт).
Создание задания не гарантирует успешной передачи: контролируйте
status и error. API не скачивает файл в ответ HTTP-запроса — он
сохраняет его в directory и возвращает сведения о задании.

Для Windows x64 включён готовый компонент шлюзов; нужны Java 17+
и установленный Npcap. macOS 11+ Intel/Apple Silicon поставляется с
исходниками и автоматической сборкой на целевом Mac; подробности ниже.
Запуск на настоящем Mac, BPF и передача через физические шлюзы
в текущем цикле не проверены. Для Linux добавлены Deploy-Linux.sh и
Start-Linux.sh; порядок и зависимости описаны в README-Linux.ru.txt.
Большие HTTP-файлы без Range, в том числе без Content-Length, загружаются
целым потоком через один выбранный шлюз. Обрыв требует начала с нуля;
resumable:false и distribution_supported:false обозначают эту границу.
Предела 64 МиБ для целого файла нет. Безопасной сегментной докачке нужен
сильный ETag либо доверенная SHA-256. Torrent проверяет исходные хеши частей.
Лимиты 16 МиБ / 5 секунд относятся только к отдельному тесту скорости.

Для контроля соединений доступны:

    POST /routes/inspect   {"gateway":"192.168.1.1"}
    POST /gateways/speed   {"gateway":"192.168.1.1"}

10. ОЧЕРЕДЬ, СКОРОСТЬ И РАСПИСАНИЕ

    GET /queue
    PUT /queue
    {
      "max_active_jobs": 2,
      "global_limit_bps": 1048576,
      "gateway_limit_bps": {"192.168.1.1":262144, "192.168.1.3":524288},
      "schedule_enabled": true,
      "schedule_start": "23:00",
      "schedule_end": "07:00"
    }

Поля можно менять частично. POST /queue — совместимый вариант PUT.
max_active_jobs: 1–32, по умолчанию 2.
Скорости задаются В БАЙТАХ/С: 1048576 = 1 МиБ/с; 0 — без ограничения.
Допустимое числовое значение лимита: 0–1000000000000.
Отсутствующий шлюз в gateway_limit_bps не имеет отдельного ограничения.
Это лимиты полезных данных. Заголовки протоколов и буферы TCP ОС не являются
точным измерением скорости на проводе. Для HTTP бюджет общий для заданий,
для torrent он распределяется между независимыми сессиями выбранных шлюзов.

Расписание использует часовой пояс компьютера: GET также возвращает
schedule_timezone. Одинаковые начало и конец означают весь день; интервал
через полночь поддерживается. По умолчанию schedule_enabled:false.
Вне расписания активные передачи приостанавливаются со статусом queued
и автоматически возобновляются в следующем окне. Ручной paused остаётся
приостановленным. Уменьшение max_active_jobs ограничивает новые старты,
уже работающие задания не отменяются принудительно.
GET возвращает также active_jobs; эти два служебных поля в PUT не передавайте.

11. ПРИОРИТЕТЫ И ПАРАМЕТРЫ ЗАДАНИЯ

    PUT /jobs/012345abcdef/options
    {"priority":50, "start_after_ms":0}

priority: целое от -100 до 100, по умолчанию 0; большее стартует раньше.
start_after_ms: время не раньше запуска, миллисекунды Unix; 0 — сейчас.
Максимум 253402300799000. POST с тем же телом также поддерживается.
Настройки сохраняются. После перезапуска ранее работающие задания
восстанавливаются приостановленными; поставленные в очередь подчиняются
расписанию и своим ограничениям. Для ручного продолжения используйте /resume.

Параметры torrent:

    PUT /jobs/012345abcdef/options
    {
      "file_priorities":{"folder/model.gguf":7, "folder/readme.txt":0},
      "seeding_enabled":true,
      "seeding_minutes":30,
      "seeding_ratio":1.0
    }

file_priorities принимает только первоначально выбранные selected_files:
0 — пропустить; 1–7 — приоритет выбора частей. Неуказанные файлы имеют
приоритет 4. Должен остаться хотя бы один файл. Изменение приоритетов
работающего torrent приостанавливает и заново ставит его в очередь,
сохраняя проверенные общие части. Повторное сохранение тех же приоритетов
или изменение прочих параметров не перезапускает передачу.

Раздача по умолчанию выключена. Если включена до завершения, начинается
после независимой проверки итоговых файлов и использует выбранные шлюзы.
seeding_minutes: 1–1440, по умолчанию 30.
seeding_ratio: больше 0 и не больше 100, по умолчанию 1.0.
Раздача прекращается по первому достигнутому пределу времени/измеренного
ratio, по отключению или паузе. Сессии находятся в режиме только отдачи,
не запрашивают недостающие части. Предел отдачи одной сессии — 1 МиБ/с.

В снимках torrent есть peers, seeds, tracker_states. В routes доступны peers,
seeds, tracker_status, uploaded_bytes, upload_speed_bps. Также выдаются
seeding_elapsed_seconds, seeding_ratio_actual и seeding_outcome.
Числа пиров/сидов суммируются по сессиям; один пир через несколько шлюзов
может учитываться несколько раз. Статусы трекеров — сведения каждой сессии.

12. ПАКЕТНОЕ ДОБАВЛЕНИЕ, ИДЕМПОТЕНТНОСТЬ И СОБЫТИЯ

    POST /jobs/batch
    {"jobs":[{обычный запрос создания},{обычный запрос создания}]}

От 1 до 128 элементов. Сохраняйте прежние поля url/directory/routes.
Ответ: {"results":[{"index":0,"ok":true,"job":...},
                   {"index":1,"ok":false,"error":"..."}], "success_count":1}.
index соответствует входному массиву. Ошибка одного элемента не отменяет
остальные. Создание списка источника может дать внутри job ответ с jobs.

Чтобы безопасно повторить POST /jobs, передайте заголовок:

    Idempotency-Key: application-request-2026-001

Либо поле idempotency_key в JSON; в пакете это поле задаётся каждому элементу.
Оба варианта должны совпадать, если переданы вместе. Ключ: 1–128 латинских
букв/цифр, подчёркиваний, точек, двоеточий или дефисов. Тот же ключ с тем же
каноническим запросом возвращает прежний результат с idempotent_replay:true.
Другая ссылка/папка/параметры с тем же ключом дают ошибку.
Порядок JSON-полей не важен, порядок массивов важен. Реестр сохраняется
в каталоге данных: до 1024 записей, срок записи 7 дней. Сведения в манифестах
помогают восстановить ключ при обрыве записи реестра. Для удалённого
одиночного задания используйте новый ключ. Списки источников возвращают
сохранённый результат первоначального создания; проверяйте актуальные id
через GET /jobs. Ключ не распространяется между разными профилями данных.
Заголовок относится к POST /jobs; для /sources/download используйте этот же
запрос создания через /jobs или ключи отдельных заданий пакета.

    GET /events
    Accept: text/event-stream

SSE-поток начинается событием snapshot с {jobs:[...]}, затем идут job,
queue и network. Данные — JSON с каноническими статусами, события имеют
числовые id. Каждые 15 секунд отправляется комментарий heartbeat.
Не более 32 подписчиков, у каждого не более 64 событий в очереди.
Медленному клиенту приходит reset с {"reason":"slow_consumer"}; после
этого получите GET /jobs и продолжайте читать события. При переподключении
приходит новый snapshot. Восстановление по Last-Event-ID не реализовано.
Публикация события не блокирует скачивание.

13. ПРОТОКОЛЫ, WEB DAV, METALINK И ЗЕРКАЛА

В POST /jobs допускаются http://, https://, ftp://, ftps://, sftp://.
FTP работает в пассивном режиме; управляющее соединение и канал данных
проходят через один выбранный шлюз. FTPS использует явный AUTH TLS и
проверяет TLS для управляющего соединения и данных. SFTP — SSH-протокол;
нужны сохранённые имя/пароль и заранее проверенный SHA256-отпечаток ключа.
Встроенные логин/пароль в URL не принимаются.

Для FTP/FTPS/SFTP приложение ищет .md5/.sha256/.sha512 рядом с файлом
и MD5SUMS/SHA256SUMS/SHA512SUMS в папке источника. При опубликованной
или переданной expected_sha256 либо expected_sha512
допускается сегментная докачка. Без доверенной суммы файл передаётся целым
потоком через один выбранный шлюз, чтобы не объединять независимые версии.
При обрыве поток начинается с нуля, остальные выбранные шлюзы пробуются
по очереди. Итоговые локальные MD5, SHA-256 и SHA-512 рассчитываются
за один проход чтения; MD5 не разрешает небезопасную сегментацию.

WebDAV поддерживается по HTTPS. Для списка папки:

    POST /sources/inspect
    {"url":"webdavs://archive.example/files/",
     "route":{"type":"gateway","gateway":"192.168.1.1"}}

Или используйте https://archive.example/files/ с source_type:"webdav".
Листинг — один уровень папки, только файлы. Возвращаются kind, source_url,
files. Передайте выбранные path в selected_files и обычные directory/routes
в POST /sources/download. Сами файлы читаются по HTTPS; сертификат проверяется.

Metalink RFC 5854 (.meta4) читается с HTTPS:

    POST /sources/inspect
    {"url":"https://publisher.example/files.meta4",
     "route":{"type":"gateway","gateway":"192.168.1.1"}}

Для URL без расширения укажите source_type:"metalink". Выберите path из
files и создайте /sources/download или /jobs с selected_files.
Нужны точный размер, опубликованная SHA-256 целого файла и 1–32 URL зеркал.
Опубликованные SHA-256 частей, если есть, проверяются перед публикацией
собранного файла; максимальная длина опубликованной части — 64 МиБ.
Разные сильные ETag зеркал не мешают объединению при доверенной SHA-256.
Первичный ETag не отправляется как If-Range другому зеркалу. При ошибке
получения сегмента пробуется другое зеркало. Размер без хеша не считается
доказательством идентичности.

Можно задать mirrors:["https://mirror-a/file", "https://mirror-b/file"]
для обычного POST /jobs вместе с expected_sha256. Конечная SHA-256 всё
равно сверяется. Хеши из торрент-метаданных проверяются отдельно.

14. АВТОРИЗАЦИЯ ИСТОЧНИКОВ

    GET /source-auth
    POST /source-auth
    PUT /source-auth
    DELETE /source-auth/<uuid>

Совместимые адреса: /sources/auth и /sources/auth/<uuid>.
Пример Bearer для доступного вашему аккаунту Hugging Face:

    POST /source-auth
    {"origin":"https://huggingface.co", "type":"bearer",
     "name":"My Hugging Face", "token":"<ваш токен>"}

origin — точные схема, домен и порт без пути/query/встроенного пароля.
Типы: basic, bearer, cookie, headers, ftp, sftp.
basic/ftp/sftp: username и password (пароль может быть пустым).
bearer: token; cookie: cookie; headers: объект из разрешённых заголовков
Authorization, Cookie, Referer, X-Api-Key, X-Auth-Token (не больше пяти).
Автоматическое чтение cookies браузера не выполняется.
SFTP дополнительно требует host_key_sha256, например SHA256:<base64>,
полученный и проверенный отдельно. Несовпадение ключа отклоняет соединение.

После сохранения отправляйте обычный URL в /jobs. Указывать auth_id в
задании не нужно: авторизация подбирается по точному origin. При редиректе
секреты получает только origin с собственными соответствующими настройками.
Ответы содержат id/origin/type/name и, для SFTP, отпечаток; секретные
значения и username обратно не выдаются. Хранилище локальное, зашифрованное,
с доступом только текущего пользователя. Метод не копирует секреты в задания.
Это авторизация источника файлов, а не роутеров.

ПРИМЕЧАНИЯ К АВТОРИЗАЦИИ И DNS В 4.1.1

ДОПОЛНИТЕЛЬНЫЕ СУММЫ MD5 И SHA-512

В POST /api/v1/jobs можно независимо передать expected_md5 (32 hex),
expected_sha256 (64 hex), expected_sha512 (128 hex). Верхний и нижний
регистр принимаются; результаты хранятся в нижнем регистре.
Для группы файлов передавайте эталоны в каждом отдельном задании.

После сборки все три суммы вычисляются за один проход чтения. Каждая
известная сумма сверяется со своим эталоном. При несовпадении итоговый
файл не публикуется как успешно завершённый, частичные данные сохраняются.

Автопоиск использует поддерживаемые Repr-Digest целого представления,
filename.md5/MD5SUMS, filename.sha256/SHA256SUMS,
filename.sha512/SHA512SUMS. Сумма частичного HTTP-ответа не считается
суммой всего файла. Данные Hugging Face LFS и Metalink проверяются как прежде.

Поля результата: md5, sha256, sha512; checksum_sources содержит источник
эталона для каждого алгоритма, у которого есть эталон. Без эталона сумма
локальная: это не подтверждённая сверка с сервером. Для torrent поля
files[].md5/sha256/sha512 относятся к отдельным собранным файлам;
обязательная проверка исходных хешей частей torrent сохраняется.
MD5 помогает обнаруживать случайное повреждение; для более сильной
проверки используйте SHA-256 или SHA-512.

ИСТОРИЯ ЗАГРУЗОК (4.0)

В папке данных находятся `logs/downloads-history.jsonl` (UTF-8, один JSON-объект на строку) и `logs/downloads-history.log` (читаемые записи с датами). Они дополняются после перезапусков и сохраняются при удалении задания; удаление задания или скачанных файлов не очищает историю. Текстовый журнал сохраняет язык на момент записи события; интерфейс отображает сохранённые события на выбранном сейчас языке. В окне журнала читается только хвост до 1 000 событий / 2 МиБ; полный архив остаётся на диске. Он растёт по мере использования, поэтому при необходимости архивируйте его отдельно. История содержит имена и полные пути назначения, но не URL источников, пароли или токены доступа. Перед передачей журнала проверьте пути.

Windows с native-установщиком: `%LOCALAPPDATA%\MultiRoute Downloader\data\logs\`. Native macOS: `~/Library/Application Support/MultiRoute Downloader/data/logs/`. В Linux и portable используется папка данных, указанная выше; параметр `--data-dir` выбирает другую.

`GET /api/v1/jobs` и ответ отдельного задания содержат `lifecycle_history`. Поля события: `event_id`, `job_id`, `kind`, `time`, `filename`, `path`; у torrent также может быть `paths`, а у паузы — `reason`. Виды событий: `started`, `resumed`, `paused`, `completed`, `recovered`, `failed`. Отметки времени — ISO 8601 UTC, например `2026-10-18T12:34:56.123Z`; читаемый журнал содержит полную местную дату, время и смещение UTC. Необязательные `first_started_at`, `last_resumed_at`, `completed_at` отражают фактически наблюдавшиеся события. Постановка в очередь ещё не считается началом; завершение записывается после проверки и публикации файла. `recovered` означает, что ранее опубликованный файл проверен сейчас, а не что известна его прежняя дата завершения. Исторические даты старых заданий не выдумываются. Прежние операции API доступны; отдельный endpoint истории не требуется.


ДОПОЛНИТЕЛЬНЫЕ ЯЗЫКИ (4.0)

Текущая версия поддерживает двенадцать языков: английский (по умолчанию),
русский, немецкий, испанский, французский, китайский, корейский,
арабский и итальянский. Интерфейс, сохранённые события и подсказки
переключаются вместе. В арабской локализации расположение интерфейса
справа налево; URL, пути и JSON-ключи не переводятся и остаются читаемыми.
Для каждого языка есть отдельное полное руководство в папке docs/.
Исторические разделы 2.4 и 3.0 выше описывают языки тех версий.


Текущий продукт — MultiRoute Downloader; GitHub: https://github.com/2018-spec-fdsds/multiroute-downloader.
Поддерживаются 12 языков, включая японский (ja), хинди (hi) и вьетнамский (vi).
Внутренний app_id multiroute-resume и ранее сохранённые профили остаются совместимыми.


Профили сайтов, отправка файлов и просмотр архивов (4.0)

Сохраните профиль сайта: имя, базовый URL, локальную папку загрузок, удалённую папку и шлюзы. Поддерживаются анонимный доступ, HTTP Basic/Bearer/Cookie/свои заголовки, учётные данные FTP и SFTP с заранее проверенным SHA-256 ключом сервера. Для одного сервера можно создать разные профили пользователей. Профиль подставляет папки, шлюзы и доступ; явно заданные папки/шлюзы имеют приоритет. Относительные URL скачивания и отправки разрешаются относительно базового URL. Секреты зашифрованы в `site-profiles/vault.bin` с локальным ключом `site-profiles/key.bin` и правами только владельца: это защита хранения, но не от владельца вашей учётной записи и ключа. В ответах API секретов нет. Пустые поля сохраняют прежний доступ только при неизменных origin и типе авторизации; `replace_credentials:true` явно заменяет его. При HTTP-перенаправлении на другой origin доступ не передаётся. Удаление профиля сохраняет задания и локальные/удалённые файлы; задание сохраняет исходную привязку к профилю и не переключается на другую учётную запись; после удаления профиля при необходимости создайте задание заново с действующим профилем.

Отправка и просмотр удалённых папок поддерживают **FTP, явный FTPS и SFTP** через выбранные шлюзы приложения. Выберите обычный локальный файл и полный URL удалённого файла (`target_url`), а не только папку. Сначала используется временный удалённый файл; докачка возможна после сравнения сохранённого префикса. Успех подтверждается повторным чтением удалённого файла и SHA-256: нужны права **чтения, записи и переименования**. Проверка повторно расходует трафик. Несовпадение суммы или запрет чтения означают ошибку. Один файл отправляется через один шлюз; независимые файлы отправляются параллельно с распределением по выбранным шлюзам. Зависший шлюз после лимита простоя заменяется другим выбранным. Разбиения одной отправки между шлюзами нет. Пауза, продолжение и прогресс сохраняются при перезапуске. Удаление задания оставляет локальный файл и удалённые итоговые/временные файлы.

Перезапись по умолчанию отключена; включайте её только для намеренной замены. FTP/SFTP не всегда дают атомарное «переименовать, только если цели нет»: другой клиент может изменить ту же цель одновременно с публикацией. Согласуйте работу с общими удалёнными файлами. Просмотр папки ничего не отправляет и не удаляет.

Просмотр архивов показывает имена, пути, размеры, папки и признаки шифрования **ZIP, TAR, 7Z, RAR4 и RAR5** без распаковки и запуска. Нужны выбранный шлюз, диапазоны байтов и стабильный ETag либо Last-Modified. Лимиты метаданных: 16 MiB, 10 000 записей и 60 секунд; декодирование заголовков 7z — до 64 MiB памяти. Список может быть неполным и не подтверждает целостность содержимого. При ошибке имён задайте исходную кодировку. Для поддерживаемых зашифрованных заголовков 7z можно передать пароль; он не сохраняется. Зашифрованные заголовки RAR обозначаются как неподдерживаемые/требующие пароль. Многотомные и неподдерживаемые архивы могут отображаться частично.

API принимает `site_profile_id` для скачивания, отправки, папок и архивов. `GET /api/v1/site-profiles` возвращает `{profiles:[...]}`, `POST` (или `PUT`) сохраняет плоский объект профиля и возвращает публичные поля. `DELETE /api/v1/site-profiles/{id}` удаляет только профиль. `POST /api/v1/uploads`: `local_path`, `target_url`, `routes`, необязательный `site_profile_id`, `overwrite:false`; ответ HTTP 201. `GET /api/v1/uploads` возвращает `{uploads:[...]}`. Для задания доступны GET/DELETE и POST `/{id}/pause` / `/{id}/resume`. `POST /api/v1/remote/list`: `url` и `route`/`routes`; `POST /api/v1/archives/preview` также принимает необязательные `password` и `charset`. Схемы — [openapi.yaml](openapi.yaml). Манифесты отправки UTF-8 находятся в `data/uploads/`, содержат ID профиля без пароля. Просмотр архива не создаёт загрузку.

Пример сохранения профиля (секрет подставляет ваш клиент; не включайте его в журнал):
POST http://127.0.0.1:8765/api/v1/site-profiles
Content-Type: application/json; charset=utf-8
{"name":"My SFTP","base_url":"sftp://files.example.org/incoming/","type":"sftp","username":"YOUR_ACCOUNT","password":"YOUR_PASSWORD","host_key_sha256":"SHA256:PREVIOUSLY_VERIFIED_FINGERPRINT","gateways":["192.168.1.1","192.168.1.2"]}

Сохраните UUID id из публичного ответа и используйте его:
POST http://127.0.0.1:8765/api/v1/uploads
Content-Type: application/json; charset=utf-8
{"local_path":"C:\\Users\\YOUR_USER\\Downloads\\пример.zip","target_url":"sftp://files.example.org/incoming/example.zip","site_profile_id":"PROFILE_UUID","routes":[{"type":"gateway","gateway":"192.168.1.1","enabled":true},{"type":"gateway","gateway":"192.168.1.2","enabled":true}],"overwrite":false}

GET /api/v1/uploads/{id} — status, uploaded_bytes, size, speed_bps (байт/с), elapsed_ms, eta_seconds, verified, verification, sha256. Поля проверки появляются после проверки. DELETE задания не удаляет исходник или удалённые файлы. PUT/POST профиля с прежним id редактирует его. Пустой пароль сохраняет прежний, если origin/тип прежние; для намеренной полной замены задайте replace_credentials:true и полный набор полей. type:none означает анонимный доступ без подстановки глобального доступа.


Расписание скачивания и приоритет

В настройках очереди/расписания задайте `max_active_jobs` (1–32), общий лимит скорости и лимиты шлюзов, суточное окно скачивания (`schedule_enabled`, `schedule_start`, `schedule_end`, HH:mm). Используется часовой пояс компьютера, API показывает его как `schedule_timezone`; окно может проходить через полночь, одинаковое начало/конец означает весь день. Вне окна загрузки возвращаются в очередь, затем продолжаются. Вручную приостановленное задание остаётся на паузе. Для выбранной загрузки `priority` от -100 до 100 задаёт порядок: большее число запускается раньше, при равенстве — порядок создания. Изменение приоритета не прерывает активную загрузку. `start_after_ms` — необязательное самое раннее время Unix epoch в миллисекундах, 0 снимает разовую задержку. Настройки сохраняются. Они относятся к скачиванию, а не независимой очереди отправок. Приложение должно работать, в том числе в трее, а компьютер — не спать; пробуждения средствами ОС нет. Те же настройки доступны через `GET`/`PUT`/`POST /api/v1/queue` и `PUT`/`POST /api/v1/jobs/{id}/options`.

Интеграция с Chrome и Edge

Откройте в приложении интеграцию **Chrome / Edge**, разрешите передачу ссылок и откройте папку расширения. Один раз перейдите в Chrome на `chrome://extensions`, в Edge — `edge://extensions`, включите режим разработчика, нажмите **Загрузить распакованное** и выберите `browser-extension` с `manifest.json`. Native-установщики включают её рядом с JAR; в исходниках есть [browser-extension/](browser-extension/). Не перемещайте выбранную папку. Отдельный `MultiRoute-Downloader-4.1.1-Chrome-Edge.zip` сначала распакуйте. Эта версия устанавливается локально, публикации в магазинах браузеров нет.

MultiRoute должен быть запущен, достаточно трея. Нажмите правой кнопкой по ссылке и выберите действие скачивания MultiRoute либо отправьте URL из окна расширения. Используются выбранные в приложении папка, шлюзы и профиль сайта; при необходимости остаётся выбор файлов репозитория/torrent. Порт расширения по умолчанию 8765; если API работает на другом порту, задайте его. Передаётся только URL: cookies и пароли браузера не копируются, остальные закачки браузера не перехватываются. Доступ к источнику настройте в приложении. Если браузер запрашивает доступ к локальному соединению, подтвердите его только для выбранного расширения.

Мост по умолчанию выключен; разрешён только origin `chrome-extension://ljdklefabmaecjalfhjoicmgedmjjkbl` на `/api/v1/browser/status` и `/api/v1/browser/download`. Правила остальных API не ослабляются. HTTP 202 означает передачу URL в приложение, а не завершение файла. Один headless-сервер не открывает нужный настольный выбор. Для отключения удалите расширение на странице браузера или снимите разрешение в приложении.


DNS ПРИЛОЖЕНИЯ — 4.2.0
======================

Настройки относятся к MultiRoute. DNS-серверы ОС, таблица маршрутизации и IP
интерфейсов не изменяются. DoH/DoT идут через выбранный шлюз и виртуальный IP;
числовые публичные bootstrap IPv4 исключают предварительный запрос имени
провайдера через ОС. Проверяются доверенная цепочка TLS, имя хоста и SNI.
Ошибка защищённого запроса не вызывает перехода к DNS роутера, порту 53 или ОС.
Режим system явно использует политику компьютера/ОС/VPN: путь DNS по отдельным
шлюзам и шифрование не гарантируются, файловые соединения сохраняют свой шлюз.

GET /api/v1/network/dns
Возвращает самостоятельный объект DNS, а не обёртку {dns:...}. Те же данные
находятся в поле dns ответа GET /api/v1/network. Ключи конфигурации:
  mode: system | doh | dot (по умолчанию doh)
  provider: cloudflare | quad9 | google | custom (по умолчанию cloudflare)
  doh_url: HTTPS URL с именем хоста, без userinfo, query и fragment
  dot_host: имя сервера для аутентификации DoT, не IP
  dot_port: целое 1..65535, кроме 53; по умолчанию 853
  bootstrap_ips: до восьми числовых публичных IPv4
Поля revision, configuration_error, encrypted, helper_ready, timeout_ms,
plaintext_fallback и gateway_status — состояние только для чтения.
encrypted может отсутствовать до инициализации службы. gateway_status содержит
наблюдения запросов: gateway, mode, provider, revision, ok, elapsed_ms,
response_bytes, error и at; пустой список не доказывает неисправность DNS.

PUT /api/v1/network/dns  (POST — совместимый вариант)
Передавайте только разрешённые шесть ключей конфигурации, не весь ответ GET.
Пресеты допускают сокращённое тело; непереданные значения берутся из пресета.
Например, {"mode":"dot","provider":"quad9"} выбирает Quad9 DoT,
а {"mode":"system"} — системное разрешение имён. У custom укажите нужный
URL или имя сервера и непустой bootstrap_ips. Изменять значения фиксированного
пресета нельзя: сначала выберите provider=custom. Неизвестные поля, включая
revision из ответа GET, отклоняются. Проверка неверных данных не применяет их.
Успех HTTP 200 возвращает самостоятельный объект DNS с применённой revision.
Изменённая конфигурация получает новую ревизию; повтор эквивалентной может
оставить её прежней. Всегда используйте возвращённое значение, не вычисляйте
следующий номер сами. Данные сохраняются в dns-settings.json активной папки
данных UTF-8. Ошибка чтения файла видна в configuration_error; исправьте и
примените настройки до подключения. Изменение DNS действует на последующие
разрешения имён; существующие файловые TCP-соединения сохраняются.

Пример полного тела (сохраните как dns.json в UTF-8):
{
  "mode": "doh",
  "provider": "cloudflare",
  "doh_url": "https://cloudflare-dns.com/dns-query",
  "dot_host": "one.one.one.one",
  "dot_port": 853,
  "bootstrap_ips": ["1.1.1.1", "1.0.0.1"]
}

curl.exe -H "Content-Type: application/json" -X PUT --data-binary @dns.json http://127.0.0.1:8765/api/v1/network/dns

POST /api/v1/network/dns/test
Тело: {"settings":{...только конфигурация...},"gateways":["192.168.1.1"],"hostname":"example.com"}
settings обязателен и непустой; gateways — 1..32 различных настроенных шлюзов,
при отсутствии берётся весь настроенный список. hostname по умолчанию example.com.
Тест использует черновик и не сохраняет его, не меняет revision и DNS ОС.
HTTP 200 может содержать ok=false при частичном или полном отказе DNS:
{
  "mode":"doh", "provider":"cloudflare", "hostname":"example.com",
  "results":[
    {"gateway":"192.168.1.1","ok":true,"addresses":["93.184.215.14"],"elapsed_ms":12},
    {"gateway":"192.168.1.4","ok":false,"error":"DNS query timed out","elapsed_ms":8000}
  ],
  "ok":false, "plaintext_fallback":false, "os_routes_changed":false
}
Это пример формы ответа, а не результат реального теста или обещанный IP/тайминг.
HTTP 400 возвращает {"error":"..."} при неверных параметрах/недоступной службе.
В system успешный тест подтверждает ответ системного резолвера, а не независимый
WAN каждого шлюза. Ошибка одного шлюза не превращается в успешный общий ответ.

GET /api/v1/network/dns/providers
Возвращает modes=["system","doh","dot"], plaintext_fallback=false и providers:
три объекта с id=cloudflare/quad9/google и полными конфигурациями doh и dot.
custom — отдельный допустимый provider, не четвёртый фиксированный пресет.
Cloudflare: https://cloudflare-dns.com/dns-query; DoT one.one.one.one:853;
  bootstrap 1.1.1.1, 1.0.0.1.
Quad9: https://dns.quad9.net/dns-query; DoT dns.quad9.net:853;
  bootstrap 9.9.9.9, 149.112.112.112.
Google: https://dns.google/dns-query; DoT dns.google:853;
  bootstrap 8.8.8.8, 8.8.4.4.

Общий предел DNS-запроса — 8 секунд, включая подключение и TLS. DoH использует
ограниченный HTTPS POST application/dns-message с HTTP/2 через TLS ALPN либо
HTTP/1.1 при согласовании этого протокола, без перенаправлений и gzip.
Совместимость провайдера через конкретный шлюз смотрите в итоговом отчёте.
Нативный положительный кэш разделён по шлюзам, имени и ревизии, ограничен
300 секундами и не кэширует TTL=0. HTTP Age уменьшает TTL DoH; Java не добавляет
своего DNS-кэша. В system действуют дополнительные правила кэша ОС/JVM.
Поддерживаются публичные IPv4 A-ответы. Локальная проверка DNSSEC, IPv6 и
отдельные запросы продолжения CNAME не реализованы.
