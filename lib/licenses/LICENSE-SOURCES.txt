Bundled jlibtorrent 2.0.12.9 runtime notices
=========================================

The Java wrapper and the five platform JNI JARs in lib/ are the unmodified
FrostWire artifacts. Each JNI JAR contains one native shared library. No
separate OpenSSL shared library is required: all five native binaries contain
the version marker "OpenSSL 3.6.0 1 Oct 2025".

GCC-COPYING-GPL-3.0.txt and GCC-RUNTIME-LIBRARY-EXCEPTION-3.1.txt
  The Windows/Linux JNI binaries include GCC C++ and compiler runtime code.

  The applicable runtime license consists of GPL version3 together with the
  GCC Runtime Library Exception version3.1. Keep both documents together.
  https://raw.githubusercontent.com/gcc-mirror/gcc/releases/gcc-13.3.0/COPYING3
  https://raw.githubusercontent.com/gcc-mirror/gcc/releases/gcc-13.3.0/COPYING.RUNTIME
  Build configuration references:
  https://raw.githubusercontent.com/frostwire/frostwire-jlibtorrent/master/swig/config/windows-x86_64-config.jam
  https://raw.githubusercontent.com/frostwire/frostwire-jlibtorrent/master/swig/config/linux-x86_64-config.jam
  https://raw.githubusercontent.com/frostwire/frostwire-jlibtorrent/master/swig/config/linux-arm64-config.jam

MINGW-W64-WINPTHREADS-LICENSE.txt
  Windows JNI is built with the MinGW-w64 GCC POSIX toolchain. This file keeps
  the MinGW-w64 winpthreads MIT and Lockless Inc. BSD notices with that runtime.
  https://raw.githubusercontent.com/mingw-w64/mingw-w64/master/mingw-w64-libraries/winpthreads/COPYING

SWIG is a wrapper-generation build tool and is not bundled as an executable.
Its generated wrapper output does not impose the SWIG compiler's GPL terms
on the application; the wrapper is distributed under jlibtorrent's MIT terms.
Official clarification: https://www.swig.org/legal.html

macOS JNI links the operating system's libc++.1.dylib and libSystem.B.dylib.
Linux JNI links the operating system's libc.so.6 and libm.so.6. Those system
shared libraries are not included in this distribution.
