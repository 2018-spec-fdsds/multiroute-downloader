# Проверка сети и журнал ошибок

MultiRoute проверяет реальную маску выбранного сетевого интерфейса. Адрес компьютера, виртуальный IP приложения и все настроенные шлюзы должны быть допустимыми адресами одной подсети. Виртуальный IP и шлюзы не должны совпадать ни с одним IPv4, назначенным компьютеру. Сетевой и широковещательный адреса определяются по маске, включая подсети /16, /23 и /25.

Во время работы сетевого компонента проверка повторяется примерно каждые две секунды. При смене IP компьютера в пределах той же подсети на том же интерфейсе приложение сохраняет виртуальный IP, собственный TCP/IP стек и порты прокси. IP компьютера и маршруты ОС приложение не меняет.

При переходе в другую подсеть, смене маски, исчезновении интерфейса или конфликте адресов собственный транспорт останавливается и требует повторной проверки сети. Проверенные сегменты загрузок сохраняются. Автоматического переключения передачи на системный шлюз нет. Проверка принадлежности одной подсети сама по себе не доказывает доступность интернета через каждый роутер.

В настройках сети отображаются IP компьютера, подсеть, виртуальный IP и количество шлюзов. API `GET /api/v1/network` возвращает эти сведения в `network_validation` со статусом `pending`, `valid` или `error`; чтение не запускает сетевой компонент. `POST /api/v1/routes/inspect` с телом `{"gateway":"192.168.1.1"}` проверяет настроенный шлюз и при необходимости запускает компонент. Это проверка сети и ARP, а не измерение скорости.

## Ошибки, повторные попытки и 502

В каталоге данных приложения ведётся отдельный журнал UTF-8 `logs/network-errors.log`. При использовании прежнего профиля Windows это обычно `%LOCALAPPDATA%\MultiRoute Resume\data\logs`, при новом профиле — `%LOCALAPPDATA%\MultiRoute Downloader\data\logs`. Фактический каталог данных возвращает `GET /api/v1/instance`.

Сохраняются дата и время, выбранный шлюз, сервер, полученный через DNS IPv4 при его наличии, этап сбоя, длительность и код ошибки сетевого компонента. Для повторных попыток загрузки также сохраняются идентификатор задания, номер сегмента и диапазон байтов. Успешная следующая попытка не удаляет предыдущую ошибку. При размере 4 МиБ журнал переносится в архив; сохраняются три архива. Он не зависит от короткой истории в окне лога и переживает перезапуск. Старые записи сохраняют язык момента записи; история в интерфейсе может переключать язык.

Локальная ошибка CONNECT 502 означает, что сетевой компонент приложения не смог открыть туннель. Новый журнал различает разбор запроса, ARP, DNS, создание сокета, привязку и установление TCP-соединения. Причины, потерянные старой сборкой, восстановить нельзя. В новые диагностические записи не включаются пути и параметры подписанных URL, учётные данные, заголовки запросов и тела ответов прокси.

Технические источники: [рекомендации OWASP по журналам](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html), [обнаружение конфликтов IPv4, RFC 5227](https://www.rfc-editor.org/info/rfc5227/), [серверы хранения и CDN Hugging Face](https://huggingface.co/docs/hub/models-downloading).
