## 4.3.9 — 現在の機能と Free／Pro

このガイドは、現在のバージョン 4.3.9 のインストール、ネットワーク設定、日常の操作を説明します。[公開済みリリース](https://github.com/2018-spec-fdsds/multiroute-downloader/releases/latest)からお使いのシステムに合うインストーラーを取得し、公開チェックサムと照合してください。Free と Pro の機能と上限は以下のとおりです。

### ライセンスの上限と機能

Free では通常の単一ファイルのダウンロード、対応する再開、利用可能な全速度、整合性検証、保護された DNS、ゲートウェイの現在速度・状態を利用できます。帯域を人為的に制限しません。署名された権限は独立しており、部分的な Pro ライセンスは含まれる権限のみ有効にします。

| 機能 | Free | 権限を含むライセンス | ID |
| --- | --- | --- | --- |
| 同時使用ゲートウェイ | ≤ 2 | ≤ 8 | `extra_gateways` |
| 同時ダウンロード | ≤ 3 | ≤ 32 | `extra_concurrent_downloads` |
| サイトプロファイル | ≤ 3 | ライセンス上限なし | `extra_site_profiles` |
| ダウンロード優先度 | 通常のみ | 選択可能 | `download_priorities` |
| ゲートウェイの優先度 | 0 | 選択可能 | `gateway_priorities` |
| ゲートウェイ履歴とレポート | 含まれない | 利用可能 | `gateway_statistics` |
| 一括ダウンロード / アップロード | 含まれない | 利用可能 | `batch_downloads` |
| 外部アプリ向け API | 含まれない | 利用可能 | `automation_api` |
| 追加テーマ | Graphite / System | すべてのテーマ | `premium_appearance` |

一括処理は **新しいダウンロード…** を開き、ウィンドウ下部の固定操作行で **URL の一覧…** を選びます。

署名付きライセンスに含まれる権限のみ有効になります。既存ファイルとプロファイルは保持されます。追加ファイルはキューで待機し、ゲートウェイの現在速度と状態は表示できます。保存領域の安全上限は適用されます。

ゲートウェイ上限はダウンロードとアップロードが共用する集合で、システム経路を追加しません。同時 3 タスクの上限はダウンロードだけに適用され、アップロードには適用されません。ほかのダウンロードは待機します。より低いキュー設定は有効なままです。既存のゲートウェイ、プロファイル、進行状況、優先度は削除されません。プロファイル上限は新規作成に適用され、既存分は使用できます。履歴・CSV は該当権限が必要ですが、ライブ表示は Free です。予約は利用でき、標準以外の優先度には権限が必要です。保存先・配信元の技術的制限は残ります。

署名ライセンスは MAC、IP、ルーターではなくインストール鍵に対応します。有効期限はなく、4–4 は 4.x を対象とします。ゲートウェイ、DHCP、アプリ MAC の変更で再認証は不要です。別の PC、ユーザー、データプロファイルでは新しい申請が必要な場合があります。改変不可能なコードや万能なハードウェア固定を約束するものではありません。

### アプリの MAC

MultiRoute は手動 IP と DHCP の両方で専用の固定 MAC を使い、OS のネットワークカード MAC は変えません。観測した機器や他の MultiRoute との競合を確認しますが、応答がなくても電源が切れた機器の不在は保証できません。 範囲はローカル管理のユニキャスト MAC（46 ランダムビット）です。DHCP の IP アドレス範囲ではありません。

**MAC を変更…** — 動作中・待機中の転送を一時停止または完了し、ローカル検証が終わってからボタンを使ってください。観測した送信元アドレスと他の MultiRoute の協調通知を調べます。「競合が見つからない」は、電源オフや無応答の機器が同じアドレスを使わない保証ではありません。アプリ MAC は物理アダプターと異なる必要があり、アダプターや OS 経路は変更しません。

### チェックサム…

参照値は再起動や進行状況の消去なしで保存されます。32、64、128 桁の16進数から MD5、SHA-256、SHA-512 を自動判別し、完了後に結合ファイルを検証します。 参照値を保存して「今すぐ検証」を選びます。完了済みローカルファイルを読み、不一致でも再ダウンロードや削除はしません。

最終検証には最後に保存した参照値を使用します。編集しても受信済みバイトを消去せず、転送を再開し直しません。ローカル再検証は完成ファイルを保持し、一致、不一致、エラーを別に表示します。公開元の参照値は独立して保持します。全体ハッシュ 1 個は torrent の 1 ファイルだけに対応します。整合性は内容の無害性を保証しないため、信頼できる SHA-256/SHA-512 を推奨します。

### 4.3.9 の API アクセス

ローカル JSON API は UTF-8 を使用し、通常の API トークンはありません。外部制御には automation_api が必要で、他の権限も確認されるため、それだけで一括処理や追加ゲートウェイは使えません。Free には限定した読み取り診断、非公開認証のライフサイクル処理、有効化できるブラウザーの単一リンク連携が残ります。[API](../API.ru.txt) と [OpenAPI](../openapi.yaml) を参照し、ポートを LAN／インターネットへ公開しないでください。

System 外観では、表の文字、入力欄、操作部にシステム背景に合ったコントラストを適用します。Graphite と System は Free に含まれます。

ファイル名とサイズは別々の列に表示されます。サイズは名前とは独立して数値順に並べ替えられ、不明なサイズはダッシュで表示されます。完全な名前とパスはツールチップで確認できます。

ファイル名にポインターを合わせると、完全な名前、保存先、転送プロトコル、ソースのアドレスまたはローカルパスを確認できます。メタデータを HTTPS で開いた場合も、トレントのプロトコルは BitTorrent と表示されます。リポジトリアドレスがあれば実際のファイル URL の後に表示されます。埋め込み認証情報、クエリ値、フラグメントは非表示で、認識された公開 magnet infohash は表示される場合があります。保存済み URL と転送状態は変わりません。


### 4.3.9 のゲートウェイ優先度と転送診断

ネットワーク設定で各ゲートウェイの優先度を **0～1000** に設定します。メイン画面のゲートウェイ表示の横にも値が表示されます。値が高いゲートウェイは小さなファイルやファイル全体の転送で優先され、大きなファイルではより多くの並列セグメントが割り当てられます。他の選択済み正常ゲートウェイも引き続き参加します。同じ値では選択順を保ち、優先ゲートウェイが失敗または停止した場合は別の選択済みゲートウェイが引き継げます。一定の速度比率を保証するものではありません。

独立した署名権限 **`gateway_priorities`** が必要です。タスク優先度の権限 **`download_priorities`** には含まれません。ゲートウェイ権限がない場合、すべての実効優先度は 0 となり、保存済みの値は保持されます。ダウンロード中に変更しても検証済み部分は消去されません。選択した各ゲートウェイに 1～4 個の並列セグメント処理を割り当て、タスク全体では最大 32 個です。

設定でライセンス範囲内の同時ダウンロード数と、自動再試行回数の有限・無制限を選択できます。手動の一時停止は維持されます。右クリックメニューで選択した対応タスクの一時停止・再開やファイル名のコピーができます。ダブルクリックはフォルダーのみを開き、プロパティ、統計、個別のダウンロードログは右クリックメニューから開きます。

完了したファイルの個別ログも参照できます。設定の「エラーと解決方法」は、全 12 言語に対応した 25 項目の検索可能なオフラインガイドです。保存先とプロパティには空き容量を GB 単位で表示します。ローカルディスクの容量不足は明示され、保存済み部分を保持してネットワークの無限再試行にはしません。小さなセグメントの再開後に新しいデータを待つ間も、保存済みの先頭部分を進捗に表示します。

### 残りのダウンロードデータ · 4.3.9

ダウンロード一覧に **残りのダウンロード量** 列を追加しました。残り時間の予測とは別に、未ダウンロードのバイト数を表示し、数値順で並べ替えられます。保存済みと受信中の進捗を反映し、ゼロ未満にはなりません。合計サイズが不明な場合はダッシュを表示します。

### Mac の起動とゲートウェイ設定をより確実に · 4.3.9

Mac のネイティブ起動では、先頭のスラッシュがない場合を含む旧来の相対既定パスを認識し、確認済みの既存プロファイルまたはユーザー所有の空の既定フォルダーを使います。曖昧なカスタム場所は推測せず、明示的な選択を求めます。

ゲートウェイの準備が失敗またはキャンセルされた後は、ネットワーク設定を明示的に再試行するまで、他のゲートウェイやバックグラウンド確認が認証要求を繰り返しません。最初の特権起動では Ethernet BPF デバイスを開くため、通常の macOS 管理者確認が必要な場合があります。

Mac ネットワーク部品 4.3.2 は macOS がアダプターの MAC を隠す場合に対応し、物理アダプターの保護確認を維持します。アプリ独自の MAC を使い、OS の経路や物理 MAC を変更しません。Mac のアイコンと名前は Windows と同じ MultiRoute の識別に統一されます。PKG 更新前にアプリを終了してください。実際の認証画面の要求元名と LAN/DHCP 転送は引き続き実機での確認が必要で、この転送には有線 Ethernet が必要です。

**macOS:** `/Applications/MultiRoute Downloader.app` · `/Library/PrivilegedHelperTools/MultiRouteResume/4.3.2/{gateway-net,gateway-launch}`.

### Mac の手動アドレスでのゲートウェイ応答 · 4.3.9

POSIX のキャプチャ設定を修正し、手動のアプリアドレスと DHCP の両方でアプリ独自の MAC 宛ての応答を受信できるモードを使います。既存の Windows 動作と同じです。システム ping の成功はコンピューター自身の接続確認であり、アプリの仮想アドレスへの応答受信を証明しません。

DHCP の診断は一般的なエラーに置き換えず、十二言語の具体的な説明を維持します。既存の認証動作は変わりません。通常のネットワーク確認は準備済み部品を再利用します。API、画面の操作項目、OS の経路や物理 MAC は変更しません。最初の特権 Ethernet BPF アクセスでは通常の管理者確認が必要な場合があります。

これは一つのキャプチャモードの差の修正であり、すべてのゲートウェイ接続障害を解決するものではありません。アドレス空き、サブネット、DHCP リースと競合の確認は維持します。Mac の手動アドレス転送は実機での確認が引き続き必要で、有線 Ethernet が必要です。

## 外観と完了音

**外観設定**で **StreamsStudio**、**Graphite**、**Nordic**、**Neon**、**Community**、**Chat**、**Studio**、**Rose**、**System** から選択します。Free には Graphite と System が含まれ、他のスタイルには対応する Pro の外観権限が必要です。設定はローカルに保存され、ダウンロードは再起動されません。**ウィンドウとボタンの角丸**は独立した設定です。各スタイルの操作部品に角丸を適用できますが、ウィンドウ外枠は OS が管理します。Windows 11 では最大化やスナップ中に直角のままになる場合があり、macOS と Linux の外枠もシステム側で決まります。速度グラフには十分な描画領域があり、ネットワーク設定にはコンパクトなゲートウェイカードを使用します。

完了音は**既定ではオフ**です。全体の有効化チェックボックスをオンにし、**ファイルごとの完了**と**すべてのダウンロードの完了**を個別に選びます。**柔らかなベル**、**ピアノ**、**マリンバ**から選択し、それぞれの完了メロディーを試聴できます。すべてのダウンロードが完了し、全体の通知が有効な場合、最後のファイルでは最終メロディーだけを再生し、二重に鳴らしません。一時停止や失敗のタスクは完了扱いになりません。起動時や設定変更時に過去の完了履歴を再生することもありません。システムの音量と出力先も確認してください。

独自の音を使う場合は**カスタムメロディー**を選び、ファイル完了用と全ダウンロード完了用に別々の **MP3 または WAV** ファイルを指定します。各音声は**10 秒以下**にしてください。アプリは拡張子やメタデータだけで判断せず、デコード後の実際の長さを検証します。受け付けた音声はローカルのアプリプロファイルにコピーされるため、その後は元ファイルを移動できます。

外観設定では、体に合った夏服を着た写実的な成人の **MultiRoute 配達員**を男性または女性から選べます。配達員は独立したデスクトップウィジェットに表示されます。袋の大きさと表示は**進行中の全ダウンロードの残りデータ量の合計**を反映し、ゲートウェイの数にかかわらず各ファイルを一度だけ数えます。バイトを受信するにつれて袋は徐々に小さくなり、残りデータ量によって荷物の状態が変わります。**1 GB 未満**は肩に担ぎ、**1 GB 以上 10 GB 未満**は床を引きずり、**10 GB 以上**はさらに力を込めます。歩行や走行の速さは別に実際の合計ダウンロード速度に応じ、待機中は停止します。新たな完了後、配達員はそのデスクトップウィジェットの右端まで進み、袋を置いて滑らかに消えます。ダウンロードがまだ進行中なら、新しい荷物を持って再び現れます。配送中の袋の表示は届ける荷物のサイズを示し、戻った後は進行中の全ダウンロードの残りデータ量の合計を再び示します。これは演出のみで、実際のファイルは選択したフォルダーに残ります。表示設定は保存され、非表示や待機中はアニメーションを止め、起動時に過去の完了を再生しません。配送動作はサウンド設定と独立しています。これらは独自に生成したキャラクターで、Codex や OpenAI とは関係ありません。

外観、角丸、音はデスクトップのローカル設定です。ダウンロード API のエンドポイントを追加したり、転送、チェックサム、DNS 保護の設定を変更したりしません。

## 起動時のデータフォルダー

ネイティブアプリは、ログイン時の作業ディレクトリに依存しない絶対パスでデータフォルダーを保存します。保存された相対プロファイルパスは、対象の既存プロファイルを一意に確認できる場合にのみ絶対パスに変換します。ダウンロード履歴、設定、保存済みの分割データは元の場所に残ります。ポータブル版のコマンドラインの相対パスと明示的な `--data-dir` は、それぞれ指定された動作を維持します。

<a name="automatic-startup"></a>

<a name="421-の自動起動"></a>

## 自動起動

言語と外観の設定の横にある **OS と同時に起動**を有効にします。**既定では無効**です。有効にすると、自分のアカウントの次回ログイン時に MultiRoute を起動する項目を登録し、無効にするとアプリ自身の起動項目を削除します。ユーザーのログイン時に起動する機能であり、システムサービスやログイン前の起動ではありません。項目の登録に管理者権限は不要です。

自動起動時は、利用可能ならトレイを使用し、利用できない場合は通常の操作可能なウィンドウを表示します。キューの優先度、一時停止、予定は維持され、一時停止中のすべてのダウンロードを強制的に再開しません。まず手動でアプリを開き、インストールとネットワークの準備を完了してください。登録したアプリの場所を維持し、ポータブル利用では Java とライブラリの場所も維持してください。移動後は新しい場所から自動起動を一度無効にして再度有効にします。アンインストール前に無効にしてください。

OS やデスクトップのポリシーが登録項目を無効にする場合があります。macOS で許可を求められたら、**システム設定 → 一般 → ログイン項目と機能拡張**を確認してください。ネットワーク部品の許可とは別です。登録状態だけでは将来のログイン時の起動成功を証明できません。専用テストプロファイルによる検証には実際の再起動やログアウトは含まれません。対応するリリースレポートを参照してください。

アプリを開けない場合は、**アプリ自身の項目だけ**を削除します。

- **Windows:** アプリは `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` に **MultiRoute Downloader** という自身の `REG_SZ` 値を保存します。通常はアプリ内で自動起動を無効にしてください。アプリを開けない場合は、レジストリエディターで **その値だけを削除**し、Run キーや他の項目は残します。OS が無効にした場合は、**設定 → アプリ → スタートアップ**で操作してください。アプリはその決定を上書きしません。Windows の起動コマンド全体は 260 文字までです。超過する場合はアプリやプロファイルのパスを短くして再登録してください。
- **macOS:** `~/Library/LaunchAgents/io.github.2018-spec-fdsds.multiroute-downloader.plist` を削除します。
- **Linux:** 実際の XDG 設定ディレクトリから `${XDG_CONFIG_HOME:-~/.config}/autostart/io.github.2018-spec-fdsds.multiroute-downloader.desktop` を削除します。XDG 自動起動対応のグラフィカルデスクトップが必要です。この設定は systemd サービスを作成しません。

<a name="422-の-dns-設定"></a>

## DNS 設定

**4.3.9 インストーラーのバージョンと公開チェックサムを照合し、プラットフォームおよびパッケージの検証結果は対応する NATIVE-INSTALLER-TESTS.json で確認してください。**

**ネットワーク → DNS 名前解決**を開きます。既定値は **DNS over HTTPS（DoH）、Cloudflare** です。MultiRoute 専用の設定で、OS の DNS、ルート、インターフェース IP は変更しません。

DoH は TLS ALPN が選択する制限付き HTTP/2 と、協議された場合の HTTP/1.1 に対応します。サービス互換性と実ゲートウェイの結果は、対応する最終リリースレポートで確認してください。

- **DoH：**選択した各ゲートウェイ経由の HTTPS 暗号化 DNS。URL のホスト名で TLS 証明書を検証します。
- **DoT：**選択した各ゲートウェイ経由の TLS DNS。既定ポートは 853 で、サーバー名で証明書を検証します。
- **システム DNS（コンピューター）：**コンピューター、OS、VPN の DNS 方針を明示的に使用します。DNS が各ゲートウェイを通る保証はありませんが、ファイル接続は選択ゲートウェイを使用します。このモード自体は DNS 暗号化を保証しません。

Cloudflare、Quad9、Google、**カスタム**から選びます。プリセット値は固定で、カスタムでは URL/サーバー名、ポート、数値の公開 IPv4 ブートストラップアドレスを編集できます。数値アドレスで接続するため、サービス名を OS で事前解決する必要がありません。DoH/DoT は信頼チェーン、ホスト名、SNI を検証し、平文やシステム DNS へ黙って切り替えません。安全な DNS が失敗するとその試行は終了します。選択ゲートウェイから到達できるサービスを使用してください。

下書きを編集し、ゲートウェイを選んで **DNS をテスト**します。保存せず、各ゲートウェイの結果、時間、公開 IPv4 またはエラーを表示します。一部失敗も残ります。システムモードの成功は OS の名前解決を確認するだけで、各ルーターの独立 WAN を証明しません。**DNS 設定を適用**で検証・保存し、返されたリビジョンが適用状態を示します。状態更新や言語変更でも未保存の下書き、カーソル、スクロールを維持します。

各問い合わせの合計制限は補助 DNSSEC 問い合わせを含め 8 秒です。検証済み TTL は署名期限も反映します。ネイティブキャッシュは最大 300 秒でゲートウェイ・設定リビジョンごとに分離します。TTL 0 と DoH HTTP Age は維持されます。システムモードは OS/JVM のキャッシュに従います。公開 IPv4 のファイル宛先をサポートし、IPv6 名前解決には対応しません。

API：`GET /api/v1/network/dns` は設定と読み取り専用状態を取得し、同パスの `PUT`/`POST` は設定を適用します。`POST /api/v1/network/dns/test` は下書きをテストし、`GET /api/v1/network/dns/providers` はプリセットを列挙します。GET のリビジョン/状態を除いた設定フィールドだけを送信してください。[API](../API.ru.txt) · [OpenAPI](../openapi.yaml)。

<a name="422-のローカル-dnssec-検証"></a>

## ローカル DNSSEC 検証

**ネットワーク → DNS 名前解決 → DNSSEC 検証**で、**署名付きドメインを検証**（DoH/DoT の既定）、**安全な DNSSEC 応答を必須にする**、**DNSSEC 無効化**を選択します。Java が dnsjava と同梱のルートトラストアンカーでローカル検証します。上流の AD フラグだけでは証明になりません。DoH/DoT は通信を暗号化し、DNSSEC は DNS データの真正性を別途確認します。

**検証**は安全な応答と保護未確認の応答を許可し、**必須**は安全な応答のみ許可します。保護未確認は認証された未署名の委任や未対応のアルゴリズムを示す場合があります。理由を確認してください。検証中は無効・判定不能の結果を拒否します。システム DNS はローカル検証を無効にし、DoH/DoT に戻ると前のポリシーを復元します。プロバイダー変更でも維持されます。適用で保存、DNS テストで未保存の下書きを検査します。

各問い合わせで `secure`、`insecure`、`bogus`、`indeterminate`、`not_checked` を区別し、結果がない場合は利用不可と表示します。接続成功は DNSSEC の安全判定ではありません。期限切れ、鍵・証明の不足、問い合わせ失敗、タイムアウトには別の理由があります。時計を正確にしてください。補助検証も同じゲートウェイと全体の制限時間を使います。DNSSEC は名前を隠さず、ダウンロード内容も検査しません。

API の `dnssec` は `off`、`validate`、`require` を受け付け、システムモードでは `off` のみです。`dnssec_validation`、`dnssec_trust_anchors` と各問い合わせの `dnssec_status`、`dnssec_reason_code`、`dnssec_reason`、`dnssec_validated_ttl`、`dnssec_aux_queries` は読み取り専用です。設定保存時に送り返さないでください。上記 API/OpenAPI と [DNSSEC](#422-のローカル-dnssec-検証)を参照してください。

**セグメントダウンロードと CDN：** Civitai などの CDN がゼロから始まる範囲に HTTP 200 を返す場合、ゼロ以外から始まる範囲も確認します。最初のセグメントは指定サイズまで読み取り、元のファイルと一致する保存済みの連続データを分割ダウンロードへ引き継げます。後続の範囲に一時的な HTTP 200 が返ると、保存済みデータとゲートウェイのワーカーを維持して 2～30 秒後に再試行します。ゲートウェイ別の永続ログで受信量と保存済み進捗を区別できます。[転送診断](transfer-diagnostics.en.md)。

[4.3.9 インストーラー](../downloads/v4.3.9/README.md)には専用の Java 21 が含まれます。Windows のセットアップは英語で表示され、デスクトップにショートカットを作成します。Npcap は別途必要です。macOS はシステムの libpcap を使用します。以下のインストール手順とセキュリティ確認に従ってください。

<a name="1-目的と仕組み"></a>

## 目的と仕組み

MultiRoute Downloader は、同じ Ethernet LAN にある複数のインターネット**ゲートウェイ**を同時に使う Java デスクトップダウンローダーです。例えば固定回線とモバイル 4G/5G ルーターを組み合わせられます。選択した利用可能なゲートウェイが共有キューからファイルの断片を受け取り、高速な回線はより多くの断片を担当します。回線が一つ切れても他は継続し、未完了の断片をキューに戻して検証済みデータを保持します。リンク一覧の一括登録と他のアプリ向けのローカル API も利用できます。

速度向上は各回線の独立した帯域、配信元の制限、安全な再開の対応状況に依存し、ルーター数に比例する保証はありません。ブラウザー用の操作画面ではなく独立したデスクトップアプリです。新しいプロファイルは英語で開始します。英語、ロシア語、ドイツ語、スペイン語、フランス語、中国語、韓国語、アラビア語、イタリア語、日本語、ヒンディー語、ベトナム語を選べます。設定と登録済みメッセージ、ログ、ヒントは言語に追従します。外部サーバーやライブラリの未登録メッセージは原文の場合があります。ファイル名、パス、URL、JSON のキーは翻訳しません。

<a name="application-virtual-ip"></a>

### アプリが仮想 IP を使う理由

**他のアプリの接続を変えずに、MultiRoute で使うゲートウェイを選択できます。** アプリは内部ネットワーク転送用に、未使用の専用ローカル IPv4 アドレスを使います。これにより、PC の既定ゲートウェイに依存せず選択したゲートウェイ経由で接続でき、OS のアダプターアドレス、経路表、既定ゲートウェイは変更しません。ブラウザーなど他のプログラムは従来のネットワーク設定を使い続けます。

例えば `192.168.1.0/24` の LAN では、PC は通常のアドレス `192.168.1.x` を維持し、MultiRoute は空いている `192.168.1.70` を使い、ダウンロードには `192.168.1.1`–`192.168.1.4` を利用できます。PC、仮想アドレス、選択したゲートウェイは、実際に同じ IPv4 サブネットに属する必要があります。アプリのネットワーク設定で未使用アドレスを確認して適用し、OS アダプターへ手動で追加しないでください。仮想 IP が新しいインターネット回線を作るわけではなく、帯域はルーターとその上流回線から提供されます。

#### アドレスの選択と確認

1. PC の Ethernet アダプターの IPv4 とサブネットマスクを確認し、同じサブネット内の有効なホストアドレスを選びます。`192.168.1.70` は例にすぎません。PC 自身、ゲートウェイ、ネットワーク、ブロードキャストのアドレスは使わないでください。
2. ルーター管理画面で実際の DHCP 配布範囲を確認します。自動配布範囲外のアドレスを使うか、DHCP サーバーで予約・除外してください。同じ LAN に複数の DHCP サーバーがある場合、すべてのサーバーで他の機器への割り当てを防ぐ必要があります。
3. MultiRoute で仮想アドレスの **確認して適用** を実行し、続けてゲートウェイを確認します。アプリはサブネットを検証し、ARP で競合を確認します。ARP 応答がないことは、その時点で競合を検出しなかったという意味であり、DHCP 配布範囲外であることの証明や、後の割り当てを防ぐ保証にはなりません。

Windows/macOS インストーラーには専用 Java 21 とコンパイル済みネットワークコンポーネントが含まれます。Windows では別途 Npcap ドライバーが必要です。Java を別にインストールする必要はありません。

| Windows x64 | Windows 11 | Java 21 |
| Apple Silicon | macOS 26+ | Java 21 |

インストール承認、ネットワーク部品の承認、不明な開発元の例外は別の確認です。必要に応じてローカルネットワークと実際の保存フォルダーへのアクセスを許可します。Gatekeeper/SIP を無効にせず、隔離属性を一括除去せず、Java 全体を root にしないでください。マルウェアや破損ファイルの警告なら中止して確認します。

<a name="4-ゲートウェイと仮想-ip"></a>

## ゲートウェイと仮想 IP

初期ゲートウェイのアドレスは `192.168.1.1`、`192.168.1.2`、`192.168.1.3`、`192.168.1.4` です。実際のネットワークに合わせて編集し、到達可能なゲートウェイを選択してください。追加・編集・削除で **1–8** 個の重複しないゲートウェイプロファイルを管理できます。Free では同時に最大 **2 つ**、`extra_gateways` 権限を含む Pro では最大 **8 つ**のゲートウェイを使用できます。初期アドレスが四つあることは、すべてが有効になることを意味しません。PC が一つを既定経路にしていても、五つ目の回線が増えるわけではありません。

アプリの仮想 IPv4 は初期値 `192.168.1.70`。ネットワーク設定で未使用を確認して適用し、DHCP 自動割当の範囲外に予約します。内部転送専用で、**OS アダプターへのアドレス追加やシステム経路表の変更は行いません**。他のアプリは従来の接続を使います。OS のネットワーク画面で手動追加しないでください。隣の「?」とヒントを参照します。

ゲートウェイを検査して、使用可能なものを一つ・複数・すべてから選択します。実際の同時使用数には上記のライセンス上限が適用されます。速度テストは **16 MiB または 5 秒**までで、接続準備に追加時間がかかる場合があります。通常ダウンロードの上限ではありません。適切な直接 HTTP URL がなければ Selectel のテストファイルを使います。

転送中もプロファイルの追加/削除や作業の選択を変更できます。ただし未完了作業ごとに一つ以上のゲートウェイを残します。追加プロファイルは既存作業に自動選択されません。仮想 IP 自体を変更する前に活動中の作業を一時停止します。アプリ MAC の用途、確認、変更条件は上記のアプリ MAC の説明を参照してください。

<a name="5-ダウンロードと画面操作"></a>

## ダウンロードと画面操作

1. 長い URL 欄に Ctrl+V、macOS は Cmd+V、または貼り付けボタンで入力します。magnet と `.torrent` も利用できます。
2. OS のフォルダー選択で保存先を指定します。既定値は Windows の `%USERPROFILE%\Downloads`、macOS/Linux の `~/Downloads`。手動指定は保持します。
3. ゲートウェイを選び URL の横の開始を押します。Hugging Face、WebDAV、Metalink はファイルをプレビュー選択できます。一括登録は 1 行 1 URL またはテキストファイルです。
4. 各作業の進捗、経過/残り時間、全体と各ゲートウェイの速度/転送量を確認します。HTTP 断片は標準 **20 MiB**、1–64 MiB に変更可能です。**60 秒**データが来ない断片は中止して共有プールに戻し、他ゲートウェイに渡します。torrent ピースサイズはメタデータによります。
5. 一時停止/再開、優先度、速度制限、予約、停止作業のフォルダー変更ができます。既定の同時作業は 2 件。再起動時の活動作業は停止状態で復元します。torrent シードは標準無効で、時間/比率の上限を設定できます。

FlatLaf のライト/ダーク/システムテーマを保存できます。サマリーはフィルターに関係なく全件、活動中、完了と全作業合計速度を示します。個別進捗バー、全幅列、ソート、検索、状態フィルター、読み位置を保つスクロールを利用できます。

進行中/完了行にカーソルを置くと**完全なファイル名と絶対保存パス**を表示します。ソートやフィルター後も正しい行に対応し、選択ファイル見出しにも同じヒントがあります。右クリックで完全パスをコピー。Ctrl+L/Cmd+L は URL、Ctrl+F/Cmd+F は検索、Escape は検索解除です。

選択作業の「詳細」と「履歴」を切り替えられます。レポートは更新・言語変更でも閲覧位置と選択を保持し、別作業では先頭を開きます。全体ログはアプリイベントとダウンロード履歴を分離し、末尾では新規イベントに追従、過去を読む際は強制移動しません。

窓を閉じてもトレイで継続します。アイコンは全作業の合計速度を 10 Gbit/s まで表示し、ヒントで正確な値を示します。トレイの「開く」で復帰、「終了」で保存・終了します。トレイ非対応ならタスクバーに最小化します。**更新前はトレイから終了**してください。

Windows/Linux では **Ctrl**、macOS では **Cmd** を押しながらクリックすると複数のダウンロード行を選択できます。**Shift** を押しながらクリックすると範囲を選択します。表にフォーカスがあるときの **Ctrl+A** または **Cmd+A** は、検索と状態フィルターを適用した現在の表示行だけをすべて選択します。削除操作は選択したグループ全体に適用され、確認は一度だけです。完了ファイルとダウンロード済みの部分も削除するオプションは**初期状態ではオフ**なので、データを残して一覧の記録だけを削除できます。それらの作業のファイルを消す場合にだけオンにしてください。他のファイルと保存先フォルダーは保持されます。結果には削除された記録数が表示されます。削除できなかった作業はエラーの概要とともに一覧に残るため、確認して再試行できます。成功した削除は繰り返されません。作業やファイルを削除しても永続的なダウンロード履歴は消えません。

<a name="6-プロトコルと整合性"></a>

## プロトコルと整合性

| ソース | 動作・条件 |
| --- | --- |
| HTTP/HTTPS | 安全な識別と byte ranges がある場合に断片再開。なければ単一ゲートウェイの全体ストリームで切断後は最初から |
| Hugging Face | ファイル/リポジトリ選択と Hub/Xet 解決。非公開や制限付きは権限が必要 |
| FTP | パッシブ EPSV/PASV。平文 FTP は認証情報やデータを暗号化しません |
| FTPS | 制御/データに明示的 TLS。暗黙 FTPS は非対応 |
| SFTP | 独立に確認・固定した SHA256 SSH ホスト鍵指紋が必要。不明な鍵は自動受理しません |
| WebDAV | HTTPS 一覧とファイル選択 |
| Metalink | `.meta4`、信頼する SHA-256、ミラーと提供されたピースハッシュ |
| Torrent/magnet | 選択ゲートウェイで転送しメタデータによるピース検証が必須。選択/優先度に対応 |

配布元アクセスにユーザー/パスワード、Bearer token、Cookie、許可されたヘッダーを正確な origin ごとに暗号化保存できます。ルーター用 token ではありません。URL にパスワードを含めないでください。信頼できる公開/手動 SHA-256 または SHA-512 がない FTP/FTPS/SFTP は全体ストリームを使います。

組み立て後に一回の読み取りで **MD5、SHA-256、SHA-512** を計算します。主欄は 32/64/128 桁の 16 進数で種別を自動判定し、追加参照も設定可能。全体表現の摘要ヘッダー、`filename.md5`、`MD5SUMS`、`filename.sha256`、`SHA256SUMS`、`filename.sha512`、`SHA512SUMS`、Hugging Face LFS/Metalink を利用します。部分 HTTP 応答の摘要は全体の値としません。

既知参照は最終ファイル公開前にすべて一致が必要で、不一致なら部分データを保持して失敗します。参照がなければローカル計算値であり、公開元との一致確認ではありません。MD5 は偶発的破損用で、強い識別や SHA-256/SHA-512 の代用にはなりません。torrent ピース検証と全体ハッシュは別で、手動全体参照は選択ファイル一つの場合だけです。

## 他のアプリから API を使う

実行中は `http://127.0.0.1:8765/api/v1` にローカル API があります。JSON UTF-8、本文に `Content-Type: application/json` を指定します。ローカル作業管理に API token は不要で、配布元認証は別です。同じ PC の接続だけを受け付け、LAN/インターネットに公開しないでください。`--headless` は API 専用です。ネイティブ起動器を使い、`.cmd` 例は portable 用です。

以下の外部管理の例には `automation_api` 権限が必要です。四つのゲートウェイを使用する例の構成には、`extra_gateways` 権限も必要です。実際のネットワークとライセンスに合わせて `gateways` と `routes` を調整してください。Free は同時に最大 2 つ、対応する Pro 権限がある場合は最大 8 つのゲートウェイを使用できます。

確認は `GET /api/v1/health`、通常 `{"ok":true,"version":"4.3.9"}`。先に画面で設定するか `POST /api/v1/network` に次を送ります。

```json
{
  "virtual_ip": "192.168.1.70",
  "gateways": ["192.168.1.1", "192.168.1.2", "192.168.1.3", "192.168.1.4"]
}
```

`POST /api/v1/jobs` の例です。URL と実際の保存先、必要ならゲートウェイを変更します。Linux は `/home/your-user/Downloads`、Mac は `/Users/your-user/Downloads`。`routes` は明示し、画面のチェックを自動継承しません。

```json
{
  "url": "https://example.org/large-file.bin",
  "directory": "C:/Users/your-user/Downloads",
  "chunk_mb": 20,
  "routes": [
    {"type": "gateway", "gateway": "192.168.1.1", "enabled": true},
    {"type": "gateway", "gateway": "192.168.1.2", "enabled": true},
    {"type": "gateway", "gateway": "192.168.1.3", "enabled": true},
    {"type": "gateway", "gateway": "192.168.1.4", "enabled": true}
  ]
}
```

`HTTP 201` は登録成功で、完了ではありません。`id` を保持して `GET /api/v1/jobs/{id}` の `status: complete` を確認し、失敗時は `error` を読みます。`speed_bps` は**バイト/秒**、8 倍して 1,000,000 で割ると Mbit/s です。

| HTTP | API |
| --- | --- |
| GET | `/api/v1/health` |
| GET / POST | `/api/v1/jobs` |
| GET | `/api/v1/jobs/{id}` |
| POST | `/api/v1/jobs/{id}/pause` |
| POST | `/api/v1/jobs/{id}/resume` |
| POST | `/api/v1/jobs/{id}/routes` |
| DELETE | `/api/v1/jobs/{id}` |
| GET / POST | `/api/v1/network` |
| POST | `/api/v1/jobs/batch` |
| GET / POST | `/api/v1/queue` |
| GET | `/api/v1/events` |

停止/再開は `{}`。削除本文、既定のファイル保持、`Idempotency-Key`、キュー、一括、SSE、認証、制限の詳細は [OpenAPI](../openapi.yaml)。`expected_md5`、`expected_sha256`、`expected_sha512` を指定でき、結果は `md5`、`sha256`、`sha512`、`checksum_sources` と警告を返します。JSON キー/状態は言語不変。[追加例](../API.ru.txt) はロシア語です。

Python 3 例です。URL を置換し、先にネットワークを設定してアプリを開いたまま実行します。UTF-8 は日本語パスも保持します。

```python
import json
import urllib.request
from pathlib import Path

data = {
    "url": "https://example.org/large-file.bin",
    "directory": str(Path.home() / "Downloads"),
    "chunk_mb": 20,
    "routes": [
        {"type": "gateway", "gateway": f"192.168.1.{n}", "enabled": True}
        for n in range(1, 5)
    ],
}
request = urllib.request.Request(
    "http://127.0.0.1:8765/api/v1/jobs",
    data=json.dumps(data, ensure_ascii=False).encode("utf-8"),
    headers={"Content-Type": "application/json; charset=utf-8"},
    method="POST",
)
with urllib.request.urlopen(request, timeout=30) as response:
    job = json.loads(response.read().decode("utf-8"))
print(job["id"])
```

## 履歴とデータの保存・更新

| 環境 | データ | アプリ/runtime |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%\MultiRoute Downloader\data` | `%LOCALAPPDATA%\MultiRoute Downloader App` |
| macOS | `~/Library/Application Support/MultiRoute Downloader/data` | `/Applications/MultiRoute Downloader.app` |
| Linux | `~/.local/share/MultiRouteResume/data` | `~/.local/share/MultiRouteResume/` |

`logs/downloads-history.jsonl` は UTF-8 の行単位 JSON、`logs/downloads-history.log` は日時付きテキストです。再起動をまたいで追記し、作業削除や言語変更で過去を書き換えません。テキストは記録時の言語、画面は現在の言語です。表示は最大直近 1,000 イベント/2 MiB ですが完全な履歴はディスクに残って増加します。必要なら別途アーカイブしてください。名前と絶対パスを含み、配布元 URL、パスワード、token を含みません。共有前に個人パスを確認します。

`lifecycle_history` の項目は `event_id`、`job_id`、`kind`、`time`、`filename`、`path`、torrent では `paths`、一時停止では `reason`（`pause`、`shutdown`、`maintenance`）を持つ場合があります。種類は `started`、`resumed`、`paused`、`completed`、`recovered`、`failed`。ISO 8601 UTC（`2026-10-18T12:34:56.123Z`）で記録し、テキストには現地日付・時刻・UTC オフセットを表示します。任意の `first_started_at`、`last_resumed_at`、`completed_at` は実際に観測した開始/再開/検証と公開後の完了です。キュー登録は開始でなく、古い日時を推測しません。`recovered` は旧公開ファイルの現在の検証で、過去の完了時刻が判明した意味ではありません。

更新前にトレイから終了し完全な新パッケージを導入し、履歴・断片を保持します。Windows は設定のインストール済みアプリから削除。Mac の `.app` 削除だけでは履歴/保護部品は消えません。アンインストールのために保存先全体を消さないでください。Linux の場所を移したら再配備します。

<a name="保存したサイトアップロードアーカイブのプレビュー40"></a>

## 保存したサイト、アップロード、アーカイブのプレビュー

**サイトプロファイル…** で作成・編集し、**ダウンロード** または **アップロード** の一覧から選択します。ゲートウェイと仮想 IP は **ネットワーク設定** にあります。**アップロード** では**リモートフォルダー URL** を入力し、**ファイルを選択してアップロード…** で OS の選択画面から一つ以上のローカルファイルを選びます。画面は名前を追加しますが、API `target_url` には完全なリモートファイル URL を指定します。アーカイブ URL を主入力欄に貼り **アーカイブの内容…** を押すと、ダウンロードせずにプレビューします。

サイトの名前、基本 URL、ローカル保存先、リモートフォルダー、ゲートウェイをプロファイルに保存できます。匿名、HTTP Basic/Bearer/Cookie/独自ヘッダー、FTP、確認済み SHA-256 ホスト鍵を使う SFTP に対応し、同一サーバーの複数アカウントを分離します。明示した保存先/ゲートウェイが優先し、相対 URL は基本 URL から解決されます。秘密情報は所有者限定の `site-profiles/vault.bin` にローカル鍵 `site-profiles/key.bin` で暗号化されますが、アカウントと鍵を制御できる人には読み取れます。公開 API は秘密を返しません。空欄は接続元と認証方式が同じ場合にだけ既存情報を保持し、`replace_credentials:true` は置換します。異なる接続元への HTTP リダイレクトには認証情報を渡しません。プロファイル削除はジョブやローカル/リモートファイルを削除しません。ジョブは元のプロファイルとの結び付きを保持し、アカウントを変更できません。元を削除した場合、必要に応じて有効なプロファイルでジョブを作り直してください。

アップロードとリモート参照は選択ゲートウェイ経由の **FTP、明示的 FTPS、SFTP** に対応します。通常のローカルファイルと、フォルダーだけでない完全なリモートファイル URL（`target_url`）を指定します。一時ファイルを使い、既存の先頭部分を比較してから再開します。成功にはリモート全体を読み戻して SHA-256 を確認するため、**読み取り・書き込み・名前変更**権限と追加通信量が必要です。不一致や読み取り拒否は失敗です。各ファイルは一度に一つのゲートウェイを使い、複数ファイルは分散して並列送信します。無通信期限後は別ゲートウェイへ切り替えられますが、一つの送信ファイルを並列分割しません。一時停止・再開・進捗は再起動後も保持されます。ジョブ削除でもローカルファイルとリモートの完成/一時ファイルは残ります。

上書きは初期状態では無効です。FTP/SFTP には「宛先がなければ原子的に名前変更」が常に備わるとは限らず、公開時に他のクライアントとの競合があり得ます。共有する宛先を調整してください。フォルダー参照は送信も削除もしません。

**ZIP、TAR、7Z、RAR4、RAR5** の名前、パス、サイズ、フォルダー/暗号化情報を、展開や実行なしで表示します。ゲートウェイ、バイト範囲、安定した ETag または Last-Modified が必要です。メタデータ 16 MiB、10,000 件、60 秒、7z ヘッダー解読メモリ 64 MiB の制限があります。一覧は省略される場合があり、内容の整合性確認ではありません。文字化けには元の文字コードを指定します。対応する暗号化 7z ヘッダー用パスワードは保存しません。暗号化 RAR ヘッダーは未対応/パスワード必要と報告され、分割アーカイブは一部だけの場合があります。

API はダウンロード、送信、参照、プレビューで `site_profile_id` を受け付けます。`GET /api/v1/site-profiles` は `{profiles:[...]}`、`POST`/`PUT` は平坦なプロファイルの保存と公開項目の返却、`DELETE /api/v1/site-profiles/{id}` はプロファイルだけの削除です。`POST /api/v1/uploads` は `local_path`、`target_url`、`routes`、任意の `site_profile_id`、`overwrite:false` を受け、HTTP 201 を返します。GET は `{uploads:[...]}`、個別 GET/DELETE、POST `/{id}/pause` / `/{id}/resume` も利用できます。`POST /api/v1/remote/list` は `url` と `route`/`routes`、`POST /api/v1/archives/preview` はさらに任意の `password`、`charset` を受け付けます。[openapi.yaml](../openapi.yaml) を参照してください。`data/uploads/` の UTF-8 マニフェストはパスワードではなくプロファイル ID を保持します。プレビューはダウンロードを作成しません。

## ダウンロードの予定と優先度

キュー/予定で `max_active_jobs`（1–32）、全体/ゲートウェイ速度制限、毎日の時間帯（`schedule_enabled`、`schedule_start`、`schedule_end`、HH:mm）を設定します。PC の現地時刻で、API は `schedule_timezone` を返します。日付をまたげます。開始と終了が同じなら終日です。時間外はキューに戻り、手動一時停止は維持されます。`priority` -100〜100 は待機中を高い順、同値なら作成順に開始し、実行中を中断しません。`start_after_ms` は最早開始の Unix ミリ秒で、0 は遅延解除です。設定は再起動後も保存され、独立したアップロードキューには適用されません。アプリと PC を起動してスリープさせないでください。OS の自動復帰機能ではありません。API：`GET`/`PUT`/`POST /api/v1/queue`、`PUT`/`POST /api/v1/jobs/{id}/options`。

## Chrome と Edge の連携

アプリの **Chrome / Edge** 連携を開き、リンク送信を有効にして同梱拡張機能フォルダーを開きます。`chrome://extensions` または `edge://extensions` でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」でそのフォルダーを選びます。選択したフォルダーを移動しないでください。

MultiRoute はトレイでもよいので実行しておきます。リンクの右クリックメニューまたは拡張ポップアップから URL を送ります。現在の保存先、ゲートウェイ、サイト設定を使い、必要なリポジトリ/torrent 選択は表示されます。既定ポート 8765 は API に合わせて変更できます。URL だけを送信し、Cookie/パスワードをコピーせず、他のブラウザーダウンロードを横取りしません。認証はアプリ側で設定します。ローカル接続の許可はこの選択した拡張だけに与えてください。
