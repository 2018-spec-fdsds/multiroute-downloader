## 4.3.9 — 현재 기능, Free와 Pro

이 안내서는 현재 버전 4.3.9의 설치, 네트워크 설정과 일상적인 사용 방법을 설명합니다. [게시된 릴리스](https://github.com/2018-spec-fdsds/multiroute-downloader/releases/latest)에서 시스템에 맞는 설치 프로그램을 받고 공개 체크섬과 비교하세요. Free와 Pro의 기능 및 한도는 다음과 같습니다.

### 라이선스 제한 및 기능

Free는 일반 단일 파일 다운로드, 지원되는 이어받기, 사용 가능한 전체 속도, 무결성 검사, 보호된 DNS와 게이트웨이 실시간 속도/상태를 제공합니다. 대역폭을 인위적으로 제한하지 않습니다. 서명된 권한은 독립적이며 부분 Pro 라이선스는 포함된 권한만 활성화합니다.

| 기능 | Free | 라이선스에 권한 포함 | ID |
| --- | --- | --- | --- |
| 동시에 사용하는 게이트웨이 | ≤ 2 | ≤ 8 | `extra_gateways` |
| 동시 다운로드 | ≤ 3 | ≤ 32 | `extra_concurrent_downloads` |
| 사이트 프로필 | ≤ 3 | 라이선스 할당량 없음 | `extra_site_profiles` |
| 다운로드 우선순위 | 기본만 | 선택 가능 | `download_priorities` |
| 게이트웨이 우선순위 | 0 | 선택 가능 | `gateway_priorities` |
| 게이트웨이 기록 및 보고서 | 포함 안 됨 | 포함 | `gateway_statistics` |
| 일괄 다운로드 / 업로드 | 포함 안 됨 | 포함 | `batch_downloads` |
| 외부 앱 API | 포함 안 됨 | 포함 | `automation_api` |
| 추가 테마 | Graphite / System | 모든 테마 | `premium_appearance` |

일괄 작업은 **새 다운로드…**을 열고 창 아래 고정 작업 줄에서 **URL 목록…**을 선택하세요.

서명된 라이선스에 포함된 권한만 활성화됩니다. 기존 파일과 프로필은 유지됩니다. 추가 파일은 대기열에서 기다리며 실시간 게이트웨이 속도와 상태는 계속 볼 수 있습니다. 저장소 안전 제한은 유지됩니다.

게이트웨이 한도는 다운로드와 업로드가 함께 쓰는 집합에 적용되며 별도 시스템 경로를 추가하지 않습니다. 동시 작업 3개 한도는 다운로드에만 적용되고 업로드에는 적용되지 않으며 나머지는 대기합니다. 더 낮게 설정한 대기열 한도는 유지됩니다. 기존 게이트웨이, 프로필, 진행률과 우선순위는 삭제하지 않습니다. 프로필 할당량은 새로 만들기에만 적용되며 기존 프로필은 계속 사용할 수 있습니다. 이력/CSV는 해당 권한이 필요하고 실시간 계기는 Free입니다. 예약은 제공되지만 기본값 외 우선순위에는 권한이 필요합니다. 저장소와 소스의 기술적 한도는 유지됩니다.

서명된 라이선스는 MAC, IP, 라우터가 아닌 설치 키에 연결됩니다. 만료일은 없고 4–4는 4.x를 포함합니다. 게이트웨이, DHCP, 앱 MAC 변경 시 재활성화가 필요하지 않습니다. 새 컴퓨터, 사용자 또는 데이터 프로필에는 새 요청이 필요할 수 있습니다. 수정 불가능한 코드나 보편적인 하드웨어 바인딩을 약속하지 않습니다.

### 앱 MAC

MultiRoute는 수동 IP와 DHCP에서 자체 고정 MAC을 사용하며 OS 네트워크 어댑터 MAC은 바꾸지 않습니다. 관찰된 장치 및 다른 MultiRoute와의 충돌을 확인하지만 응답이 없다고 꺼진 장치가 없다고 보장할 수는 없습니다. 범위: 46비트 무작위 값을 쓰는 로컬 관리 유니캐스트 MAC입니다. DHCP IP 주소 풀과 다릅니다.

**MAC 변경…** — 활성/대기 전송을 일시 중지하거나 완료하고 로컬 체크섬 검사가 끝난 뒤 버튼을 사용하세요. 관찰된 소스 주소와 다른 MultiRoute 인스턴스의 협력 알림을 확인합니다. ‘충돌이 발견되지 않음’은 꺼져 있거나 응답하지 않는 장치가 같은 주소를 쓰지 않는다는 보장이 아닙니다. 앱 MAC은 물리 어댑터 MAC과 달라야 하며 어댑터나 OS 경로는 변경되지 않습니다.

### 체크섬…

참조값은 재시작이나 진행률 초기화 없이 저장됩니다. 32, 64, 128자리 16진수로 MD5, SHA-256, SHA-512를 자동 인식하며 다운로드 후 조립된 파일을 검사합니다. 참조값을 저장한 뒤 지금 확인을 누르세요. 완료된 로컬 파일을 읽어 검사하며 불일치해도 다시 다운로드하거나 삭제하지 않습니다.

최종 검사는 마지막으로 저장한 기준값을 사용합니다. 편집해도 받은 바이트를 지우거나 전송을 다시 시작하지 않습니다. 로컬 재검사는 완료 파일을 보존하고 일치, 불일치 또는 오류를 별도로 표시합니다. 게시자 기준값은 독립적으로 유지됩니다. 전체 파일 체크섬 하나는 torrent 파일 하나에만 적용됩니다. 무결성은 콘텐츠의 무해함을 보장하지 않으므로 신뢰할 수 있는 SHA-256/SHA-512 기준값을 권장합니다.

### 4.3.9 API 접근

로컬 JSON API는 UTF-8을 사용하며 일반 API 토큰이 없습니다. 외부 제어에는 automation_api가 필요하며 다른 권한도 검사하므로 이 권한만으로 일괄 작업이나 추가 게이트웨이를 사용할 수 없습니다. Free에는 제한된 읽기 진단, 비공개 인증 수명주기와 선택적 브라우저 단일 링크 전달이 남습니다. [API](../API.ru.txt), [OpenAPI](../openapi.yaml)를 참고하고 포트를 LAN/인터넷에 공개하지 마세요.


원본 앱은 [라이선스 1.2](../LICENSE.txt)를 사용합니다. Free는 개인 및 조직/사업 용도로 사용 가능하며 권리자는 유료 Pro를 제공할 수 있습니다. 다른 수령자는 별도 허가 없이 판매할 수 없습니다. 확인된 라이브러리 권한이 전체 상용 배포를 인증하지는 않습니다. OpenJDK GPLv2와 Classpath Exception은 고지/대응 소스를, JNA Apache-2.0은 고지를 요구하며 별도 JLayer LGPL-2.1의 교체/디버깅/소스 권리는 유지됩니다. [조건](../LICENSING.md), [전체 목록](../THIRD-PARTY-NOTICES.txt), 앱 라이선스 페이지를 확인하세요.

System 스타일은 표 텍스트, 입력란과 컨트롤에 시스템 배경에 맞는 대비를 제공합니다. Graphite와 System은 Free에 포함됩니다.

파일 이름과 크기는 별도 열에 표시됩니다. 크기는 파일 이름과 관계없이 숫자로 정렬되며, 알 수 없는 크기는 대시로 표시됩니다. 도구 설명에서 전체 이름과 경로를 확인할 수 있습니다.

파일 이름에 포인터를 올리면 전체 이름, 저장 경로, 전송 프로토콜과 원본 주소 또는 로컬 원본 경로가 표시됩니다. 메타데이터를 HTTPS로 열었어도 토렌트 작업은 BitTorrent로 표시됩니다. 저장소 주소가 있으면 실제 파일 URL 다음에 표시됩니다. 포함된 인증 정보, 쿼리 값과 프래그먼트는 숨겨지며, 인식된 공개 magnet infohash는 표시될 수 있습니다. 저장된 URL과 전송 상태는 바뀌지 않습니다.


### 4.3.9의 게이트웨이 우선순위와 전송 진단

네트워크 설정에서 각 게이트웨이의 우선순위를 **0~1000**으로 지정합니다. 기본 화면의 게이트웨이 표시 옆에도 값이 보입니다. 값이 높으면 작은 파일이나 전체 파일 전송에서 우선 사용하며 큰 파일의 병렬 세그먼트도 더 많이 배정됩니다. 선택된 다른 정상 게이트웨이도 계속 참여합니다. 값이 같으면 선택 순서를 유지하고, 우선 게이트웨이가 실패하거나 멈추면 다른 선택된 게이트웨이가 작업을 이어받을 수 있습니다. 일정한 속도 비율을 보장하지는 않습니다.

독립된 서명 권한 **`gateway_priorities`**가 필요합니다. 작업 우선순위 권한 **`download_priorities`**에는 포함되지 않습니다. 해당 게이트웨이 권한이 없으면 모든 실제 우선순위는 0이며 저장된 값은 유지됩니다. 다운로드 중 변경해도 검증된 부분은 지워지지 않습니다. 선택한 게이트웨이마다 병렬 세그먼트 작업자 1~4개를 사용하며 작업당 총 32개 이하입니다.

설정에서 라이선스 한도 내 동시 다운로드 수와 유한 또는 무제한 자동 재시도 횟수를 정할 수 있습니다. 수동 일시 중지는 유지됩니다. 상황에 맞는 메뉴에서 선택된 지원 작업을 일시 중지/계속하거나 파일 이름을 복사할 수 있습니다. 두 번 클릭하면 폴더만 열리며 속성, 통계 및 개별 다운로드 로그는 메뉴에서 엽니다.

완료된 파일도 개별 로그를 볼 수 있습니다. 설정의 오류 및 해결 방법은 12개 인터페이스 언어로 25개 주제를 검색하는 오프라인 안내서입니다. 저장 위치와 속성에 여유 공간(GB)이 표시됩니다. 로컬 디스크가 가득 차면 명확히 알리고 저장된 부분을 보존하며 네트워크 오류처럼 무한 반복하지 않습니다. 작은 세그먼트를 재개한 뒤 데이터를 기다리는 동안 저장된 접두 부분도 진행률에 계속 반영됩니다.

### 남은 다운로드 데이터 · 4.3.9

다운로드 표에 **남은 다운로드 용량** 열이 추가되었습니다. 예상 남은 시간과 별도로 아직 받을 바이트를 표시하고 숫자로 정렬합니다. 저장된 진행 상황과 수신 중인 진행 상황을 반영하며 0보다 작아지지 않습니다. 전체 크기를 모르면 대시가 표시됩니다.

### 더 안정적인 Mac 시작과 게이트웨이 설정 · 4.3.9

Mac 기본 실행은 처음 슬래시가 빠진 경우를 포함한 이전 상대 기본 경로를 인식합니다. 확인된 기존 프로필 또는 사용자의 빈 기본 폴더를 사용합니다. 모호한 사용자 지정 위치는 추측하지 않고 명시적 선택을 요구합니다.

게이트웨이 준비가 실패하거나 취소되면 다른 게이트웨이와 백그라운드 검사는 사용자가 네트워크 설정을 명시적으로 다시 시도할 때까지 권한 요청을 반복하지 않습니다. 최초 권한 실행에서는 Ethernet BPF 장치를 열기 위한 일반 macOS 관리자 확인이 필요할 수 있습니다.

Mac 네트워크 구성 요소 4.3.2은 macOS가 어댑터 MAC을 숨기는 경우를 처리하면서 물리 어댑터 보호 검사를 유지합니다. 앱 자체 MAC을 사용하며 OS 경로나 물리 MAC을 바꾸지 않습니다. Mac 아이콘과 앱 이름은 Windows의 MultiRoute와 통일됩니다. PKG 업데이트 전에 앱을 종료하세요. 실제 시스템 대화상자의 요청자 이름과 LAN/DHCP 전송은 하드웨어 확인이 더 필요하며 이 전송 방식은 계속 유선 Ethernet을 요구합니다.

**macOS:** `/Applications/MultiRoute Downloader.app` · `/Library/PrivilegedHelperTools/MultiRouteResume/4.3.2/{gateway-net,gateway-launch}`.

### Mac 수동 주소의 게이트웨이 응답 · 4.3.9

POSIX 캡처 설정을 수정하여 수동 앱 주소와 DHCP 모두 앱 자체 MAC으로 오는 응답을 받도록 했습니다. 기존 Windows 동작과 같습니다. 시스템 ping 성공은 컴퓨터의 연결만 확인하며 앱 가상 주소의 게이트웨이 응답 수신을 증명하지 않습니다.

DHCP 진단은 일반 오류로 대체되지 않고 열두 언어의 구체적인 문구를 유지합니다. 기존 권한 동작은 유지됩니다. 일반 네트워크 검사는 준비된 구성 요소를 재사용합니다. API 엔드포인트, 화면 컨트롤, OS 경로와 물리 MAC은 바뀌지 않습니다. 최초 Ethernet BPF 권한 접근에는 일반 관리자 확인이 필요할 수 있습니다.

이 수정은 하나의 캡처 모드 차이를 해결하며 모든 게이트웨이 연결 문제를 해결한다는 뜻은 아닙니다. 주소 사용 여부, 서브넷 및 DHCP 임대·충돌 검사는 유지됩니다. Mac 수동 주소 전송은 실제 하드웨어 확인이 더 필요하고 유선 Ethernet이 계속 필요합니다.

## 모양 및 완료 알림음

**모양 설정**에서 **StreamsStudio**, **Graphite**, **Nordic**, **Neon**, **Community**, **Chat**, **Studio**, **Rose**, **System** 중 하나를 선택합니다. Free에는 Graphite와 System이 포함되며 다른 스타일에는 해당 Pro 외관 권한이 필요합니다. 선택은 로컬에 저장되며 다운로드를 다시 시작하지 않습니다. **둥근 창과 버튼**은 별도 옵션입니다. 모든 스타일에서 컨트롤을 둥글게 표시할 수 있지만 창 바깥 테두리는 운영체제가 결정합니다. Windows 11의 최대화되거나 화면에 맞춰 배치된 창은 직각을 유지할 수 있으며, macOS와 Linux도 시스템이 창 외곽을 관리합니다. 속도 그래프에는 넉넉한 표시 공간이 있고 네트워크 설정은 간결한 게이트웨이 카드를 사용합니다.

완료 알림음은 **기본적으로 꺼져 있습니다**. 전체 활성화 확인란을 켠 다음 **각 파일 완료**와 **모든 다운로드 완료** 알림을 따로 선택하세요. **부드러운 종소리**, **피아노**, **마림바**가 있으며 두 종류의 멜로디를 미리 들을 수 있습니다. 모든 다운로드가 끝나고 전체 완료 알림이 켜져 있으면 마지막 파일에는 최종 멜로디만 재생되어 소리가 겹치지 않습니다. 일시 중지되거나 실패한 작업은 완료된 다운로드가 아닙니다. 시작하거나 설정을 바꿀 때 이전 완료 기록의 소리는 다시 재생되지 않습니다. 시스템 음량과 오디오 출력도 확인하세요.

자신의 소리를 사용하려면 **사용자 지정 멜로디**를 선택하고 파일 완료와 전체 다운로드 완료에 쓸 **MP3 또는 WAV** 파일을 각각 고르세요. 각 소리는 **10초 이하**여야 합니다. 앱은 확장자나 메타데이터만 믿지 않고 디코딩된 오디오의 길이를 확인합니다. 승인된 파일은 로컬 앱 프로필에 복사되므로 원본을 나중에 옮겨도 됩니다.

외관 설정에서 몸에 맞는 여름옷을 입은 사실적인 성인 **MultiRoute 배달원**을 남성 또는 여성으로 선택할 수 있습니다. 배달원은 별도의 데스크톱 위젯에 표시됩니다. 자루의 크기와 표시는 **모든 활성 다운로드의 남은 데이터 총량**을 반영하며 게이트웨이 수와 관계없이 파일마다 한 번만 계산합니다. 바이트를 받을수록 자루가 점차 작아지며 남은 데이터양에 따라 짐의 형태가 달라집니다. **1 GB 미만**은 어깨에 메고, **1 GB 이상 10 GB 미만**은 바닥으로 끌며, **10 GB 이상**은 더 힘들게 끕니다. 걷기와 달리기는 별도로 실제 총 다운로드 속도에 적응하며 유휴 상태에서는 멈춥니다. 새 파일이 완료되면 배달원이 해당 데스크톱 위젯의 오른쪽 끝으로 가서 자루를 내려놓고 부드럽게 사라지며, 활성 다운로드가 남아 있으면 새 짐을 가지고 다시 나타납니다. 배송 중 자루의 표시는 전달하는 짐의 크기를, 돌아온 뒤에는 활성 다운로드의 남은 데이터 총량을 다시 보여줍니다. 이는 애니메이션일 뿐 실제 파일은 선택한 폴더에 그대로 있습니다. 표시 여부는 저장되며 숨김·유휴 상태에서는 애니메이션이 멈추고 시작 시 이전 완료 기록을 재생하지 않습니다. 배송 동작은 소리 설정과 독립적입니다. 이 독자적으로 생성된 캐릭터는 Codex 또는 OpenAI와 관련이 없습니다.

모양, 모서리와 소리는 로컬 데스크톱 설정입니다. 새 다운로드 API 엔드포인트를 추가하거나 전송, 체크섬, DNS 보안 설정을 바꾸지 않습니다.

<a name="423-시작-시-프로필-경로-수정"></a>

## 시작 시 데이터 폴더

기본 설치 앱은 로그인 시 작업 디렉터리와 관계없이 데이터 폴더의 절대 경로를 저장합니다. 저장된 상대 프로필 경로는 대상 기존 프로필을 명확하게 하나로 확인할 수 있을 때만 절대 경로로 변환합니다. 다운로드 기록, 설정 및 저장된 조각은 그대로 유지됩니다. 휴대용 명령줄 버전의 상대 경로와 명시적 `--data-dir`는 각각 지정된 동작을 유지합니다.

<a name="421-자동-시작"></a>

## 자동 시작

언어와 테마 설정 옆에서 **운영체제와 함께 시작**을 켭니다. **기본값은 꺼짐**입니다. 켜면 현재 계정의 다음 로그인에 MultiRoute를 시작하도록 등록하고, 끄면 앱이 소유한 시작 항목을 제거합니다. 사용자 로그인 시 시작하는 기능이며 시스템 서비스나 로그인 전 실행 기능은 아닙니다. 항목 등록에 관리자 권한은 필요하지 않습니다.

자동 시작 시 트레이를 지원하면 트레이를 사용하고, 그렇지 않으면 접근 가능한 일반 창을 표시합니다. 큐의 우선순위, 일시 중지 및 일정은 유지되며 중지된 다운로드를 모두 강제로 재개하지 않습니다. 먼저 앱을 수동으로 열어 설치와 네트워크 구성 요소 준비를 완료하십시오. 등록된 앱 경로를 유지하고, 포터블 사용 시 Java와 라이브러리 경로도 유지하십시오. 이동한 경우 새 위치에서 자동 시작을 껐다가 다시 켭니다. 제거하기 전에 자동 시작을 끄십시오.

운영체제나 데스크톱 정책이 등록 항목을 비활성화할 수 있습니다. macOS에서 승인을 요청하면 **시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램**을 확인하십시오. 네트워크 구성 요소 승인은 별도입니다. 등록되었다는 사실만으로 다음 로그인 실행이 보장되지는 않습니다. 자체 테스트 프로필 검증에는 실제 재부팅이나 로그아웃이 포함되지 않습니다. 해당 릴리스 보고서를 확인하십시오.

앱을 열 수 없으면 **앱의 항목만** 제거하십시오.

- **Windows:** 앱은 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`에 **MultiRoute Downloader**라는 자체 `REG_SZ` 값을 저장합니다. 가능하면 앱에서 자동 시작을 끄십시오. 앱을 열 수 없으면 레지스트리 편집기에서 **그 값만 삭제**하고 Run 키와 다른 항목은 유지합니다. OS가 비활성화했다면 **설정 → 앱 → 시작 프로그램**을 사용하십시오. 앱은 이 결정을 재정의하지 않습니다. Windows는 전체 시작 명령을 260자로 제한합니다. 초과하면 앱/프로필 경로를 짧게 바꾸고 다시 등록하십시오.
- **macOS:** `~/Library/LaunchAgents/io.github.2018-spec-fdsds.multiroute-downloader.plist`를 제거합니다.
- **Linux:** 실제 XDG 구성 디렉터리에서 `${XDG_CONFIG_HOME:-~/.config}/autostart/io.github.2018-spec-fdsds.multiroute-downloader.desktop`을 제거합니다. XDG 자동 시작을 지원하는 그래픽 데스크톱이 필요하며 systemd 서비스는 설치하지 않습니다.

<a name="dns-settings"></a>

<a name="422-dns-설정"></a>

## DNS 설정

**4.3.9 설치 파일 버전과 공개 체크섬을 확인하고, 플랫폼 및 패키지 검증 결과는 해당 NATIVE-INSTALLER-TESTS.json을 참조하십시오.**

**네트워크 → DNS 확인**을 엽니다. 기본값은 **DNS over HTTPS(DoH), Cloudflare**입니다. MultiRoute 전용 설정이며 OS DNS, 경로 또는 인터페이스 IP를 변경하지 않습니다.

DoH는 TLS ALPN으로 선택한 제한된 HTTP/2와 협상된 HTTP/1.1을 지원합니다. 공급자 호환성과 실제 게이트웨이 결과는 해당 최종 릴리스 보고서를 확인하십시오.

- **DoH:** 각 선택 게이트웨이를 통해 암호화된 HTTPS DNS를 사용하며 URL 호스트 이름으로 TLS 인증서를 검증합니다.
- **DoT:** 각 선택 게이트웨이를 통해 TLS DNS를 사용합니다. 기본 포트는 853이며 서버 이름으로 인증서를 검증합니다.
- **시스템 DNS(컴퓨터):** 컴퓨터/OS/VPN의 DNS 정책을 명시적으로 사용합니다. DNS는 선택한 각 게이트웨이를 따르지 않을 수 있지만 파일 연결은 해당 게이트웨이를 사용합니다. 이 모드 자체는 DNS 암호화를 보장하지 않습니다.

Cloudflare, Quad9, Google 또는 **사용자 지정**을 선택합니다. 프리셋 값은 고정되며 사용자 지정에서 URL/서버 이름, 포트, 숫자형 공용 IPv4 부트스트랩 주소를 편집할 수 있습니다. 숫자 주소로 DNS 공급자에 직접 연결하므로 OS를 통한 사전 이름 조회가 필요 없습니다. DoH/DoT는 신뢰 체인, 호스트 이름, SNI를 검증하며 평문 또는 시스템 DNS로 조용히 전환하지 않습니다. 보안 조회 실패는 해당 시도를 종료합니다. 공급자는 선택 게이트웨이로 접근 가능해야 합니다.

초안을 편집하고 게이트웨이를 선택한 다음 **DNS 테스트**를 누릅니다. 저장하지 않고 각 게이트웨이의 결과, 시간, 공용 IPv4 또는 오류를 보여 줍니다. 일부 실패도 표시됩니다. 시스템 모드 성공은 OS 이름 조회를 확인할 뿐 각 게이트웨이의 독립 WAN을 증명하지 않습니다. **DNS 설정 적용**은 검증 후 저장하며 반환된 리비전이 적용 구성을 식별합니다. 상태 갱신과 언어 변경은 미저장 초안, 커서, 스크롤을 유지합니다.

전체 쿼리 제한은 DNSSEC 보조 쿼리를 포함해 8초입니다. 검증된 TTL은 서명 만료도 반영합니다. 네이티브 캐시는 최대 300초이며 게이트웨이·설정 리비전별로 분리됩니다. TTL 0과 DoH HTTP Age는 유지됩니다. 시스템 모드는 OS/JVM 캐시를 따릅니다. 공개 IPv4 파일 대상을 지원하며 IPv6 이름 확인은 지원하지 않습니다.

API: `GET /api/v1/network/dns`는 구성과 읽기 전용 상태를 반환하고 같은 경로의 `PUT`/`POST`는 구성을 적용합니다. `POST /api/v1/network/dns/test`는 초안을 테스트하고 `GET /api/v1/network/dns/providers`는 프리셋을 나열합니다. GET의 리비전/상태가 아닌 구성 필드만 전송하십시오. [API](../API.ru.txt) · [OpenAPI](../openapi.yaml).

<a name="422의-로컬-dnssec-검증"></a>

## 로컬 DNSSEC 검증

**네트워크 → DNS 확인 → DNSSEC 검증**에서 **서명된 도메인 검증**(DoH/DoT 기본값), **안전한 DNSSEC 응답 필수**, **DNSSEC 사용 안 함**을 선택하세요. Java가 dnsjava와 내장 루트 신뢰 앵커로 로컬 검증합니다. 상위 서버의 AD 플래그만으로는 검증이 입증되지 않습니다. DoH/DoT는 전송을 암호화하고 DNSSEC는 DNS 데이터의 진위를 별도로 확인합니다.

**검증**은 안전한 응답과 보호 미확인 응답을 허용하고, **필수**는 안전한 응답만 허용합니다. 보호 미확인은 인증된 서명 없는 위임이나 미지원 알고리즘을 뜻할 수 있으므로 사유를 확인하세요. 검증을 켜면 잘못되거나 판정 불가한 결과는 거부됩니다. 시스템 DNS에서는 로컬 검증이 꺼지며 DoH/DoT로 돌아가면 이전 정책을 복원합니다. 공급자 변경은 정책을 유지합니다. 적용은 저장하고 DNS 테스트는 미저장 초안을 검사합니다.

쿼리별 결과는 `secure`, `insecure`, `bogus`, `indeterminate`, `not_checked`를 구분합니다. 결과가 없으면 사용 불가로 표시합니다. 연결 성공이 DNSSEC 안전 판정은 아닙니다. 만료, 키·증명 누락, 조회 실패, 시간 초과는 각각 사유가 있습니다. 시스템 시각이 정확해야 합니다. 보조 검증 쿼리는 동일한 게이트웨이와 전체 제한 시간을 사용합니다. DNSSEC는 이름을 숨기거나 다운로드 내용을 검사하지 않습니다.

API의 `dnssec` 값은 `off`, `validate`, `require`이며 시스템 모드는 `off`만 허용합니다. `dnssec_validation`, `dnssec_trust_anchors`와 쿼리별 `dnssec_status`, `dnssec_reason_code`, `dnssec_reason`, `dnssec_validated_ttl`, `dnssec_aux_queries`는 읽기 전용이므로 설정 저장 시 보내지 마세요. 위 API/OpenAPI와 [DNSSEC](#422의-로컬-dnssec-검증)를 참조하세요.

**세그먼트 다운로드와 CDN:** Civitai 같은 CDN이 0부터 시작하는 범위에 HTTP 200을 반환하면 0이 아닌 위치의 범위도 검사합니다. 첫 세그먼트는 정해진 크기까지만 읽으며, 원본이 일치하는 기존 순차 다운로드 데이터를 세그먼트로 이어받을 수 있습니다. 이후 범위에 일시적으로 HTTP 200이 반환되면 저장된 데이터와 게이트웨이 작업 스레드를 유지하며 2–30초 후 다시 시도합니다. 게이트웨이별 영구 전송 로그는 수신 트래픽과 저장된 진행량을 구분합니다. [전송 진단](transfer-diagnostics.en.md).

[4.3.9 설치 파일](../downloads/v4.3.9/README.md)에는 전용 Java 21이 포함됩니다. Windows 설치 마법사는 영어로 표시되며 바탕 화면 바로 가기를 만듭니다. Npcap은 별도로 필요하며 macOS는 시스템 libpcap을 사용합니다. 아래의 설치 및 보안 확인 절차를 따르십시오.

<a name="1-용도와-동작"></a>

## 용도와 동작

MultiRoute Downloader는 같은 로컬 Ethernet 네트워크의 여러 인터넷 **게이트웨이**로 파일을 나누어 받는 Java 데스크톱 프로그램입니다. 예를 들어 유선 인터넷과 모바일 4G/5G 회선을 함께 사용할 수 있습니다. 선택한 사용 가능한 게이트웨이가 공유 대기열에서 조각을 가져가므로 빠른 회선이 더 많은 조각을 처리합니다. 회선 하나가 끊겨도 나머지는 계속하고, 미완료 조각은 대기열로 돌아가며 검증된 데이터는 보존됩니다. URL 목록 일괄 가져오기와 다른 프로그램을 위한 로컬 API도 제공합니다.

속도 향상은 독립적인 상위 회선 용량, 서버 제한과 프로토콜의 안전한 이어받기 지원에 달려 있습니다. 게이트웨이 수만큼 항상 빨라지지는 않습니다. 웹 인터페이스가 아닌 독립 데스크톱 앱입니다. 새 프로필의 기본 언어는 영어이며 러시아어, 독일어, 스페인어, 프랑스어, 중국어, 한국어, 아랍어, 이탈리아어, 일본어, 힌디어, 베트남어도 선택할 수 있습니다. 선택한 언어는 저장되고 등록된 상태/로그/도움말에 적용됩니다. 외부 서버나 라이브러리의 원문 오류는 번역되지 않을 수 있습니다. 파일명, 경로, URL, JSON 키는 변경하지 않습니다.

<a name="application-virtual-ip"></a>

### 앱에서 가상 IP를 사용하는 이유

**다른 앱의 연결을 바꾸지 않고 MultiRoute에서 사용할 게이트웨이를 선택할 수 있습니다.** 앱은 내부 네트워크 전송을 위해 사용하지 않는 자체 로컬 IPv4 주소를 사용합니다. 따라서 컴퓨터의 기본 게이트웨이에 종속되지 않고 선택한 게이트웨이로 연결하며, 시스템 어댑터 주소, OS 라우팅 테이블 또는 시스템 기본 게이트웨이를 변경하지 않습니다. 브라우저와 다른 프로그램은 기존 네트워크 설정을 그대로 사용합니다.

예를 들어 `192.168.1.0/24` LAN에서 컴퓨터는 원래 주소 `192.168.1.x`를 유지하고, MultiRoute는 비어 있는 `192.168.1.70`을 사용하며, 다운로드는 `192.168.1.1`–`192.168.1.4`를 거칠 수 있습니다. 컴퓨터, 가상 주소, 선택한 게이트웨이는 실제로 같은 IPv4 서브넷에 있어야 합니다. 앱의 네트워크 설정에서 빈 주소를 검사하고 적용하며, OS 어댑터에 직접 추가하지 마십시오. 가상 IP가 인터넷 회선을 새로 만드는 것은 아닙니다. 대역폭은 라우터와 외부 회선에서 제공됩니다.

#### 주소 선택 및 확인

1. 컴퓨터 Ethernet 어댑터의 IPv4와 서브넷 마스크를 확인하고 같은 서브넷의 유효한 호스트 주소를 선택합니다. `192.168.1.70`은 예시일 뿐이며, 컴퓨터 자신의 IP, 게이트웨이 IP, 네트워크 주소 또는 브로드캐스트 주소를 사용하면 안 됩니다.
2. 라우터 관리 화면에서 실제 DHCP 할당 범위를 확인합니다. 자동 할당 범위 밖의 주소를 사용하거나 DHCP 서버에서 예약/제외합니다. 이 LAN에 DHCP 서버가 여러 개라면 모든 서버가 해당 주소를 다른 장치에 할당하지 않도록 해야 합니다.
3. MultiRoute에서 가상 주소의 **확인 및 적용**을 실행한 뒤 게이트웨이를 검사합니다. 앱은 서브넷을 검증하고 ARP 충돌을 확인합니다. ARP 응답이 없다는 것은 그 순간 충돌을 감지하지 못했다는 뜻일 뿐, DHCP 범위 밖이라는 증거나 나중의 DHCP 할당을 막는 보장은 아닙니다.

## 필요한 환경

Windows/macOS 설치 프로그램에는 전용 Java 21과 컴파일된 네트워크 구성 요소가 들어 있습니다. Windows에는 Npcap 드라이버가 별도로 필요하며 Java를 따로 설치할 필요는 없습니다.

| 플랫폼 | 운영체제 | 구성 요소 |
| --- | --- | --- |
| Windows x64 | Windows 11 | Java 21 |
| Apple Silicon | macOS 26+ | Java 21 |
| Intel Mac | macOS 15+ | Java 21 |

선택한 모든 게이트웨이와 같은 IPv4 서브넷의 유선 Ethernet 어댑터, 사용하지 않는 가상 IPv4 주소, 쓰기 가능한 데이터/다운로드 폴더와 파일 및 임시 조각을 위한 공간이 필요합니다. 속도 향상은 독립적인 WAN 용량과 원본 서버에 달려 있으며 GPU는 필요하지 않습니다.

앱은 Linux를 지원하지만 이 배포 저장소에는 Linux 4.x 설치 프로그램이 게시되어 있지 않습니다. Linux에서 Windows 또는 macOS 패키지를 사용하지 마세요.

업데이트 전에 진행 중인 다운로드, 업로드와 최종 파일 검증이 끝날 때까지 기다리세요. 그런 다음 트레이에서 종료하고 완전한 새 설치 프로그램을 실행하세요. 기존 데이터 폴더, 다운로드 파일과 저장한 조각을 보존하세요.

### Windows

EXE를 열어 현재 사용자용 설치를 마치고 시작 메뉴나 바탕 화면 바로 가기로 실행합니다. 명령 스크립트 창으로 실행되지 않습니다. 자체 설치 화면은 영어이고 Windows 보안 창은 운영체제 언어를 사용합니다.

첫 실행에서 Npcap을 확인합니다. 없으면 앱에서 다운로드에 동의한 뒤 고정된 공식 설치 파일의 SHA-256과 Authenticode 게시자를 검증하고 Npcap의 정상 설치 프로그램을 엽니다. 라이선스를 읽고 표준 UAC 요청을 승인하십시오. 재시작이 필요하면 Windows를 재부팅한 뒤 다시 엽니다. Npcap은 앱에 번들되거나 조용히 설치되지 않으며, 없는 경우 이 단계에 인터넷이 필요합니다. AdminOnly 드라이버는 추가 캡처 권한을 요구할 수 있지만 Java 전체를 관리자 권한으로 실행하지는 마십시오.

앱과 설치 파일에는 게시자 서명이 없습니다. 출처와 해시를 확인한 경우에만 SmartScreen의 “추가 정보 → 실행” 선택 여부를 판단하십시오. 악성코드 탐지는 단순한 알 수 없는 게시자 알림과 다릅니다. 백신을 끄거나 예외를 추가하지 마십시오.

### macOS

CPU에 맞는 PKG를 Apple Installer에서 열고 보호된 네트워크 구성 요소 설치를 위한 관리자 요청을 승인합니다. `/Applications/MultiRoute Downloader.app`을 Finder/Spotlight/Dock에서 엽니다. 이 기본 패키지에는 별도 Java, Terminal, Command Line Tools, Homebrew가 필요 없습니다.

Ethernet BPF 장치를 열어야 할 때 정상적인 macOS 관리자 인증이 나타납니다. 네트워크 구성 요소는 캡처 장치를 연 뒤 권한을 낮추고 Java 창은 일반 사용자로 실행됩니다. PKG와 앱은 **Developer ID 서명 및 공증이 없습니다**. 개발자를 확인할 수 없다는 알림에 예외가 제공된다면 출처와 SHA-256을 검증한 후에만 **시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**, 이어서 “열기”를 선택하십시오. [Apple 공식 안내](https://support.apple.com/en-us/102445)를 참고하고 관리형 Mac의 제한을 따릅니다.

설치 승인, 이후 네트워크 권한, 미확인 개발자 예외는 별개입니다. 요청이 나타나면 실제 LAN 게이트웨이를 위한 **로컬 네트워크**와 선택한 다운로드 폴더 접근을 허용합니다. Gatekeeper/SIP를 끄거나 격리 속성을 전체 제거하지 말고, Java 전체를 root로 실행하지 마십시오. 악성/손상 파일 경고는 일반 개발자 알림이 아니므로 중지하고 파일을 확인합니다.

<a name="4-게이트웨이와-가상-ip"></a>

## 게이트웨이와 가상 IP

기본 게이트웨이 주소는 `192.168.1.1`, `192.168.1.2`, `192.168.1.3`, `192.168.1.4`입니다. 실제 네트워크에 맞게 수정하고 접근 가능한 게이트웨이를 선택하세요. 추가·편집·삭제로 중복 없는 게이트웨이 프로필 **1–8개**를 관리할 수 있습니다. Free는 동시에 **게이트웨이 2개**까지, `extra_gateways` 권한이 포함된 Pro는 **게이트웨이 8개**까지 사용합니다. 기본 주소 네 개가 모두 활성화된다는 뜻은 아닙니다. 컴퓨터가 하나를 기본 게이트웨이로 사용해도 다섯 번째 회선이 추가되는 것은 아닙니다.

앱의 가상 IPv4는 처음에 `192.168.1.70`입니다. 네트워크 설정에서 확인/적용하고 다른 장치가 사용하지 않는지 검사합니다. DHCP 자동 할당 범위 밖에 예약하십시오. 이 주소는 앱 내부 전송 전용이며 **시스템 어댑터에 추가하거나 OS 라우팅 테이블을 변경하지 않습니다**. 다른 앱은 평소 연결을 사용합니다. OS 네트워크 설정에 직접 이 IP를 넣지 마십시오. 옆의 물음표와 도움말을 참고합니다.

게이트웨이를 검사한 다음 사용 가능한 하나/여러 개/전체를 선택합니다. 실제 동시 사용 개수에는 위의 라이선스 한도가 적용됩니다. 속도 테스트는 **16 MiB 또는 5초**까지이며 연결 준비는 더 걸릴 수 있습니다. 정상 다운로드에는 이 제한이 적용되지 않습니다. 적당한 직접 HTTP URL이 없으면 Selectel 테스트 파일을 씁니다.

진행 중에도 프로필과 해당 작업의 게이트웨이를 추가/제거할 수 있지만 미완료 작업마다 최소 하나가 남아야 합니다. 새 프로필은 기존 작업에 자동 선택되지 않습니다. 가상 IP 자체를 바꾸기 전에는 활동 작업을 일시 중지합니다. 앱 MAC의 용도, 검사와 변경 조건은 위의 앱 MAC 설명을 참조하세요.

## 다운로드 관리와 화면 조작

1. 긴 URL 칸에 Ctrl+V 또는 macOS의 Cmd+V로 붙여 넣거나 붙여넣기 버튼을 사용합니다. magnet을 넣거나 `.torrent`를 열 수도 있습니다.
2. OS 폴더 선택기로 저장 위치를 지정합니다. 기본값은 Windows `%USERPROFILE%\Downloads`, macOS/Linux `~/Downloads`이고 수동으로 고른 폴더는 유지합니다.
3. 게이트웨이를 선택하고 URL 옆의 다운로드 시작을 누릅니다. Hugging Face 저장소, WebDAV 목록, Metalink는 파일을 미리 보고 선택합니다. 일괄 가져오기는 한 줄당 URL 하나 또는 텍스트 파일을 받습니다.
4. 작업별 진행률/경과/남은 시간, 전체 속도, 각 게이트웨이 속도/전송량과 그래프를 확인합니다. HTTP 조각은 기본 **20 MiB**, 설정 범위 1–64 MiB입니다. **60초** 동안 데이터가 없는 조각은 취소 후 공유 풀로 돌아가 다른 게이트웨이가 처리합니다. torrent 조각 크기는 메타데이터에 따릅니다.
5. 일시 중지/계속, 우선순위/속도 제한/예약, 정지한 작업의 폴더 변경을 지원합니다. 기본 동시 작업은 2개이며 재시작 시 진행 중이던 작업은 일시 중지로 복원됩니다. torrent 배포는 기본 꺼짐이며 시간/비율 상한을 정할 수 있습니다.

FlatLaf의 밝게/어둡게/시스템 테마를 선택하면 저장됩니다. 요약은 필터와 무관하게 전체/활성/완료 작업과 전체 속도를 보여 줍니다. 개별 진행률 막대, 넓이에 맞는 열, 정렬/검색/상태 필터와 스크롤을 유지합니다.

진행 중 또는 완료된 행에 마우스를 올리면 **전체 파일 이름과 절대 저장 경로**가 나타납니다. 정렬/필터 후에도 실제 행과 일치하며 선택 파일 제목도 같은 도움말을 제공합니다. 우클릭 메뉴로 전체 경로를 복사합니다. Ctrl+L/Cmd+L은 URL, Ctrl+F/Cmd+F는 검색에 포커스를 주고 Escape는 검색을 지웁니다.

선택한 작업에는 세부 정보와 기록 탭이 있습니다. 새로고침/언어 변경 시 보고서 읽기 위치와 선택 텍스트가 유지되며, 다른 작업을 고르면 그 보고서 처음으로 이동합니다. 전체 로그는 앱 이벤트/다운로드 기록으로 구분됩니다. 끝에 있을 때 새 기록을 따라가고 위를 읽을 때 강제로 이동하지 않습니다.

창을 닫아도 트레이에서 다운로드가 계속됩니다. 아이콘은 모든 작업의 합산 속도를 최대 10 Gbit/s까지 표시하고 툴팁에 정확한 값을 보여 줍니다. 트레이의 앱 열기로 복원하고 앱 종료로 저장/종료합니다. 트레이를 지원하지 않으면 작업 표시줄로 최소화합니다. 업데이트 전에는 반드시 트레이에서 종료하십시오.

Windows/Linux에서는 **Ctrl**을 누른 채 클릭하고 macOS에서는 **Cmd**를 누른 채 클릭하여 여러 다운로드 행을 선택합니다. **Shift**를 누른 채 클릭하면 범위를 선택합니다. 표에 포커스가 있을 때 **Ctrl+A** 또는 **Cmd+A**는 검색과 상태 필터를 적용한 현재 표시 행만 모두 선택합니다. 선택한 작업의 삭제는 전체 그룹에 대한 확인 창 하나로 처리합니다. 완료 파일과 다운로드한 부분까지 삭제하는 옵션은 **기본 해제**되어 목록 항목만 제거하고 데이터를 보관할 수 있습니다. 해당 작업의 파일을 지우려는 경우에만 선택하며, 다른 파일과 저장 폴더는 보존됩니다. 결과에는 삭제된 항목 수가 표시됩니다. 삭제하지 못한 작업은 오류 요약과 함께 목록에 남으므로 확인한 뒤 다시 시도할 수 있고, 이미 성공한 삭제는 반복되지 않습니다. 작업이나 파일을 삭제해도 영구 다운로드 기록은 지워지지 않습니다.

<a name="6-지원-프로토콜과-무결성"></a>

## 지원 프로토콜과 무결성

| 소스 | 동작과 조건 |
| --- | --- |
| HTTP/HTTPS | 안전한 파일 식별과 바이트 범위가 있을 때 분할/이어받기; 없으면 한 게이트웨이의 전체 스트림이며 중단 후 처음부터 다시 받음 |
| Hugging Face | 파일/저장소 선택과 Hub/Xet 해석; 비공개/제한 리소스에는 적절한 소스 접근 권한 필요 |
| FTP | 수동 EPSV/PASV; 평문 FTP는 자격 증명/데이터를 암호화하지 않음 |
| FTPS | 명시적 TLS 제어/데이터 연결; 암시적 FTPS 미지원 |
| SFTP | 독립적으로 확인해 고정한 SHA256 SSH 서버 호스트키 지문 필수; 알 수 없는 키를 자동 수락하지 않음 |
| WebDAV | HTTPS 목록과 파일 선택 |
| Metalink | `.meta4`, 신뢰할 SHA-256, 미러와 제공된 조각 해시 |
| Torrent/magnet | 선택한 게이트웨이 전송, 메타데이터 기준 조각 검증 필수, 파일 선택/우선순위 |

소스 접근 설정에서 정확한 origin별 사용자/비밀번호, Bearer token, Cookie 또는 허용된 헤더를 저장할 수 있으며 로컬 암호화됩니다. 라우터용 토큰은 필요 없습니다. URL에 비밀번호를 넣지 마십시오. 신뢰할 게시/수동 SHA-256 또는 SHA-512가 없는 FTP/FTPS/SFTP는 전체 파일 모드를 사용합니다.

조립 후 한 번 읽어 **MD5, SHA-256, SHA-512**를 모두 계산합니다. 주 입력란은 32/64/128자리 16진수 길이로 유형을 자동 감지하며 추가 참조도 입력할 수 있습니다. 전체 표현 다이제스트 헤더와 `filename.md5`, `MD5SUMS`, `filename.sha256`, `SHA256SUMS`, `filename.sha512`, `SHA512SUMS`를 탐색하고 Hugging Face LFS/Metalink 검증을 유지합니다. 일부 HTTP 응답의 다이제스트를 전체 파일 값으로 취급하지 않습니다.

알려진 참조는 최종 파일 게시 전에 모두 일치해야 합니다. 불일치 시 실패하며 부분 데이터는 남깁니다. 참조가 없으면 로컬 계산값일 뿐 게시자와 일치했다고 확인한 것이 아닙니다. MD5는 우발적 손상 탐지용이며 강한 파일 식별이나 SHA-256/SHA-512를 대체하지 않습니다. torrent 조각 검증과 전체 파일 해시는 별개이며 수동 전체 해시는 파일 하나만 선택해야 합니다.

<a name="7-다른-프로그램에서-api-사용"></a>

## 다른 프로그램에서 API 사용

앱 실행 중 `http://127.0.0.1:8765/api/v1`에 로컬 API가 있습니다. 요청/응답은 JSON UTF-8, 본문 헤더는 `Content-Type: application/json`입니다. 작업 생성/제어용 API token은 필요 없고 소스 자격 증명은 별개입니다. 같은 컴퓨터에서만 사용하며 LAN/인터넷에 포트를 공개하지 마십시오. `--headless`는 API 전용 실행입니다. 기본 설치는 정상 실행기를 사용하고 `.cmd` 예는 portable용입니다.

아래의 외부 관리 예제에는 `automation_api` 권한이 필요합니다. 게이트웨이 네 개를 쓰는 예제 구성에는 `extra_gateways` 권한도 필요합니다. 실제 네트워크와 라이선스에 맞게 `gateways`와 `routes`를 조정하세요. Free는 동시에 게이트웨이 2개까지, 해당 Pro 권한이 있으면 8개까지 사용할 수 있습니다.

상태 확인: `GET /api/v1/health`, 정상 예 `{"ok":true,"version":"4.3.9"}`. 먼저 창에서 네트워크를 설정하거나 다음을 `POST /api/v1/network`에 보냅니다.

```json
{
  "virtual_ip": "192.168.1.70",
  "gateways": ["192.168.1.1", "192.168.1.2", "192.168.1.3", "192.168.1.4"]
}
```

다음 JSON을 `POST /api/v1/jobs`로 전송합니다. URL과 실제 로컬 폴더를 바꾸십시오. Linux `/home/your-user/Downloads`, macOS `/Users/your-user/Downloads`도 가능합니다. API의 `routes`는 명시해야 하며 화면 체크박스를 자동 복사하지 않습니다.

```json
{
  "url": "https://example.org/large-file.bin",
  "directory": "C:/Users/your-user/Downloads",
  "chunk_mb": 20,
  "routes": [
    {"type": "gateway", "gateway": "192.168.1.1", "enabled": true},
    {"type": "gateway", "gateway": "192.168.1.2", "enabled": true},
    {"type": "gateway", "gateway": "192.168.1.3", "enabled": true},
    {"type": "gateway", "gateway": "192.168.1.4", "enabled": true}
  ]
}
```

`HTTP 201`은 작업 생성이지 완료가 아닙니다. 응답 `id`를 저장하고 `GET /api/v1/jobs/{id}`를 조회해 `status: complete`를 확인하거나 실패의 `error`를 읽습니다. `speed_bps`는 **바이트/초**이며 8을 곱하고 1,000,000으로 나누면 Mbit/s입니다.

| HTTP | API |
| --- | --- |
| GET | `/api/v1/health` |
| GET / POST | `/api/v1/jobs` |
| GET | `/api/v1/jobs/{id}` |
| POST | `/api/v1/jobs/{id}/pause` |
| POST | `/api/v1/jobs/{id}/resume` |
| POST | `/api/v1/jobs/{id}/routes` |
| DELETE | `/api/v1/jobs/{id}` |
| GET / POST | `/api/v1/network` |
| POST | `/api/v1/jobs/batch` |
| GET / POST | `/api/v1/queue` |
| GET | `/api/v1/events` |

일시 중지/계속은 빈 JSON `{}`로 호출합니다. 삭제 본문과 기본 파일 보존, `Idempotency-Key`, 대기열/일괄/SSE/소스 접근/제한의 정확한 필드는 [OpenAPI](../openapi.yaml)를 따릅니다. 생성 시 `expected_md5`, `expected_sha256`, `expected_sha512`를 제공할 수 있습니다. 응답에는 `md5`, `sha256`, `sha512`, `checksum_sources`와 경고가 나옵니다. JSON 키와 상태는 UI 언어가 바뀌어도 동일합니다. [추가 API 예제](../API.ru.txt)는 러시아어입니다.

Python 3 예제입니다. 실제 URL로 바꾸고 창에서 네트워크를 설정한 뒤 앱을 실행해 둡니다. UTF-8은 한국어 경로도 보존합니다.

```python
import json
import urllib.request
from pathlib import Path

data = {
    "url": "https://example.org/large-file.bin",
    "directory": str(Path.home() / "Downloads"),
    "chunk_mb": 20,
    "routes": [
        {"type": "gateway", "gateway": f"192.168.1.{n}", "enabled": True}
        for n in range(1, 5)
    ],
}
request = urllib.request.Request(
    "http://127.0.0.1:8765/api/v1/jobs",
    data=json.dumps(data, ensure_ascii=False).encode("utf-8"),
    headers={"Content-Type": "application/json; charset=utf-8"},
    method="POST",
)
with urllib.request.urlopen(request, timeout=30) as response:
    job = json.loads(response.read().decode("utf-8"))
print(job["id"])
```

<a name="8-기록-데이터와-업데이트"></a>

## 기록, 데이터와 업데이트

| 시스템 | 데이터 | 앱/런타임 |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%\MultiRoute Downloader\data` | `%LOCALAPPDATA%\MultiRoute Downloader App` |
| macOS | `~/Library/Application Support/MultiRoute Downloader/data` | `/Applications/MultiRoute Downloader.app` |
| Linux | `~/.local/share/MultiRouteResume/data` | `~/.local/share/MultiRouteResume/` |

`logs/downloads-history.jsonl`은 UTF-8 줄 단위 JSON, `logs/downloads-history.log`는 날짜/시간이 있는 읽기용 로그입니다. 재시작 후에도 추가되고 작업 삭제/언어 변경으로 과거 기록을 다시 쓰지 않습니다. 텍스트는 기록 당시 언어를 유지하지만 화면은 현재 언어로 렌더링합니다. 창은 최대 최근 1,000개 이벤트/2 MiB만 읽고 전체 파일은 디스크에 남아 증가하므로 필요 시 따로 보관합니다. 이름과 절대 경로가 들어가며 소스 URL, 비밀번호, token은 기록하지 않습니다. 공유 전 개인 경로를 확인하십시오.

API `lifecycle_history`에는 `event_id`, `job_id`, `kind`, `time`, `filename`, `path`가 있고 torrent는 `paths`, 일시 중지는 `reason`(`pause`, `shutdown`, `maintenance`)가 있을 수 있습니다. 유형은 `started`, `resumed`, `paused`, `completed`, `recovered`, `failed`입니다. 시간은 ISO 8601 UTC(예: `2026-10-18T12:34:56.123Z`)이고 읽기용 로그에는 현지 전체 날짜/시간과 UTC 오프셋이 있습니다. 선택 필드 `first_started_at`, `last_resumed_at`, `completed_at`는 실제 관측한 시작/최근 계속/검증 게시 후 완료만 나타냅니다. 대기 중은 시작이 아니고 오래된 날짜를 추측하지 않습니다. `recovered`는 과거 게시 파일의 현재 검증이며 원래 완료일을 안다는 뜻은 아닙니다.

업데이트 전 트레이에서 종료하고 완전한 새 패키지를 설치하며 기록/부분 파일을 보존합니다. Windows는 설정 → 앱 → 설치된 앱에서 제거합니다. macOS의 `.app`만 지워도 데이터/보호 구성 요소는 남습니다. 제거하려고 다운로드 폴더를 삭제하지 마십시오. Linux 앱 폴더를 옮기면 배포를 다시 실행합니다.

<a name="10-라이선스"></a>

## 라이선스

원본 앱은 개인/조직 및 업무에서 무료로 사용할 수 있습니다. 별도 허가 없이 앱 판매, 라이선스 요금 청구나 유료 배포는 금지합니다. 사용자 정의 라이선스는 일반적인 수정/재배포 권한을 주지 않으며 OSI 승인 오픈소스 라이선스가 아닙니다. 영어 [LICENSE.txt](../LICENSE.txt)가 우선합니다. FlatLaf(Apache-2.0) 등 타사 구성 요소는 각자 라이선스를 유지합니다. 소유자: [2018-spec-fdsds](https://github.com/2018-spec-fdsds).

<a name="이름과-기존-프로필-호환"></a>

## 데이터 폴더와 기존 프로필

데이터는 위 표의 사용자 폴더에 저장됩니다. 표준 데이터 폴더가 없고 사용 가능한 기존 프로필이 감지되면 파일 이동이나 삭제 없이 그 프로필을 재사용합니다. 기존 프로필은 `%LOCALAPPDATA%\MultiRoute Resume\data` 또는 `~/Library/Application Support/MultiRoute Resume/data`에 있을 수 있으므로 실제로 사용하는 데이터 폴더를 보존하세요. 보호 디렉터리 `MultiRouteResume`, Windows 업그레이드 ID, 내부 API 식별자와 포트는 호환성을 유지합니다. 설치된 MultiRoute Downloader 바로 가기나 앱으로 실행하세요.

<a name="저장한-사이트-업로드와-압축-파일-미리-보기-40"></a>

## 저장한 사이트, 업로드와 압축 파일 미리 보기

**사이트 프로필…**에서 프로필을 만들거나 수정한 뒤 **다운로드** 또는 **업로드**에서 선택합니다. 게이트웨이와 가상 IP는 **네트워크 설정**에 있습니다. **업로드**에서 **원격 폴더 URL**을 입력하고 **파일을 선택하여 업로드…**로 시스템 선택기에서 한 개 이상의 로컬 파일을 선택합니다. 화면은 파일명을 붙이지만 API `target_url`은 전체 원격 파일 URL을 사용합니다. 압축 파일 URL을 기본 입력란에 붙이고 **압축 파일 내용…**를 누르면 다운로드 없이 미리 봅니다.

사이트 프로필에 이름, 기본 URL, 로컬 다운로드 폴더, 원격 폴더와 게이트웨이를 저장합니다. 익명 접근, HTTP Basic/Bearer/Cookie/사용자 헤더, FTP 및 사전에 확인한 서버 SHA-256 키를 사용하는 SFTP를 지원합니다. 같은 서버의 여러 계정도 별도로 보관합니다. 명시한 폴더/게이트웨이가 기본값보다 우선하며 상대 URL은 기본 URL을 기준으로 합니다. 비밀 정보는 소유자 전용 `site-profiles/vault.bin`에 암호화되고 키는 `site-profiles/key.bin`에 있습니다. 계정과 키를 장악한 사람으로부터는 보호하지 못합니다. 공개 API는 비밀을 반환하지 않습니다. 출처와 인증 방식이 같을 때만 빈 입력은 이전 비밀을 유지하며 `replace_credentials:true`로 교체합니다. 다른 출처로 HTTP 리디렉션하면 자격 증명을 보내지 않습니다. 프로필 삭제는 작업이나 로컬/원격 파일을 삭제하지 않으며 연결된 작업은 원래 프로필 연결을 유지하며 계정을 바꿀 수 없으므로 삭제했다면 필요에 따라 유효한 프로필로 작업을 다시 만드십시오.

업로드와 원격 폴더 탐색은 선택한 게이트웨이를 통한 **FTP, 명시적 FTPS, SFTP**를 지원합니다. 일반 로컬 파일과 폴더가 아닌 전체 원격 파일 URL(`target_url`)을 선택합니다. 원격 임시 파일의 기존 접두부를 비교한 뒤 이어 올릴 수 있습니다. 완료하려면 원격 파일 전체를 다시 읽어 SHA-256을 비교하므로 **읽기·쓰기·이름 변경** 권한이 필요하며 추가 트래픽이 발생합니다. 불일치나 읽기 거부는 실패입니다. 한 파일은 한 번에 한 게이트웨이를 사용하고 여러 파일은 게이트웨이에 나뉘어 병렬 전송됩니다. 유휴 제한 후 다른 게이트웨이로 바꿀 수 있지만 한 업로드를 동시에 분할하지는 않습니다. 일시 중지/재개와 진행률은 재시작 후에도 유지됩니다. 작업 삭제는 로컬 파일과 원격 완성/임시 파일을 남깁니다.

덮어쓰기는 기본으로 꺼져 있습니다. FTP/SFTP는 대상이 없을 때만 원자적으로 이름을 바꾸는 기능을 항상 제공하지 않으므로 외부 클라이언트와 최종 대상이 충돌할 수 있습니다. 공유 대상을 조정하십시오. 폴더 탐색은 파일을 올리거나 삭제하지 않습니다.

**ZIP, TAR, 7Z, RAR4, RAR5** 미리 보기는 이름, 경로, 크기, 폴더/암호화 표시만 읽고 압축 해제나 실행은 하지 않습니다. 선택한 게이트웨이, 바이트 범위 및 안정적인 ETag 또는 Last-Modified가 필요합니다. 메타데이터 16 MiB, 10,000개, 60초 제한이며 7z 헤더 해독 메모리는 64 MiB입니다. 목록은 잘릴 수 있고 내용의 무결성을 확인하지 않습니다. 이름 오류에는 원래 문자셋을 지정하십시오. 지원하는 암호화 7z 헤더에는 저장하지 않는 암호를 사용할 수 있습니다. 암호화 RAR 헤더는 미지원/암호 필요로 표시되며 분할 볼륨은 일부만 보일 수 있습니다.

다운로드·업로드·목록·미리 보기 API는 `site_profile_id`를 받습니다. `GET /api/v1/site-profiles`는 `{profiles:[...]}`, `POST`/`PUT`는 평면 프로필 저장과 공개 메타데이터 반환, `DELETE /api/v1/site-profiles/{id}`는 프로필만 삭제합니다. `POST /api/v1/uploads`는 `local_path`, `target_url`, `routes`, 선택적 `site_profile_id`, `overwrite:false`를 받아 HTTP 201을 반환합니다. GET은 `{uploads:[...]}`를 반환하며 개별 GET/DELETE, POST `/{id}/pause` / `/{id}/resume`도 지원합니다. `POST /api/v1/remote/list`는 `url`과 `route`/`routes`, `POST /api/v1/archives/preview`는 추가로 선택적 `password`, `charset`을 받습니다. [openapi.yaml](../openapi.yaml)을 참조하십시오. `data/uploads/`의 UTF-8 매니페스트에는 암호 대신 프로필 ID가 있습니다. 미리 보기는 다운로드 작업을 만들지 않습니다.

## 다운로드 일정과 우선순위

큐/일정에서 `max_active_jobs`(1–32), 전체/게이트웨이 속도 제한, 일일 시간대(`schedule_enabled`, `schedule_start`, `schedule_end`, HH:mm)를 설정합니다. 컴퓨터 현지 시간대이며 `schedule_timezone`으로 확인할 수 있습니다. 자정을 넘길 수 있고 시작/끝이 같으면 하루 종일입니다. 시간대 밖에서는 큐로 돌아가며 수동 일시 중지는 유지됩니다. `priority` -100~100에서 높은 대기 작업부터, 같으면 생성 순서로 시작하며 실행 중인 작업을 중단하지 않습니다. `start_after_ms`는 Unix 밀리초 기준 가장 이른 시작 시각이고 0은 지연 해제입니다. 재시작 후 유지되며 다운로드에만 적용되고 업로드 큐는 별개입니다. 앱과 컴퓨터가 깨어 있어야 하며 OS 깨우기는 지원하지 않습니다. API: `GET`/`PUT`/`POST /api/v1/queue`, `PUT`/`POST /api/v1/jobs/{id}/options`.

## Chrome 및 Edge 통합

앱에서 **Chrome / Edge** 통합을 열어 링크 전송을 켜고 기본 설치 프로그램에 포함된 확장 폴더를 여세요. `chrome://extensions` 또는 `edge://extensions`에서 개발자 모드를 켜고 “압축해제된 확장 프로그램을 로드합니다”로 해당 폴더를 선택하세요. 선택한 폴더를 옮기지 마세요.

MultiRoute가 실행 중이어야 하며 트레이여도 됩니다. 링크 메뉴 또는 확장 팝업에서 URL을 보냅니다. 현재 폴더, 게이트웨이, 사이트 프로필을 사용하며 필요한 저장소/torrent 선택은 계속 나타납니다. 기본 포트 8765를 API 포트와 맞추십시오. URL만 보내며 브라우저 쿠키/암호를 복사하거나 다른 다운로드를 가로채지 않습니다. 원본 인증은 앱에서 설정합니다. 로컬 연결 권한 요청은 이 확장에만 허용하십시오.

기본으로 꺼진 브리지는 `chrome-extension://ljdklefabmaecjalfhjoicmgedmjjkbl`의 `/api/v1/browser/status`, `/api/v1/browser/download`만 허용하며 다른 API 규칙을 바꾸지 않습니다. HTTP 202는 화면 전달이지 다운로드 완료가 아닙니다. headless 서버만으로는 화면 선택이 열리지 않습니다. 브라우저에서 확장을 삭제하거나 앱 통합을 끄면 중단됩니다.
