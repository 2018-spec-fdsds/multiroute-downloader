# MultiRoute Downloader 4.2.0

[Русский](4.2.0.ru.md) · [Home](../../README.md) · [DNS instructions](../en.md#dns-settings) · [Installers and checksums](../../downloads/v4.2.0/README.md)

Version 4.2.0 adds application DNS settings with strict encrypted modes and an explicit System mode. Match the installer version and checksums; see the matching `NATIVE-INSTALLER-TESTS.json` for platform and asset verification results.

## DNS settings belong to the application

Open **Network → DNS resolution**. The default is strict **Cloudflare DNS over HTTPS (DoH)**. Select **DNS over TLS (DoT)** or explicitly select **System DNS (computer)** to use the computer/OS/VPN resolver policy. No operating-system DNS servers, routes or interface addresses are changed.

In DoH/DoT mode, each lookup uses its selected gateway and the application's virtual IPv4 address. Numeric public bootstrap addresses reach the provider without an initial system DNS lookup. TLS checks the trusted certificate chain and logical hostname, with SNI sent for that hostname. Certificate, connection or DNS errors fail the attempt; secure modes do not silently switch to port 53, a router resolver or System mode.

System mode uses OS/VPN policy and its cache behavior. It cannot promise that DNS follows each selected gateway or that DNS is encrypted. File connections still use their selected gateways. A successful System DNS test does not prove independent WAN access through each router.

| Preset | DoH URL | DoT hostname / port | Bootstrap IPv4 |
| --- | --- | --- | --- |
| Cloudflare | `https://cloudflare-dns.com/dns-query` | `one.one.one.one:853` | `1.1.1.1`, `1.0.0.1` |
| Quad9 | `https://dns.quad9.net/dns-query` | `dns.quad9.net:853` | `9.9.9.9`, `149.112.112.112` |
| Google | `https://dns.google/dns-query` | `dns.google:853` | `8.8.8.8`, `8.8.4.4` |

Presets are fixed. **Custom** enables the applicable HTTPS URL or DoT name/port and up to eight numeric public bootstrap IPv4 addresses. A DoH URL must use HTTPS with a hostname, without credentials, query or fragment. DoT needs an authentication hostname; port 53 is rejected.

DoH supports bounded HTTP/2 when selected by TLS ALPN and HTTP/1.1 when that protocol is negotiated. This includes the HTTP/2 transport required by Quad9, which disabled HTTP/1.1 DoH. Availability through a particular gateway remains a separate live check; consult the matching final report. [Official Quad9 protocol requirement](https://docs.quad9.net/FAQs/#dns-over-https-no-http11-support).

## Draft, test and apply

Editing creates an unsaved draft. **Test DNS** tests that draft through the selected configured gateways without saving it. The panel shows each gateway's result, elapsed time and public IPv4 addresses or an error; partial failures remain visible. **Apply DNS settings** validates and persists the configuration in the active data directory's UTF-8 `dns-settings.json`.

The applied revision identifies the policy used by new lookups. Repeating an equivalent configuration may keep its revision; use the value returned by the API. Native positive caches are separated by gateway, hostname and revision, with a maximum of 300 seconds. TTL zero is not cached; DoH HTTP Age reduces the received TTL. Java adds no separate DNS cache. Existing file TCP streams are retained when only DNS settings change.

Each query has an 8-second total limit, including connection and TLS work. Public IPv4 A answers are supported. Local DNSSEC validation, IPv6 resolution and separate CNAME continuation queries are not implemented.

Background status updates and language changes keep the unsaved text, selection/caret and reading position. The editor, help, tooltips and diagnostic templates support the twelve interface languages.

## Local API

| Method / path | Purpose |
| --- | --- |
| `GET /api/v1/network/dns` | Standalone DNS configuration plus readonly revision/runtime state |
| `PUT` or `POST /api/v1/network/dns` | Validate, apply and persist configuration; return the applied DNS state |
| `POST /api/v1/network/dns/test` | Test `{settings, gateways, hostname}` without saving; inspect every result row and overall `ok` |
| `GET /api/v1/network/dns/providers` | Modes and three fixed providers with their DoH/DoT configurations |

Writable keys are only `mode`, `provider`, `doh_url`, `dot_host`, `dot_port` and `bootstrap_ips`. Do not send a full GET response back: revision and runtime status are readonly. DNS state is also included under `dns` in `GET /api/v1/network`. See [API examples](../../API.ru.txt) and [OpenAPI](../../openapi.yaml).

## Verification and release boundaries

Owned Windows fixtures passed **42 resolver protocol checks**, **106 HTTP/2 checks in 43 cases** and **891 Swing checks**. HTTP/2 tests use owned TLS/ALPN `h2` fixtures with four injected provider identities; Swing tests include the actual desktop’s 900 ms timer, twelve languages, Unicode, asynchronous draft operations and partial gateway failure. Managed DNS integration is covered by separate fixtures. See the matching `NATIVE-INSTALLER-TESTS.json` for final source commit, artifact hashes and platform/asset results; these fixture counts alone do not establish installer or physical-gateway success.

A separate live check confirmed Quad9 DoH over HTTP/2 through gateways `192.168.1.1`, `192.168.1.2` and `192.168.1.3`. This establishes those DNS queries, not completion of a file transfer. Gateway `192.168.1.4` has no working WAN connection, as confirmed by the operator. A preset, ARP reply or one successful transfer does not establish working Internet access through all configured gateways. Final live provider/platform results must be read from the matching release report.

The 4.1.3 Civitai/CDN resumable-download fixes and durable per-gateway transfer journal are retained; see their [separate notes](4.1.3.en.md) and [diagnostic guide](../transfer-diagnostics.en.md).
