# MultiRoute Downloader 4.2.0

В 4.2.0 добавлены настройки DNS приложения со строгими зашифрованными режимами и явным системным режимом. Сверьте версию установщика и контрольные суммы; результаты проверки платформ и пакетов приведены в соответствующем `NATIVE-INSTALLER-TESTS.json`.

## DNS настраивается внутри приложения

Откройте **Сеть → Разрешение DNS**. По умолчанию используется строгий **Cloudflare DNS через HTTPS (DoH)**. Можно выбрать **DNS через TLS (DoT)** либо явно включить **Системный DNS (компьютер)**, следующий политике ОС/VPN. DNS-серверы ОС, системные маршруты и IP-адреса интерфейсов не меняются.

В DoH/DoT каждый запрос идёт через выбранный шлюз и виртуальный IPv4 приложения. Числовые публичные bootstrap-адреса позволяют подключиться к провайдеру без предварительного системного DNS-запроса. TLS проверяет доверенную цепочку сертификата и логическое имя хоста; для этого имени отправляется SNI. Ошибка сертификата, подключения или DNS завершает попытку: скрытого перехода к порту 53, DNS роутера или системному режиму нет.

Системный режим использует правила ОС/VPN и её кэш. Он не гарантирует шифрование DNS или путь через каждый выбранный шлюз. Файловые соединения продолжают использовать свои шлюзы. Успешная системная проверка DNS не доказывает независимый выход в Интернет каждого роутера.

| Пресет | URL DoH | Имя и порт DoT | Bootstrap IPv4 |
| --- | --- | --- | --- |
| Cloudflare | `https://cloudflare-dns.com/dns-query` | `one.one.one.one:853` | `1.1.1.1`, `1.0.0.1` |
| Quad9 | `https://dns.quad9.net/dns-query` | `dns.quad9.net:853` | `9.9.9.9`, `149.112.112.112` |
| Google | `https://dns.google/dns-query` | `dns.google:853` | `8.8.8.8`, `8.8.4.4` |

Пресеты фиксированы. **Свой** позволяет изменить соответствующий HTTPS URL или имя/порт DoT и до восьми числовых публичных IPv4 начального подключения. URL DoH должен содержать HTTPS и имя хоста без учётных данных, query и fragment. Для DoT требуется имя сервера аутентификации; порт 53 запрещён.

DoH поддерживает ограниченный HTTP/2 при выборе через TLS ALPN и HTTP/1.1 при согласовании этого протокола. Это включает транспорт HTTP/2, необходимый Quad9 после отключения DoH по HTTP/1.1. Доступность через конкретный шлюз проверяется отдельно; смотрите соответствующий итоговый отчёт. [Официальное требование Quad9](https://docs.quad9.net/FAQs/#dns-over-https-no-http11-support).

## Черновик, проверка и применение

Редактирование создаёт несохранённый черновик. **Проверить DNS** использует его через выбранные настроенные шлюзы без сохранения. Для каждого показываются результат, время, публичные IPv4 или ошибка; частичный отказ остаётся виден. **Применить настройки DNS** проверяет и сохраняет конфигурацию в UTF-8 `dns-settings.json` активной папки данных.

Применённая ревизия определяет политику новых запросов. Эквивалентная конфигурация может сохранить прежний номер; используйте значение из ответа API. Нативный положительный кэш разделён по шлюзу, имени и ревизии и ограничен 300 секундами. TTL=0 не кэшируется; HTTP Age уменьшает TTL DoH. Дополнительного DNS-кэша Java нет. Изменение только DNS сохраняет существующие файловые TCP-соединения.

Общий предел запроса — 8 секунд, включая подключение и TLS. Поддерживаются публичные IPv4 A-ответы. Локальная проверка DNSSEC, разрешение IPv6 и отдельные запросы продолжения CNAME не реализованы.

Фоновые обновления и смена языка сохраняют несохранённый текст, выделение/курсор и прокрутку. Редактор, справка, подсказки и шаблоны диагностик поддерживают двенадцать языков интерфейса.

## Локальный API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/network/dns` | Самостоятельный объект конфигурации DNS с ревизией и состоянием только для чтения |
| `PUT` или `POST /api/v1/network/dns` | Проверка, применение и сохранение конфигурации; возврат применённого состояния DNS |
| `POST /api/v1/network/dns/test` | Проверка `{settings, gateways, hostname}` без сохранения; проверяйте каждую строку и общий `ok` |
| `GET /api/v1/network/dns/providers` | Режимы и три фиксированных провайдера с конфигурациями DoH/DoT |

Разрешены только ключи `mode`, `provider`, `doh_url`, `dot_host`, `dot_port`, `bootstrap_ips`. Не отправляйте весь ответ GET обратно: ревизия и состояние доступны только для чтения. Состояние DNS также включено в поле `dns` ответа `GET /api/v1/network`. См. [примеры API](../../API.ru.txt) и [OpenAPI](../../openapi.yaml).

## Проверки и границы подтверждённого

На Windows собственные фикстуры прошли **42 проверки протокола резолвера**, **106 проверок HTTP/2 в 43 сценариях** и **891 Swing-проверку**. HTTP/2 проверяется собственными TLS/ALPN `h2` фикстурами с четырьмя подставными идентификаторами провайдеров; Swing-проверки включают реальный таймер окна 900 мс, 12 языков, Unicode, асинхронную работу с черновиком и частичный отказ шлюзов. Интеграция управляемого DNS проверяется отдельными фикстурами. Точный коммит, хеши файлов и результаты платформенных проверок приведены в соответствующем `NATIVE-INSTALLER-TESTS.json`; сами эти количества не подтверждают успех установщиков или физических шлюзов.

Отдельная живая проверка подтвердила Quad9 DoH по HTTP/2 через шлюзы `192.168.1.1`, `192.168.1.2` и `192.168.1.3`. Это подтверждает конкретные DNS-запросы, а не завершение передачи файла. У шлюза `192.168.1.4` нет рабочего WAN, что подтверждено оператором. Наличие пресета, ответ ARP или одна успешная загрузка не доказывают доступ в Интернет через все настроенные шлюзы. Итоговые живые проверки провайдеров и платформ смотрите в отчёте соответствующего выпуска.

Исправления докачки Civitai/CDN и постоянный журнал по шлюзам из 4.1.3 сохранены: [описание 4.1.3](4.1.3.ru.md), [диагностика передачи](../transfer-diagnostics.ru.md).
