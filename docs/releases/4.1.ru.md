# MultiRoute Downloader 4.1

[English](4.1.en.md) · [Русская инструкция](../ru.md) · [Описание проекта](../../README.ru.md)

В этой версии добавлены постоянный журнал сетевых ошибок и проверка локальной сети для собственного транспорта приложения через выбранные шлюзы. Скачивание, отправка файлов, профили сайтов, управление очередью, интеграция с браузерами и проверка контрольных сумм сохранены.

## Ошибки сохраняются после повторных попыток

- Отдельный журнал UTF-8 `logs/network-errors.log` сохраняет время, выбранный шлюз, сервер, этап сбоя и длительность. Для ошибки туннеля также записываются полученный через DNS IPv4 назначения и код lwIP, если они известны.
- Промежуточные ошибки загрузки содержат идентификатор задания, номер сегмента и диапазон байтов, даже если следующая попытка успешна. Журнал переживает перезапуск и удаление старых записей из ограниченной истории в окне лога.
- При размере 4 МиБ журнал переносится в архив; сохраняются три архива. Записи на диске остаются на языке момента записи, а история в интерфейсе может отображаться на текущем выбранном языке.
- В новые диагностические записи не включаются пути URL источника, параметры, фрагменты, учётные данные, заголовки запросов и тела ответов прокси. Имя сервера сохраняется, чтобы различать исходный сайт и сервер хранения/CDN после перенаправления.
- Локальная ошибка CONNECT указывает этап: разбор запроса, ARP, DNS, создание сокета, привязка или установка TCP-соединения. Закрытие соединения до установки отличается от истечения времени ожидания.

Эти изменения позволяют разобрать новый сбой. Они не восстанавливают сведения, потерянные старой сборкой, и не подтверждают устранение всех прежних случаев `Tunnel failed, got: 502`. Локальный ответ CONNECT 502 и HTTP 502 от HTTPS-источника имеют разные причины.

## Проверка подсети и смена IP компьютера

- Используется реальная маска IPv4 выбранного интерфейса. Компьютер, виртуальный IP приложения и все настроенные шлюзы должны иметь разные допустимые адреса узлов одной подсети. Проверка учитывает сети, отличающиеся от /24, например /16, /23 и /25.
- Виртуальный IP и адреса шлюзов не должны быть назначены самому компьютеру. Адрес сети и широковещательный адрес определяются по реальной маске и отклоняются.
- Во время работы сетевого компонента выбранный интерфейс проверяется примерно каждые две секунды. Новый IPv4 компьютера на том же физическом интерфейсе, в той же подсети и с той же маской не меняет виртуальный IP приложения, собственный TCP/IP стек и порты прокси. Наблюдаемая смена адреса записывается в лог.
- При смене подсети или маски, отключении интерфейса, смене аппаратной идентичности адаптера или конфликте адресов собственный транспорт останавливается и требует повторной проверки сети. Проверенные сегменты сохраняются для докачки.

MultiRoute не назначает IP компьютеру и не меняет таблицу маршрутизации ОС. Загрузка через выбранные шлюзы не переключается скрытно на системный шлюз. Проверка подсети подтверждает согласованность локальных настроек; каждый роутер по-прежнему должен предоставлять выход в Интернет для виртуального IP.

Интерфейс показывает наблюдаемые IP компьютера, подсеть, виртуальный IP и число шлюзов. Добавлены переведённые статусы и подсказка о назначении проверки. Новые сообщения поддерживают все двенадцать языков приложения.

## API

`GET /api/v1/network` дополнен объектом `network_validation` со статусом `pending`, `valid` или `error` и доступными сведениями об интерфейсе и подсети. Чтение не запускает сетевой компонент. `POST /api/v1/routes/inspect` проверяет настроенный шлюз и при необходимости запускает компонент; это проверка сети и ARP, а не тест скорости.

Подробности: [проверка сети и диагностика](../network-diagnostics.ru.md), [примеры API](../../API.ru.txt), [схема OpenAPI](../../openapi.yaml). Локальный API по умолчанию остаётся на `http://127.0.0.1:8765/api/v1`; виртуальный IP приложения не является адресом прослушивания API.

## Установка и границы проверки

Устанавливайте полный пакет 4.1, чтобы Java-приложение и сетевой компонент для ОС обновлялись вместе. Нативные пакеты включают Java:

| Платформа | Установщик |
| --- | --- |
| Windows 11 x64 | `MultiRoute-Downloader-4.1-Windows-x64-Setup.exe` |
| Apple Silicon, macOS 26+ | `MultiRoute-Downloader-4.1-macOS-arm64.pkg` |
| Intel, macOS 15+ | `MultiRoute-Downloader-4.1-macOS-x86_64.pkg` |

Отчёт `NATIVE-INSTALLER-TESTS.json` соответствующей версии распространяется рядом с установщиками на странице релиза; в документацию установленного приложения он не включён. В нём указаны версия исходников, контрольные суммы пакетов и фактически выполненные проверки. Требования окружения и подтверждения безопасности описаны в [инструкции](../ru.md).

Это предварительный релиз. У установщиков нет подписи издателя; macOS-пакеты не подписаны Developer ID и не нотарифицированы. Проверки пакетов и тестовых сценариев не доказывают работу на конкретном компьютере. Реальная смена DHCP-адреса во время загрузки через несколько физических роутеров не проверялась; поведение внутри одной подсети проверяется на контролируемых снимках интерфейса. Установка и диалоги безопасности пользователя, а также реальная передача через WAN требуют проверки на целевых системах.

Сохранены требования транспорта к публичному IPv4 и Ethernet. DNS через выбранный шлюз использует UDP-запросы A без перехода на TCP при усечённом ответе и без отдельного запроса продолжения CNAME. Источники только с IPv6, транспорт только по Wi-Fi или только через VPN в этот режим не входят. Ошибки DNS, недоступность WAN и ограничения сервера по-прежнему могут помешать установке туннеля.
