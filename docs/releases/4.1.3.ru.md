# MultiRoute Downloader 4.1.3

[English](4.1.3.en.md) · [Главная](../../README.ru.md) · [Установщики](https://github.com/2018-spec-fdsds/multiroute-downloader/tree/main/downloads/v4.1.3) · [Полная инструкция](../ru.md)

Полный релиз включает Java-приложение, отдельную Java 21 и сетевой компонент для выбранной платформы. В него входят исправления докачки и постоянная диагностика передачи, подготовленные после 4.1.1. Существующий тег 4.1.2 с исходниками сохраняется без изменений; для обновления установленной программы используйте полный пакет 4.1.3.

## Докачка Civitai и других CDN

- Некоторые CDN отвечают HTTP 200 на `Range: bytes=0-0`, хотя поддерживают ненулевые диапазоны. Перед выбором последовательной загрузки MultiRoute проверяет `bytes=1-1`. Ответ HTTP 206 должен соответствовать запрошенному диапазону, размеру и признакам идентичности источника.
- Проверенный ответ HTTP 200 для первого сегмента читается только до его границы. Затем поток закрывается: оставшаяся часть полного файла не записывается поверх соседних сегментов.
- Совместимая сохранённая часть старой последовательной загрузки после проверки источника переводится в полные сегменты без обрезания сохранённых данных. Незавершённый последний сегмент скачивается повторно; подтверждённый прогресс может уменьшиться менее чем на один сегмент.
- Временный проверенный HTTP 200 для ненулевого диапазона отклоняется до записи данных. Сегмент возвращается в очередь; поток выбранного шлюза остаётся доступным и повторяет попытку через 2–30 секунд. Один такой ответ больше не выводит этот поток из работы навсегда.
- Если безопасная докачка действительно невозможна, неполный файл сохраняется, задание приостанавливается с `restart_required=true`. Продолжение повторно проверяет источник и не разрешает удалять сохранённые данные. Перед повторными попытками изучите ошибку и поля состояния докачки.

Проверки размера, идентичности источника и ответов сервера сохраняются. Ожидаемые контрольные суммы, заданные вручную или найденные автоматически, по-прежнему сверяются после завершения; один локально вычисленный хеш не подтверждает соответствие файлу издателя. Размер сегмента по умолчанию — 20 МиБ.

## Постоянная диагностика передачи

Переведённые события доступны в **Настройки → Журнал**, постоянные файлы — через **Открыть папку журналов**. `logs/download-transfers.jsonl` хранится в UTF-8, по одной JSON-записи на строку: текущий файл до 4 МиБ и три архивных файла. Журнал переживает перезапуск и содержит идентификаторы задания, шлюза и попытки, диапазон байтов, время и результат.

`attempt_bytes` — данные, полученные за попытку, включая неудачную; `persisted_bytes` — полезный сохранённый прогресс; `wire_total_bytes` — все полученные данные, включая повторный трафик. Служебные данные Ethernet/TCP/TLS в эти счётчики не входят. Начало и конец попытки фиксируются отдельно, промежуточные сводки — не чаще одного раза в 12 секунд для каждой попытки. URL источника, локальные пути, содержимое файлов и секреты авторизации не записываются. Значение полей и события сохранения данных описаны в [диагностике передачи](../transfer-diagnostics.ru.md).

## Выполненная проверка и ограничения

Установленное приложение завершило реальную загрузку **10 164 675 942 байт**; итоговая SHA-256 совпала с ожидаемым эталоном. Частные имена, пути, URL и эталонные хеши не публикуются. Это подтверждает конкретную передачу и её целостность; проверки сборки, установщиков и регрессии новых файлов релиза учитываются отдельно.

У шлюза `192.168.1.4` сейчас нет работающего WAN-подключения, что подтвердил оператор. Наличие шлюза в настройках или успешный ARP не доказывает доступ в Интернет. Этот релиз не заявляет исправность всех четырёх настроенных шлюзов. Реальная передача через шлюзы в macOS и смена DHCP при активной передаче через физические роутеры ещё не проверены.

Перед установкой сверяйте контрольные суммы пакета, версию и коммит исходников с `NATIVE-INSTALLER-TESTS.json` рядом с файлами релиза. Отчёт перечисляет фактически завершённые проверки и платформы. Этот документ не объявляет новую сборку или проверку установщика успешной до её фиксации в отчёте. Результаты передачи версии 4.1.1 относятся к той версии.

## Установка и обновление

Перед обновлением выйдите через меню трея, затем установите полный пакет своей платформы. Сохраните папку данных и загруженные части. Мастер Windows работает на английском и создаёт ярлык на рабочем столе. Npcap устанавливается отдельно обычным интерактивным установщиком с UAC. macOS использует системную libpcap и стандартное подтверждение администратора для защищённого компонента; Java работает от обычного пользователя.

| Платформа | Установщик |
| --- | --- |
| Windows 11 x64 | `MultiRoute-Downloader-4.1.3-Windows-x64-Setup.exe` |
| Apple Silicon, macOS 26+ | `MultiRoute-Downloader-4.1.3-macOS-arm64.pkg` |
| Intel, macOS 15+ | `MultiRoute-Downloader-4.1.3-macOS-x86_64.pkg` |

Установщики не подписаны издателем; пакеты macOS не подписаны Developer ID и не нотарифицированы. Подтверждения SmartScreen/Gatekeeper, администратора, локальной сети и доступа к папке описаны в [инструкциях на двенадцати языках](../ru.md). В нативные пакеты включена отдельная Java 21; для нативного пакета macOS отдельная Java, Terminal, Command Line Tools и Homebrew не требуются.

API сохраняет `/api/v1` и адрес по умолчанию `http://127.0.0.1:8765/api/v1`; health сообщает `4.1.3`. DNS через выбранный шлюз сохраняет повтор UDP → TCP и общий лимит 8 секунд. DoH, DNSSEC, IPv6 и отдельные запросы продолжения CNAME не поддерживаются. Приложение не меняет маршруты и адреса интерфейсов ОС.

Источники реализации: [HTTP Range и Content-Range, RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-range), [рекомендации OWASP по журналированию](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html).
