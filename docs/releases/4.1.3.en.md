# MultiRoute Downloader 4.1.3

This full package release includes the Java application, private Java 21 runtime and platform network component. It publishes the resumable-download and persistent-transfer-diagnostic changes prepared after 4.1.1. The existing 4.1.2 source-only tag remains unchanged; use a complete matching 4.1.3 installer to update the installed application.

## Resuming downloads from Civitai and similar CDNs

- Some CDNs return HTTP 200 to `Range: bytes=0-0` even though a nonzero range works. MultiRoute checks `bytes=1-1` before deciding that the source cannot resume. A valid HTTP 206 response must match the requested range, size and source validators.
- A validated HTTP 200 response for the first segment supplies only that segment's bounded byte count. The stream then closes; its remaining full-file body is not written into neighboring segments.
- Compatible data saved by an older whole-file attempt can be recovered as complete segments after source-identity checks, without truncating the saved prefix. An incomplete final segment is fetched again; displayed verified progress can therefore decrease by less than one segment.
- A temporary validated HTTP 200 for a nonzero range is rejected before payload writing. The segment returns to the queue and the selected gateway worker remains available, with a retry delay of 2–30 seconds. This response no longer permanently removes that worker after the first occurrence.
- When a source truly cannot resume safely, the partial file is preserved and the job pauses with `restart_required=true`. Resume rechecks the source; it does not authorize discarding existing data. Inspect the job's error and resume fields before repeating retries.

Source-size, identity and response validation remain enforced. Configured or discovered expected whole-file checksums are still checked at completion; a locally calculated hash alone is not publisher verification. The default segment size remains 20 MiB.

## Persistent transfer diagnostics

Open **Settings → Log** for translated transfer events, or **Open logs folder** for the active data directory. `logs/download-transfers.jsonl` is UTF-8 JSON Lines, with a 4 MiB current file and three rotated archives. It survives restarts and records job/gateway/attempt identifiers, byte ranges, elapsed time and outcome.

`attempt_bytes` counts received payload for one attempt, including unsuccessful traffic; `persisted_bytes` shows useful saved progress; `wire_total_bytes` includes cumulative received payload and repeated traffic. These counters do not include Ethernet/TCP/TLS framing. Attempt boundaries are recorded separately; progress summaries occur no more often than every 12 seconds per attempt. The structured event fields omit source URLs, local paths, file contents and authentication secrets. Filesystem error text in `reason` can contain a local filename or path; review logs before sharing them. See [transfer diagnostics](../transfer-diagnostics.en.md) for field meanings and preserved-prefix events.

## Evidence and validation limits

The installed application completed one real file of **10,164,675,942 bytes** and its final SHA-256 matched the expected reference. Private file names, paths, source URLs and reference hashes are not published. This confirms that transfer and its integrity check; it is separate from the build, installer and regression gates for the new release artifacts.

Gateway `192.168.1.4` currently has no working WAN connection, as confirmed by the operator. A configured gateway or a successful ARP check does not establish Internet access. This release does not claim that all four configured gateways are live or healthy. Real macOS gateway operation and a DHCP change during an active physical multi-router transfer remain unverified.

Before installing, match the package checksums and source version/commit against `NATIVE-INSTALLER-TESTS.json` beside the release assets. That report records the actual completed gates and platform checks. This document does not declare a new build or installer test passed before it is recorded there. Earlier 4.1.1 transfer results remain historical evidence for that version.

## Install and update

Exit the running application through its tray menu, then install the complete matching package. Preserve the existing data directory and downloaded parts. Windows Setup uses English and creates a desktop shortcut. Npcap is a separately installed prerequisite; missing-driver installation uses the normal interactive installer and UAC. macOS uses system libpcap and the protected component's normal administrator authorization. Java runs as the normal user.

| Platform | Installer |
| --- | --- |
| Windows 11 x64 | `MultiRoute-Downloader-4.1.3-Windows-x64-Setup.exe` |
| Apple Silicon, macOS 26+ | `MultiRoute-Downloader-4.1.3-macOS-arm64.pkg` |
| Intel, macOS 15+ | `MultiRoute-Downloader-4.1.3-macOS-x86_64.pkg` |

Installers are unsigned; macOS packages are not Developer ID signed or notarized. Follow the [twelve language guides](../en.md) for SmartScreen/Gatekeeper, administrator, Local Network and folder confirmations. The packages include private Java 21; a separate Java installation, Terminal session, Command Line Tools or Homebrew is not required for native macOS installation.

The local API remains `/api/v1`, defaulting to `http://127.0.0.1:8765/api/v1`; health reports version `4.1.3`. Gateway-bound DNS retains the UDP-to-TCP retry behavior and the 8-second total DNS budget. DoH, DNSSEC, IPv6 and separate CNAME continuation queries remain unsupported. The application does not change operating-system routes or interface addresses.

Implementation references: [HTTP Range and Content-Range semantics, RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-range) and [OWASP logging guidance](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html).
