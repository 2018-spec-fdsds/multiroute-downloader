# Диагностика передачи файлов (4.1.3)

Переведённые события передачи доступны в **Настройки → Лог**. Кнопка открытия папки журналов показывает журналы текущего каталога данных.

`logs/download-transfers.jsonl` — журнал UTF-8: один JSON-объект на строку. Хранятся текущий файл до 4 МиБ и три архивных файла (`.1` — самый новый). В записях есть:

- дата и время UTC, идентификаторы задания и попытки, IP шлюза;
- запрошенный диапазон байтов и длительность попытки;
- `attempt_bytes` — полученные байты этой попытки, включая неудачные попытки;
- `persisted_bytes` — полезный сохранённый прогресс задания на момент записи;
- `wire_total_bytes` — суммарно полученные байты задания, включая повторную передачу;
- завершение, обрыв, причина ошибки и сохранение скачанной части.

Промежуточные записи создаются не чаще одного раза в 12 секунд для каждой попытки. Начало и окончание записываются отдельно. Событие `prefix_restarted` обозначает явно запрошенный сброс; поле `discarded_bytes` отличает его от повторной попытки с сохранением данных. Исправление предотвращает автоматический сброс последовательной загрузки. Структурированные поля событий не содержат URL источника и секреты авторизации. Текст ошибки файловой системы в `reason` может содержать локальное имя или путь файла; перед отправкой журнала проверьте его содержимое.

## Докачка и поведение источника

Некоторые CDN игнорируют диапазоны, начинающиеся с нуля, но поддерживают остальные. Приложение проверяет ненулевой диапазон перед выбором последовательного режима. Первый сегмент из ответа HTTP 200 читается только до границы сегмента после проверки ответа. Для остальных диапазонов обязательны HTTP 206 и корректный Content-Range. Проверка заданных или найденных итоговых контрольных сумм сохраняется.

Если уже работающая загрузка по частям временно получает HTTP 200 для ненулевого диапазона, такой ответ отклоняется до записи. Выбранный шлюз повторяет попытку с задержкой 2–30 секунд вместо постоянного отключения после одного неверного ответа.

Частичный файл прежней последовательной загрузки переиспользуется целыми сегментами, если проходят проверки идентичности источника. Последний незавершённый сегмент запрашивается заново: отображаемый прогресс может уменьшиться менее чем на один сегмент. Полные сохранённые сегменты при этом остаются.

Если источник действительно не позволяет продолжить, приложение сохраняет частичный файл, приостанавливает задание и выставляет `restart_required=true`. Вызов `POST /api/v1/jobs/{id}/resume` повторно проверяет источник и не разрешает удаление частичного файла. Перед автоматическими повторами проверяйте `status`, `error`, `resumable`, `distribution_supported` и `restart_required`.
