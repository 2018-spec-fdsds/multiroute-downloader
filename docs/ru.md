## 4.3.9 — Актуальные возможности, Free и Pro

Инструкция описывает MultiRoute Downloader 4.3.9. Установщики и опубликованные контрольные суммы доступны в [релизе 4.3.9](https://github.com/2018-spec-fdsds/multiroute-downloader/releases/tag/v4.3.9). Разделы ниже описывают актуальные функции и лицензионные возможности.

### Лимиты и возможности лицензии

Free включает обычную загрузку одного файла, поддерживаемую докачку, всю доступную скорость, проверку целостности, защищённый DNS и текущие скорости/статусы шлюзов. Искусственного ограничения скорости нет. Подписанные права независимы: частичная лицензия Pro открывает только перечисленные в ней возможности.

| Возможность | Free | С правом в лицензии | ID |
| --- | --- | --- | --- |
| Одновременно используемые шлюзы | ≤ 2 | ≤ 8 | `extra_gateways` |
| Одновременные загрузки | ≤ 3 | ≤ 32 | `extra_concurrent_downloads` |
| Профили сайтов | ≤ 3 | Без лицензионной квоты | `extra_site_profiles` |
| Приоритеты загрузок | Только обычный | Можно выбирать | `download_priorities` |
| Приоритеты шлюзов | 0 | Можно выбирать | `gateway_priorities` |
| История и отчёты по шлюзам | Недоступно | Доступно | `gateway_statistics` |
| Групповые загрузки / отправки | Недоступно | Доступно | `batch_downloads` |
| API для сторонних приложений | Недоступно | Доступно | `automation_api` |
| Дополнительные темы оформления | Graphite / System | Все темы | `premium_appearance` |

Для пакета откройте **Новая загрузка…** и нажмите **Список ссылок…** в неподвижной строке действий внизу этого окна.

Включаются только права из вашей подписанной лицензии. Существующие файлы и профили сохраняются. Остальные файлы ждут в очереди; текущие скорости и состояния шлюзов доступны. Технические ограничения хранилища сохраняются.

Лимит шлюзов — общий набор, используемый скачиваниями и отправками, без дополнительного системного шлюза. Лимит трёх одновременных заданий относится к скачиваниям, а не отправкам; остальные скачивания ждут очередь. Меньший настроенный лимит очереди сохраняет силу. Старые списки шлюзов, профили, прогресс и приоритеты не удаляются. Квота профилей ограничивает создание новых; прежними можно пользоваться. История трафика/CSV требует своего права, живые показатели доступны в Free. Расписание доступно; нестандартные приоритеты требуют своего права. Технические ограничения хранилища и источника сохраняются.

Подписанная лицензия относится к ключу установки, а не MAC, IP или роутеру. У неё нет срока истечения; диапазон 4–4 покрывает 4.x. Смена шлюзов, DHCP или MAC приложения не требует повторной активации. Другой компьютер, учётная запись или профиль данных могут потребовать новый запрос. Это не обещание невозможности изменения кода или универсальной аппаратной привязки.

### MAC приложения

MultiRoute использует собственный постоянный MAC при ручном IP и DHCP. MAC сетевой карты ОС не меняется. Проверяются конфликты с наблюдаемыми устройствами и другими MultiRoute; отсутствие ответа не гарантирует отсутствия выключенных устройств. Пул: локально администрируемые одноадресные MAC, 46 случайных бит. Это не пул IP-адресов DHCP.

**Сменить MAC…** — Кнопка доступна после приостановки или завершения активных и ожидающих передач и окончания локальных проверок контрольных сумм. MultiRoute проверяет наблюдаемые адреса источников и совместные объявления других экземпляров MultiRoute. «Конфликт не обнаружен» не гарантирует отсутствия выключенного или молчащего устройства с таким адресом. MAC приложения должен отличаться от физического MAC адаптера; его смена не меняет адаптер и маршруты ОС.

### Контрольная сумма…

Эталон сохраняется без перезапуска и обнуления прогресса. MD5, SHA-256 или SHA-512 определяются автоматически по 32, 64 или 128 шестнадцатеричным символам. Собранный файл будет проверен после скачивания. Сохраните эталон и нажмите «Проверить сейчас». Проверяется готовый локальный файл. Несовпадение показывается без повторной загрузки и удаления файла.

При финальной сборке используется последняя сохранённая эталонная сумма. Её изменение не сбрасывает скачанные байты и не перезапускает передачу. Повторная проверка готового файла сохраняет файл и показывает совпадение, несовпадение или ошибку отдельно от завершения загрузки. Эталоны издателя сохраняются независимо. Одна сумма целого файла не подходит сразу к нескольким файлам torrent. Сравнение проверяет целостность относительно эталона, а не безопасность содержимого; для защиты предпочтителен доверенный SHA-256/SHA-512.

### Доступ к API в 4.3.9

Локальный JSON API использует UTF-8 без обычного API-токена. Внешнее управление требует automation_api; остальные права проверяются дополнительно, поэтому это право само по себе не разрешает пакетную загрузку или лишние шлюзы. В Free остаются узкая диагностика чтения, закрытая аутентифицированная остановка экземпляра и включаемая передача одной ссылки из браузера. См. [описание API](../API.ru.txt) и [OpenAPI](../openapi.yaml). Не открывайте порт в LAN или Интернет.


Для оригинального приложения действует [Лицензия 1.2](../LICENSE.txt): Free разрешена для личного использования и работы организаций/бизнеса; правообладатель может предлагать платные условия Pro. Другим получателям продажа/перепродажа без отдельного разрешения запрещена. OpenJDK GPLv2 с Classpath Exception требует уведомлений и соответствующих исходников; JNA используется по Apache-2.0 с уведомлениями; отдельная JLayer LGPL-2.1 сохраняет права замены/отладки и доступ к исходникам. См. [условия](../LICENSING.md), [полный каталог компонентов](../THIRD-PARTY-NOTICES.txt) и страницу лицензий приложения.

Оформление System обеспечивает читаемый контраст текста таблиц, полей и элементов на системном фоне; Graphite и System входят в Free.

Имя файла и размер показаны в отдельных столбцах. Размер сортируется численно, независимо от имени; неизвестный размер обозначен тире. Полное имя и путь доступны во всплывающей подсказке.

Наведите указатель на имя файла: подсказка показывает полное имя, путь сохранения, протокол передачи и адрес источника либо путь к локальному источнику. Для торрент-задания указан BitTorrent, даже если его метаданные открыты через HTTPS. При наличии адреса репозитория он показан после фактического URL файла. Встроенные учётные данные, значения query-параметров и fragment скрыты; распознанный публичный infohash magnet может оставаться видимым. Меняется только подсказка, а не сохранённый адрес загрузки или состояние передачи.


### Приоритеты шлюзов и диагностика передач в 4.3.9

В настройках сети задайте приоритет каждого шлюза от **0 до 1000**; значение видно рядом с его индикатором. Большее число даёт шлюзу предпочтение для небольших файлов и загрузок целиком, а для большого файла — больше параллельных сегментов. Остальные выбранные исправные шлюзы продолжают помогать. При равных значениях сохраняется порядок выбора; при сбое или зависании предпочтительного шлюза работу может получить другой выбранный шлюз. Это предпочтение, а не обещанное соотношение скоростей.

Нужно отдельное подписанное право **`gateway_priorities`**. Право приоритета заданий **`download_priorities`** его не включает. Без права на приоритеты шлюзов фактическое значение у всех равно 0; сохранённые настройки остаются. Приоритеты можно менять во время загрузки без сброса проверенных частей. Распределитель использует от одного до четырёх параллельных обработчиков сегментов на выбранный шлюз, всего не более 32 на задание.

В настройках доступны число одновременных загрузок в пределах лицензии и конечное либо неограниченное число автоматических повторов. Ручная пауза сохраняется. Контекстное меню поддерживает паузу/продолжение подходящих выбранных заданий и копирование имён файлов. Двойной щелчок открывает только папку файла; свойства, статистика и индивидуальный лог открываются из контекстного меню.

Лог доступен и для завершённых файлов. В настройках «Ошибки и решения» открывается локальный справочник с поиском: 25 тем на всех 12 языках интерфейса. У места сохранения и в свойствах файла видно свободное место в ГБ. Локальное заполнение диска явно обозначается как «Нет места на диске», сохраняет скачанные части и не превращается в бесконечный сетевой повтор. При ожидании новых данных после продолжения небольшого сегмента сохранённый префикс остаётся в показателе прогресса.

### Оставшийся объём загрузки · 4.3.9

В таблице загрузок появилась отдельная колонка **Осталось скачать**. Она показывает объём ещё не загруженных данных отдельно от оценки оставшегося времени и сортируется численно. Значение учитывает сохранённые данные и текущий прогресс, не опускается ниже нуля; при неизвестном общем размере отображается тире.

### Надёжнее запуск Mac и настройка шлюзов · 4.3.9

При нативном запуске Mac распознаётся старый относительный путь по умолчанию, в том числе без начального слеша: используется подтверждённый существующий профиль или пустая папка по умолчанию в учётной записи. Для неоднозначного пользовательского пути требуется явный выбор, а не догадка.

После ошибки или отмены подготовки шлюза остальные шлюзы и фоновые проверки не повторяют запросы прав до явной повторной настройки сети. Первый привилегированный запуск по-прежнему может потребовать обычного подтверждения администратора macOS для открытия Ethernet-устройства BPF.

Сетевой компонент Mac 4.3.2 учитывает скрытый системой MAC адаптера, сохраняя проверки защиты физической карты. У приложения остаётся собственный MAC; маршруты ОС и MAC физической карты не меняются. Значок и имя Mac-приложения приведены к идентичности MultiRoute в Windows. Перед обновлением через PKG закройте приложение. Имя инициатора в реальном системном диалоге и передачи LAN/DHCP ещё требуют проверки на оборудовании; для этого транспорта по-прежнему нужен проводной Ethernet.

**macOS:** `/Applications/MultiRoute Downloader.app` · `/Library/PrivilegedHelperTools/MultiRouteResume/4.3.2/{gateway-net,gateway-launch}`.

### Ответы шлюзов Mac при ручном адресе · 4.3.9

Настройка захвата POSIX исправлена: и ручной адрес приложения, и DHCP используют режим приёма ответов на собственный MAC приложения, как уже было в Windows. Успешный системный ping проверяет соединение самого компьютера и не подтверждает приём ответов шлюза виртуальным адресом приложения.

Диагностика DHCP сохраняет формулировки на двенадцати языках вместо замены общим сообщением. Поведение авторизации остаётся прежним: обычные проверки сети повторно используют подготовленный компонент. Методы API, элементы интерфейса, маршруты ОС и MAC физической карты не меняются. Первый привилегированный доступ к Ethernet BPF по-прежнему может запросить обычное подтверждение администратора.

Исправляется конкретное различие режима захвата, а не все причины недоступности шлюза. Проверки свободного адреса, подсети и аренды/конфликтов DHCP остаются активны. Передачи Mac с ручным адресом ещё требуют проверки на оборудовании; проводной Ethernet по-прежнему необходим.

## Оформление и звуки завершения

Выбирайте из девяти оформлений: Graphite, Nordic, Streams Studio, Neon, Community, Chat, Studio, Rose и System. По умолчанию используется Graphite. Graphite и System доступны в Free; остальным нужно соответствующее право Pro на оформление. В разделе Настройки → Оформление можно менять стиль и скругление элементов. Загрузки при этом продолжаются. **Закруглённые окна и кнопки** включаются отдельно. Закругление элементов работает в разных стилях; внешнюю рамку окна определяет ОС. В Windows 11 развёрнутые и закреплённые окна могут оставаться прямоугольными, а в macOS и Linux форму рамки задаёт система. В интерфейсе доступен график скорости, а в настройках сети используются компактные карточки шлюзов.

Звуки завершения **выключены по умолчанию**. Включите общий флажок, затем независимо выберите уведомления **после каждого файла** и **после всех загрузок**. Доступны **Мягкие колокольчики**, **Пиано** и **Маримба**; обе мелодии можно прослушать заранее. Когда завершены все загрузки и включён общий сигнал, для последнего файла звучит только финальная мелодия, без второго наложенного сигнала. Задания на паузе или с ошибкой не считаются завершёнными. Старая история не озвучивается при запуске или смене настроек. Слышимость также зависит от системной громкости и выбранного аудиовыхода.

Для своих звуков выберите **Собственная мелодия** и укажите отдельные файлы **MP3 или WAV** для завершения файла и всех загрузок. Каждый фрагмент должен длиться **не более 10 секунд**: приложение проверяет длительность декодированного звука, а не только расширение или метаданные. Принятые файлы копируются в локальный профиль приложения; исходники после этого можно переместить.

Необязательный курьер на рабочем столе превращает прогресс скачивания в наглядный груз. В настройках оформления выберите мужчину или женщину и масштаб от 40% до 100%. На мешке показана сумма известного оставшегося объёма активных загрузок; по мере получения байтов мешок уменьшается. Движение зависит от общей скорости скачивания, а при нулевой скорости курьер стоит. Маленький груз он несёт на плече, больший тащит по земле, а очень большой — с заметным усилием.

Кнопка Аватар показывает или скрывает курьера. Перетаскивайте его мышью, дважды нажмите левой кнопкой, чтобы открыть приложение, или нажмите правой для меню действий. Это визуальный спутник: файлы сохраняются в выбранных вами папках.

После завершения курьер кладёт доставленный груз и плавно исчезает. Если загрузки продолжаются, он возвращается с оставшимся объёмом.

Оформление, закругление и звуки — локальные настройки настольного интерфейса. Они не добавляют методы API загрузки и не меняют параметры передачи, контрольных сумм или защиты DNS.

## Папка данных приложения

Настольная установка использует сохранённый абсолютный путь к папке данных, независимо от рабочего каталога при входе в систему. История загрузок, настройки и сохранённые части находятся в выбранном профиле. Поддерживаются пути переносимой версии в командной строке; явный `--data-dir` задаёт папку данных.

<a name="automatic-startup"></a>

## Автозапуск

Рядом с выбором языка и темы включите **Запускать вместе с операционной системой**. По умолчанию настройка **выключена**. Включение создаёт запись для следующего входа именно в вашу учётную запись; отключение удаляет собственную запись приложения. Это запуск при входе пользователя, а не системная служба и не запуск до входа. Для создания записи не нужны права администратора.

При автоматическом запуске приложение использует трей, если он поддерживается; иначе остаётся доступное обычное окно. Приоритеты, паузы и расписания очереди сохраняются: автозапуск не отменяет их и не продолжает принудительно все приостановленные загрузки. Сначала завершите установку и настройку сетевых компонентов, открыв приложение вручную. Не перемещайте зарегистрированное приложение, а для переносной версии — также Java и библиотеки. После переноса выключите и снова включите автозапуск из нового расположения. Перед удалением программы выключите автозапуск.

ОС или политика рабочего стола может отключить созданную запись. В macOS при запросе разрешения проверьте **Системные настройки → Основные → Объекты входа и расширения**; разрешение для сетевого компонента выдаётся отдельно. Наличие записи не доказывает успешный запуск при будущем входе. Реальная перезагрузка и выход из учётной записи не входят в проверки на отдельных тестовых профилях; результаты приведены в отчёте соответствующего релиза.

Если приложение не открывается, удалите **только его собственную запись**:

- **Windows:** приложение хранит собственный параметр `REG_SZ` с именем **MultiRoute Downloader** в `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`. Сначала попробуйте выключить автозапуск в приложении. Если оно не открывается, в редакторе реестра удалите **только этот параметр**, сохранив раздел Run и остальные записи. Если запись отключена ОС, используйте **Параметры → Приложения → Автозагрузка**; приложение не отменяет это решение. Полная команда автозапуска Windows ограничена 260 символами; при превышении используйте более короткий путь приложения/профиля и создайте запись заново.
- **macOS:** удалите `~/Library/LaunchAgents/io.github.2018-spec-fdsds.multiroute-downloader.plist`.
- **Linux:** удалите `${XDG_CONFIG_HOME:-~/.config}/autostart/io.github.2018-spec-fdsds.multiroute-downloader.desktop` из фактической папки конфигурации XDG. Нужен графический рабочий стол с поддержкой автозапуска XDG; эта настройка не создаёт службу systemd.

<a name="dns-settings"></a>

## Настройки DNS

Результаты проверки платформ и установщиков приведены в [NATIVE-INSTALLER-TESTS.json](../NATIVE-INSTALLER-TESTS.json).

Откройте **Сеть → Разрешение DNS**. По умолчанию выбраны **DNS через HTTPS (DoH), Cloudflare**. Настройка относится только к MultiRoute: DNS компьютера, системные маршруты и IP-адреса интерфейсов не меняются.

DoH поддерживает ограниченный HTTP/2 при выборе через TLS ALPN и HTTP/1.1 при согласовании этого протокола. Совместимость провайдера и живые результаты шлюзов подтверждаются отчётом соответствующего конечного выпуска.

- **DoH:** зашифрованные DNS-запросы через HTTPS по каждому выбранному шлюзу. Сертификат TLS проверяется по имени хоста из URL.
- **DoT:** зашифрованные DNS-запросы через TLS по каждому выбранному шлюзу; стандартный порт — 853. Сертификат TLS проверяется по имени сервера.
- **Системный DNS (компьютер):** явно использовать политику DNS компьютера, ОС или VPN. Для DNS не гарантируется путь через каждый выбранный шлюз; файловые соединения продолжают использовать свои шлюзы. Этот режим сам по себе не гарантирует шифрование DNS.

Выберите Cloudflare, Quad9, Google или **Свой**. Значения пресетов фиксированы; свой сервер позволяет менять соответствующий URL/имя, порт и числовые публичные IPv4 для начального подключения. Они позволяют подключиться к провайдеру без предварительного запроса его имени через ОС. DoH/DoT проверяют доверенную цепочку сертификата, имя хоста и SNI; скрытого перехода к незашифрованному или системному DNS нет. Ошибка защищённого DNS завершает эту попытку. Провайдер должен быть доступен через выбранный шлюз.

Измените черновик, выберите шлюзы и нажмите **Проверить DNS**. Проверка использует черновик, не сохраняя его; для каждого шлюза показывает результат, время и публичные IPv4 либо ошибку. Частичная ошибка остаётся видна. В системном режиме успешный ответ подтверждает разрешение имени ОС, а не отдельный выход в Интернет каждого шлюза. **Применить настройки DNS** проверяет и сохраняет конфигурацию. Возвращённая ревизия обозначает применённую конфигурацию; фоновые обновления статуса и смена языка сохраняют несохранённый текст, курсор и прокрутку.

Общий предел запроса — 8 секунд, включая дополнительные запросы проверки. TTL проверенного ответа ограничен также сроком подписи; нативный кэш ограничен 300 секундами и разделён по шлюзам и ревизиям. Нулевой TTL и HTTP Age для DoH сохраняют значение. Системный режим следует политике кэша ОС/JVM. Для файлов поддерживаются публичные IPv4; разрешение IPv6 не поддерживается.

API: `GET /api/v1/network/dns` возвращает конфигурацию и состояние только для чтения; `PUT` (или `POST`) по тому же адресу применяет конфигурацию. `POST /api/v1/network/dns/test` проверяет черновик; `GET /api/v1/network/dns/providers` перечисляет пресеты. Передавайте только поля конфигурации без ревизии и статусов из GET. См. [руководство API](../API.ru.txt) и [схему OpenAPI](../openapi.yaml).

<a name="dnssec-validation"></a>

## Локальная проверка DNSSEC

В разделе **Сеть → Разрешение DNS → Проверка DNSSEC** выберите **Проверять подписанные домены** (по умолчанию для DoH/DoT), **Требовать защиту DNSSEC** или **DNSSEC отключён**. Подписи проверяются локально в Java через dnsjava со встроенными корневыми якорями доверия. Один флаг AD от провайдера не является доказательством. DoH/DoT шифрует передачу, а DNSSEC отдельно подтверждает подлинность DNS-данных.

Обычная **проверка** принимает защищённые ответы и ответы без подтверждённой защиты; **строгий режим** — только защищённые. Отсутствие защиты может означать подтверждённое неподписанное делегирование или неподдерживаемые алгоритмы: смотрите причину. Недостоверные и неопределённые ответы при включённой проверке отклоняются. Системный DNS отключает локальную проверку; возврат к DoH/DoT восстанавливает последнюю политику. Смена пресета провайдера её сохраняет. «Применить» сохраняет настройку, «Проверить DNS» использует несохранённый черновик.

Результат каждого запроса различает `secure`, `insecure`, `bogus`, `indeterminate`, `not_checked`; отсутствие результата показывается отдельно. Успешное соединение не означает защиту DNSSEC. Есть отдельные причины для истёкшей подписи, отсутствующего ключа/доказательства, ошибки запроса и тайм-аута проверки. Часы компьютера должны быть точными. Дополнительные запросы проверки идут через тот же выбранный шлюз в пределах общего времени. DNSSEC не скрывает имена и не проверяет содержимое скачиваемого файла.

В API добавлено поле конфигурации `dnssec`: `off`, `validate`, `require` (системный режим принимает только `off`). Поля `dnssec_validation`, `dnssec_trust_anchors` и результаты `dnssec_status`, `dnssec_reason_code`, `dnssec_reason`, `dnssec_validated_ttl`, `dnssec_aux_queries` доступны только для чтения. Не передавайте их обратно при сохранении настроек. См. API/OpenAPI выше и [DNSSEC](#dnssec-validation).

**Обработка диапазонов HTTP:** CDN, включая Civitai, которые отвечают HTTP 200 на диапазон с нулевого байта, дополнительно проверяются ненулевым диапазоном. Первый сегмент ограничен своим размером; совместимые сохранённые данные последовательной загрузки продолжаются по сегментам. Временный HTTP 200 для ненулевого диапазона вызывает повтор через 2–30 секунд с сохранением данных и доступности потока шлюза. Постоянный журнал по шлюзам различает полученный трафик и сохранённый прогресс. [Диагностика передачи](transfer-diagnostics.ru.md).

[Установщики 4.3.9](../downloads/v4.3.9/README.md) содержат отдельную Java 21. Мастер Windows работает на английском и создаёт ярлык на рабочем столе; Npcap устанавливается отдельно. В macOS используется системная libpcap. Подробные шаги установки и подтверждения безопасности приведены ниже.

MultiRoute Downloader — настольное приложение на Java для скачивания через один или несколько **шлюзов** вашей локальной сети. Оно выдаёт доступные части шлюзам, сохраняет проверенные данные и собирает итоговый файл. Локальный API позволяет создавать и управлять загрузками из других приложений. Окно программы — отдельный настольный интерфейс.

Владелец проекта: [2018-spec-fdsds](https://github.com/2018-spec-fdsds).

## Для чего нужно приложение

При нескольких независимых интернет-подключениях в вашей сети, например проводной линии и мобильного роутера 4G/5G, приложение использует их пропускную способность одновременно. Компьютер обращается к шлюзам через общую локальную Ethernet-сеть.

- **Увеличение общей скорости:** все выбранные доступные шлюзы параллельно скачивают части файлов из общей очереди; более быстрые шлюзы могут получать больше частей.
- **Отказоустойчивость:** при отказе одного шлюза остальные продолжают сегментированную загрузку. Незавершённые части возвращаются в очередь для другого шлюза, а проверенные данные сохраняются.
- **Групповая загрузка:** добавляйте список ссылок, управляйте очередью нескольких файлов или создавайте группу загрузок через локальный API.

Прирост скорости зависит от независимости внешних подключений и ограничений сервера. Докачка и перераспределение частей требуют поддержки безопасного возобновления передачи источником и протоколом.

<a name="application-virtual-ip"></a>

### Зачем приложению виртуальный IP

**Выбирайте шлюзы для MultiRoute, сохраняя обычное подключение остальных программ.** Приложение использует собственный свободный адрес локальной сети IPv4 для внутреннего сетевого транспорта. Это позволяет устанавливать соединения через выбранные шлюзы независимо от шлюза компьютера по умолчанию, без изменения IP системного адаптера, таблицы маршрутов и основного шлюза ОС. Браузер и другие программы продолжают работать по своим обычным сетевым настройкам.

Например, в сети `192.168.1.0/24` компьютер сохраняет свой обычный адрес `192.168.1.x`, MultiRoute может использовать свободный `192.168.1.70`, а загрузки — шлюзы `192.168.1.1`–`192.168.1.4`. Компьютер, виртуальный адрес и выбранные шлюзы должны находиться в одной реальной подсети IPv4. Свободный адрес нужно проверить и применить в разделе сети приложения; вручную добавлять его системному адаптеру не требуется. Виртуальный IP не создаёт ещё одно подключение к интернету: пропускную способность обеспечивают роутеры и их внешние каналы.

#### Как выбрать и проверить адрес

1. Посмотрите IPv4 и маску Ethernet-адаптера компьютера. Выберите допустимый адрес устройства в той же подсети. `192.168.1.70` — только пример; нельзя выбирать собственный IP компьютера, адрес любого шлюза, адрес сети или широковещательный адрес.
2. Откройте админку роутера и проверьте фактический диапазон выдачи DHCP. Используйте адрес вне автоматической выдачи либо зарезервируйте/исключите его на DHCP-сервере. Если LAN обслуживают несколько DHCP-серверов, адрес должен быть защищён от выдачи каждым из них.
3. В MultiRoute нажмите **«Проверить и применить»** для виртуального адреса, затем проверьте шлюзы. Приложение проверяет подсеть и конфликт через ARP. Отсутствие ответа ARP означает лишь, что конфликт не обнаружен в этот момент: это не доказывает исключение адреса из DHCP-пула и не мешает серверу выдать его позднее.

### Windows: установка и запуск программы

1. Скачайте `.exe`, сравните его с SHA-256, опубликованной в релизе. Откройте файл и выполните шаги мастера. Приложение устанавливается для вашей учётной записи; выберите предлагаемые параметры ярлыков.
2. Откройте **MultiRoute Downloader** через «Пуск» или ярлык. Появится обычное окно приложения без командной строки. Java уже включена, отдельно устанавливать её не нужно.
3. Приложение проверит Npcap. Если драйвер отсутствует, подтвердите его скачивание в программе. Будет получен фиксированный официальный установщик, проверены SHA-256, подпись Authenticode и издатель, затем открыта обычная установка Npcap. Прочитайте лицензию и подтвердите UAC Windows. Если требуется перезагрузка, перезагрузите компьютер и снова откройте MultiRoute. Npcap — отдельный драйвер: **он не включён в установщик и не ставится скрытно**. Для этого шага нужен Интернет, если Npcap ещё не установлен.

У приложения и установщика нет подписи издателя. SmartScreen может показать неизвестного издателя: проверьте официальный релиз и файл, прежде чем выбирать **«Подробнее → Выполнить в любом случае»**, если этот вариант доступен. Обнаружение вредоносного файла — отдельная ситуация. Отключение антивируса и добавление исключений не являются шагами установки. Npcap с ограничением AdminOnly может отдельно запросить разрешение захвата. Открывайте Java-программу обычным способом; запуск всего приложения от администратора не нужен.

### macOS: установка и запуск программы

1. Выберите `.pkg` для **реального** процессора: arm64 для Apple Silicon, x86_64 для Intel. Новые пакеты требуют **macOS 26+ на Apple Silicon** либо **15+ на Intel**, включая работу torrent/magnet. Старый минимальный порог portable-пакета для HTTP к ним не относится.
2. Скачайте `.pkg`, сравните опубликованную SHA-256 и откройте его штатным установщиком Apple. Подтвердите установку и запрос администратора для размещения защищённого сетевого компонента.

На управляемом Mac это может запрещать администратор. [Инструкция Apple](https://support.apple.com/ru-ru/102445).

Разрешение установки, последующее разрешение сетевого компонента и исключение для неизвестного разработчика — отдельные подтверждения. Если появляется запрос **«Локальная сеть»** для MultiRoute/Java, разрешите доступ для подключения к вашим шлюзам LAN. При запросе доступа к папке разрешайте выбранное место сохранения. Отмена запроса не требует запуска всей Java-программы от root.

Установщик не отключает Gatekeeper/SIP, не меняет системные маршруты, не создаёт глобальное исключение `sudoers` и не удаляет глобально атрибуты карантина. Предупреждение о вредоносном или повреждённом файле отличается от обычного сообщения о неизвестном разработчике: остановитесь и проверьте файл. Текст диалогов зависит от macOS и правил организации.

<a name="3-настройка-сети"></a>

## Настройка сети

Редактируемые примеры адресов шлюзов: `192.168.1.1`, `192.168.1.2`, `192.168.1.3`, `192.168.1.4`. Выберите шлюзы вручную для своей LAN: Free позволяет одновременно использовать до **2 шлюзов**, соответствующее право Pro — до **8**. Обычное подключение компьютера **не добавляется отдельным шлюзом**.

1. Откройте настройки сети и замените адреса шлюзов, если ваша LAN отличается.
2. Задайте виртуальный адрес приложения, первоначально `192.168.1.70`.
3. Проверьте адрес и шлюзы перед скачиванием. Если адрес занят, выберите другой. Исключите его из автоматического диапазона DHCP, чтобы роутер не выдал его другому устройству позже.
4. Выберите хотя бы один шлюз в пределах лицензионного лимита.
5. Кнопка **«Добавить шлюз»** расширяет список: поддерживается **от 1 до 8** различных адресов. Можно добавлять и удалять профили во время закачки, если у каждого затронутого незавершённого задания остаётся хотя бы один активный шлюз. Чтобы текущее задание использовало новый шлюз, включите его и в выборе шлюзов этого задания.

Виртуальный IP относится к внутреннему транспорту MultiRoute. **Он не добавляется адаптеру ОС и не меняет таблицу системных маршрутов**, поэтому остальные программы используют обычное подключение. Вручную добавлять этот IP в настройки Windows, Linux или macOS не нужно. Видимая кнопка **?** рядом с адресом и подсказки при наведении объясняют назначение настроек.

Тест скорости передаёт до **16 МиБ или 5 секунд**; подготовка подключения может занять дополнительное время. Это пределы теста, а не скачивания файла. Без подходящей прямой HTTP-ссылки используется тестовый файл Selectel.

<a name="4-скачивание-докачка-и-управление"></a>

## Скачивание, докачка и управление

1. Выберите **Русский** в переключателе языка. Для новых профилей установлен английский; доступны также немецкий, испанский, французский, китайский, корейский, арабский, итальянский, японский, хинди и вьетнамский. Ранее сохранённый язык сохраняется.
2. Вставьте ссылку в длинное поле сочетанием **Ctrl+V**, а на macOS — также **Cmd+V**. Есть и кнопка вставки. Можно вводить magnet либо открывать файл `.torrent`.
3. Выберите папку системным диалогом. Изначально используется `Downloads` вашего пользователя; проверьте реально сохранённый путь перед началом.
4. Выберите шлюзы и нажмите **«Начать загрузку»** рядом со ссылкой. Для страницы репозитория Hugging Face, списка WebDAV или Metalink проверьте список и отметьте нужные файлы.
5. Следите за общей скоростью, скоростью и объёмом каждого шлюза, прошедшим временем, приблизительным оставшимся временем и необязательным графиком.

HTTP-части по умолчанию **20 МиБ**, настройка от 1 до 64 МиБ. Шлюзы берут части из общей очереди: быстрый может получить больше частей. Если часть не получает данные **60 секунд**, прежняя передача отменяется и часть возвращается в пул для другого шлюза. Размер torrent-частей задаёт раздача, независимо от HTTP-настройки.

Можно приостанавливать и продолжать, менять выбранные шлюзы работающего задания, задавать приоритет/лимиты/расписание, менять папку остановленного задания. Изначально очередь допускает два работающих задания. Работавшие задания после перезапуска восстанавливаются приостановленными: продолжите их, когда нужно.

Массовый импорт принимает списки ссылок и текстовые файлы. Есть поиск, фильтры состояния, контекстное меню и выбор файлов torrent. Раздача завершённого torrent по умолчанию отключена; при включении задайте пределы времени и соотношения отданного/скачанного.

Выделяйте несколько строк загрузок через **Ctrl+щелчок** в Windows/Linux или **Cmd+щелчок** в macOS; **Shift+щелчок** выделяет диапазон. Когда фокус находится в таблице, **Ctrl+A** или **Cmd+A** выделяет все видимые строки с учётом поиска и фильтра состояния. Действие удаления применяется ко всему выделению с одним общим подтверждением. Флажок удаления готовых файлов и скачанных частей **изначально снят**: можно убрать только записи из списка, сохранив данные. Отмечайте его только для удаления файлов этих заданий; другие файлы и папка сохранения остаются. По завершении показывается число удалённых записей. Задания, которые удалить не удалось, остаются в списке; сводка ошибок помогает проверить их и повторить действие, уже удалённые записи повторно не обрабатываются. Удаление заданий или файлов не стирает постоянную историю загрузок.

<a name="5-протоколы-и-проверка"></a>

## Протоколы и проверка

| Источник | Возможности и условия |
| --- | --- |
| HTTP/HTTPS | Части при поддержке диапазонов и надёжной идентификации файла; поиск опубликованной SHA-256 и сравнение итогового файла, если сумма доступна. |
| Hugging Face | Ссылки на файлы и выбор из репозитория; получение адресов Hub/Xet. Для закрытого доступа нужны учётные данные источника и необходимые права. |
| FTP | Пассивный EPSV/PASV. Обычный FTP не шифрует пароль и данные. |
| FTPS | Явное TLS для управляющего соединения FTP и данных; неявный FTPS не поддерживается. |
| SFTP | SSH с **проверенным и закреплённым отпечатком SHA256 ключа сервера**. Сначала настройте учётные данные и отпечаток; неизвестные ключи молча не принимаются. |
| WebDAV | Список и скачивание через HTTPS; выберите файлы из списка. |
| Metalink | `.meta4`, доверенная SHA-256, зеркала и хеши частей при их наличии в метаданных. |
| Torrent/magnet | Проверка частей по метаданным, выбор/приоритет файлов, работа через выбранные шлюзы. Проверьте дополнительные требования библиотеки в разделе 1. |

Если источник требует входа, настройте пользователя/пароль, Bearer token, cookies или разрешённые заголовки в **доступе к источникам**. Это учётные данные сервера; вашим роутерам токены для программы не нужны. Сохранённые данные шифруются локально и доступны только вашему пользователю. Не помещайте пароли в URL.

Если HTTP-сервер игнорирует диапазоны, весь файл передаётся **через один** шлюз: распределения и докачки по частям нет, обрыв требует начать этот поток с нуля. FTP/FTPS/SFTP без доверенной опубликованной или указанной SHA-256 либо SHA-512 также используют передачу целиком.

Не каждый сервер публикует SHA-256. Вычисление локальной суммы отличается от **сравнения с ожидаемой суммой издателя**: само вычисление не доказывает авторство или точное совпадение с оригиналом. Проверка torrent основана на его метаданных и не подтверждает личность автора раздачи. Можно указать ожидаемую SHA-256 из доверенного источника.

<a name="6-api-для-других-приложений"></a>

## API для других приложений

При работающем MultiRoute API доступен на `http://127.0.0.1:8765/api/v1`. Запросы и ответы — JSON UTF-8. Для создания и управления заданиями токен не требуется. Принимаются только локальные соединения; не публикуйте этот порт как удалённый сервис.

Проверка:

```http
GET http://127.0.0.1:8765/api/v1/health
```

Создание загрузки: `POST http://127.0.0.1:8765/api/v1/jobs`, заголовок `Content-Type: application/json`:

```json
{
  "url": "https://example.org/large-file.bin",
  "directory": "C:/Users/your-user/Downloads",
  "chunk_mb": 20,
  "routes": [
    {"type": "gateway", "gateway": "192.168.1.1", "enabled": true},
    {"type": "gateway", "gateway": "192.168.1.2", "enabled": true},
    {"type": "gateway", "gateway": "192.168.1.3", "enabled": true},
    {"type": "gateway", "gateway": "192.168.1.4", "enabled": true}
  ]
}
```

Подставьте URL и папку. Пример Linux: `/home/your-user/Downloads`, macOS: `/Users/your-user/Downloads`. Папка находится на компьютере MultiRoute. Укажите `routes` явно: галочки окна не переносятся автоматически в API-запрос. Адреса worker и токены роутеров не нужны.

`HTTP 201` означает создание, а не завершение. Сохраните `id` из ответа; запрашивайте `GET /jobs/{id}` до `status: "complete"` либо смотрите `error` при ошибке. Значения API `speed_bps` — **байты в секунду**: для Мбит/с умножьте на 8 и разделите на 1 000 000. Есть пауза/продолжение, смена шлюзов задания, массовый импорт, настройки очереди и SSE `/events`.

Предварительно настройте сеть в окне или через `POST /network`. Полные форматы и методы описаны в [API.ru.txt](../API.ru.txt) и [openapi.yaml](../openapi.yaml). Имена JSON-полей и значения состояний не меняются при переключении языка.

## Проверка MD5, SHA-256 и SHA-512

После сборки приложение вычисляет все три суммы целого файла за один проход чтения. Вставьте эталон в основное необязательное поле контрольной суммы через Ctrl+V или Cmd+V. Тип определяется автоматически: 32 шестнадцатеричных символа — MD5, 64 — SHA-256, 128 — SHA-512. В раскрываемом разделе дополнительных сумм можно указать несколько эталонов.

Эталоны автоматически ищутся в поддерживаемых заголовках суммы целого представления и файлах рядом с источником: `filename.md5`, `MD5SUMS`, `filename.sha256`, `SHA256SUMS`, `filename.sha512`, `SHA512SUMS`. Сумма частичного HTTP-ответа не считается суммой всего файла. Проверка опубликованной SHA-256 Hugging Face LFS и метаданных Metalink сохраняется.

Все известные эталоны должны совпасть до публикации итогового файла. Несовпадение переводит задание в ошибку с сохранением частичных данных. Без эталона показанная сумма вычислена локально и не означает подтверждённого совпадения с источником. MD5 помогает обнаружить случайное повреждение; для более сильной проверки используйте SHA-256 или SHA-512. MD5 не заменяет требования к надёжной идентичности файла и доверенным зеркалам.

Проверка частей torrent остаётся обязательной. MD5/SHA-256/SHA-512 собранных файлов — отдельные суммы целых файлов. Ручной эталон целого файла допускается при выборе ровно одного файла; для группы передавайте отдельные эталоны каждому заданию.

Локальный API принимает `expected_md5`, `expected_sha256`, `expected_sha512` в `POST /api/v1/jobs`. Результат содержит `md5`, `sha256`, `sha512` и происхождение эталонов в `checksum_sources`. Прежние запросы с `expected_sha256` совместимы.

<a name="прогресс-каждой-загрузки-40"></a>

## Прогресс каждой загрузки

У каждой загрузки есть собственная полоса в колонке «Прогресс». Колонки растягиваются на всю ширину панели загрузок. При большом числе заданий список прокручивается вертикально; в узкой панели доступна горизонтальная прокрутка без сжатия колонок ниже читаемой ширины. При обновлении сохраняется первое видимое задание. Сортировка и фильтры сохраняют связь каждой полосы с её загрузкой. Если общий размер неизвестен, показан объём полученных данных вместо процентов; подсказка показывает размер, состояние и причину ошибки. Выбор строки по-прежнему открывает подробный прогресс, время и скорости шлюзов.

Папка загрузок по умолчанию определяется для текущего пользователя при запуске: `%USERPROFILE%\Downloads` в Windows и `~/Downloads` в macOS/Linux. Сохранённая папка по умолчанию следует за текущим профилем; выбранная вручную папка сохраняется.

<a name="интерфейс-и-история-загрузок-40"></a>

## Интерфейс и история загрузок

Настольный интерфейс использует FlatLaf. В **Настройках оформления** доступны **Graphite** и **System**; дополнительные стили требуют соответствующего права Pro. Выбор оформления сохраняется локально. В очереди остаются отдельные полосы прогресса, колонки по ширине окна, сортировка и фильтрация. Сводка показывает общее число заданий, активные и завершённые загрузки, а также суммарную скорость всех заданий независимо от фильтра таблицы.

Наведите указатель на строку скачиваемого или уже скачанного файла: подсказка покажет **полное имя файла и абсолютный путь сохранения**. Это работает после сортировки и фильтрации. Такая же подсказка есть у заголовка выбранного файла. В меню правой кнопки выберите **Копировать полный путь**, чтобы скопировать путь назначения.

Клавиши **Ctrl+L** (Windows/Linux) или **Cmd+L** (macOS) переводят фокус на ссылку загрузки; **Ctrl+F** или **Cmd+F** — на поиск в очереди; **Escape** очищает поиск. Обычная вставка Ctrl+V/Cmd+V сохраняется.

У выбранной загрузки есть вкладки **Подробности** и **История**. История хранит события с датой и временем, включая первый запуск, каждое продолжение и успешное завершение. Старым заданиям без записанных дат вымышленные отметки времени не добавляются. Пути хранения и поля API описаны ниже.

Приложение поддерживает протоколы загрузки, выбор шлюзов, виртуальный адрес, тесты скорости, групповой импорт, настройки доступа к источникам, проверки MD5/SHA-256/SHA-512, трей, локальный API и удобную прокрутку журнала и подробностей. Интерфейс не меняет маршруты системы.

### Хранение истории и API

В папке данных находятся `logs/downloads-history.jsonl` (UTF-8, один JSON-объект на строку) и `logs/downloads-history.log` (читаемые записи с датами). Они дополняются после перезапусков и сохраняются при удалении задания; удаление задания или скачанных файлов не очищает историю. Текстовый журнал сохраняет язык на момент записи события; интерфейс отображает сохранённые события на выбранном сейчас языке. В окне журнала читается только хвост до 1 000 событий / 2 МиБ; полный архив остаётся на диске. Он растёт по мере использования, поэтому при необходимости архивируйте его отдельно. История содержит имена и полные пути назначения, но не URL источников, пароли или токены доступа. Перед передачей журнала проверьте пути.

Windows с native-установщиком: `%LOCALAPPDATA%\MultiRoute Downloader\data\logs\`. Native macOS: `~/Library/Application Support/MultiRoute Downloader/data/logs/`. В Linux и portable используется папка данных, указанная выше; параметр `--data-dir` выбирает другую.

`GET /api/v1/jobs` и ответ отдельного задания содержат `lifecycle_history`. Поля события: `event_id`, `job_id`, `kind`, `time`, `filename`, `path`; у torrent также может быть `paths`, а у паузы — `reason`. Виды событий: `started`, `resumed`, `paused`, `completed`, `recovered`, `failed`. Отметки времени — ISO 8601 UTC, например `2026-10-18T12:34:56.123Z`; читаемый журнал содержит полную местную дату, время и смещение UTC. Необязательные `first_started_at`, `last_resumed_at`, `completed_at` отражают фактически наблюдавшиеся события. Постановка в очередь ещё не считается началом; завершение записывается после проверки и публикации файла. `recovered` означает, что ранее опубликованный файл проверен сейчас, а не что известна его прежняя дата завершения. Исторические даты старых заданий не выдумываются. Прежние операции API доступны; отдельный endpoint истории не требуется.

В общем окне **Журнал** есть вкладки **События приложения** и **История загрузок**. Вторая показывает датированные события разных заданий, в том числе удалённых; вкладка истории выбранной загрузки относится только к этому заданию.

## Сохранённые профили приложения

Профили используют указанные выше пути данных. В выбранной папке находятся настройки, история загрузок и сохранённые части; при обновлении сохраняйте эту папку и скачанные файлы. Установленное приложение использует защищённую папку сетевого компонента `MultiRouteResume` и внутренние идентификаторы приложения. Для запуска используйте ярлык или `.app` MultiRoute Downloader.

## Профили сайтов, отправка файлов и просмотр архивов

Откройте **Профили сайтов…**, создайте/измените профиль и выберите его в списке на вкладке **Загрузки** или **Отправки**. Шлюзы и виртуальный IP находятся на вкладке **Настройки сети**. На **Отправки** укажите **URL удалённой папки** и нажмите **Выбрать файлы и отправить…**: системный диалог позволяет выбрать один или несколько локальных файлов. Интерфейс добавляет имена сам; поле API `target_url` ниже, напротив, указывает полный URL одного файла. Для архива вставьте URL в основное поле и нажмите **Содержимое архива…**: просмотр не запускает скачивание.

Сохраните профиль сайта: имя, базовый URL, локальную папку загрузок, удалённую папку и шлюзы. Поддерживаются анонимный доступ, HTTP Basic/Bearer/Cookie/свои заголовки, учётные данные FTP и SFTP с заранее проверенным SHA-256 ключом сервера. Для одного сервера можно создать разные профили пользователей. Профиль подставляет папки, шлюзы и доступ; явно заданные папки/шлюзы имеют приоритет. Относительные URL скачивания и отправки разрешаются относительно базового URL. Секреты зашифрованы в `site-profiles/vault.bin` с локальным ключом `site-profiles/key.bin` и правами только владельца: это защита хранения, но не от владельца вашей учётной записи и ключа. В ответах API секретов нет. Пустые поля сохраняют прежний доступ только при неизменных origin и типе авторизации; `replace_credentials:true` явно заменяет его. При HTTP-перенаправлении на другой origin доступ не передаётся. Удаление профиля сохраняет задания и локальные/удалённые файлы; задание сохраняет исходную привязку к профилю и не переключается на другую учётную запись; после удаления профиля при необходимости создайте задание заново с действующим профилем.

Отправка и просмотр удалённых папок поддерживают **FTP, явный FTPS и SFTP** через выбранные шлюзы приложения. Выберите обычный локальный файл и полный URL удалённого файла (`target_url`), а не только папку. Сначала используется временный удалённый файл; докачка возможна после сравнения сохранённого префикса. Успех подтверждается повторным чтением удалённого файла и SHA-256: нужны права **чтения, записи и переименования**. Проверка повторно расходует трафик. Несовпадение суммы или запрет чтения означают ошибку. Один файл отправляется через один шлюз; независимые файлы отправляются параллельно с распределением по выбранным шлюзам. Зависший шлюз после лимита простоя заменяется другим выбранным. Разбиения одной отправки между шлюзами нет. Пауза, продолжение и прогресс сохраняются при перезапуске. Удаление задания оставляет локальный файл и удалённые итоговые/временные файлы.

Перезапись по умолчанию отключена; включайте её только для намеренной замены. FTP/SFTP не всегда дают атомарное «переименовать, только если цели нет»: другой клиент может изменить ту же цель одновременно с публикацией. Согласуйте работу с общими удалёнными файлами. Просмотр папки ничего не отправляет и не удаляет.

Просмотр архивов показывает имена, пути, размеры, папки и признаки шифрования **ZIP, TAR, 7Z, RAR4 и RAR5** без распаковки и запуска. Нужны выбранный шлюз, диапазоны байтов и стабильный ETag либо Last-Modified. Лимиты метаданных: 16 MiB, 10 000 записей и 60 секунд; декодирование заголовков 7z — до 64 MiB памяти. Список может быть неполным и не подтверждает целостность содержимого. При ошибке имён задайте исходную кодировку. Для поддерживаемых зашифрованных заголовков 7z можно передать пароль; он не сохраняется. Зашифрованные заголовки RAR обозначаются как неподдерживаемые/требующие пароль. Многотомные и неподдерживаемые архивы могут отображаться частично.

API принимает `site_profile_id` для скачивания, отправки, папок и архивов. `GET /api/v1/site-profiles` возвращает `{profiles:[...]}`, `POST` (или `PUT`) сохраняет плоский объект профиля и возвращает публичные поля. `DELETE /api/v1/site-profiles/{id}` удаляет только профиль. `POST /api/v1/uploads`: `local_path`, `target_url`, `routes`, необязательный `site_profile_id`, `overwrite:false`; ответ HTTP 201. `GET /api/v1/uploads` возвращает `{uploads:[...]}`. Для задания доступны GET/DELETE и POST `/{id}/pause` / `/{id}/resume`. `POST /api/v1/remote/list`: `url` и `route`/`routes`; `POST /api/v1/archives/preview` также принимает необязательные `password` и `charset`. Схемы — [openapi.yaml](../openapi.yaml). Манифесты отправки UTF-8 находятся в `data/uploads/`, содержат ID профиля без пароля. Просмотр архива не создаёт загрузку.

## Расписание скачивания и приоритет

В настройках очереди/расписания задайте `max_active_jobs` (1–32), общий лимит скорости и лимиты шлюзов, суточное окно скачивания (`schedule_enabled`, `schedule_start`, `schedule_end`, HH:mm). Используется часовой пояс компьютера, API показывает его как `schedule_timezone`; окно может проходить через полночь, одинаковое начало/конец означает весь день. Вне окна загрузки возвращаются в очередь, затем продолжаются. Вручную приостановленное задание остаётся на паузе. Для выбранной загрузки `priority` от -100 до 100 задаёт порядок: большее число запускается раньше, при равенстве — порядок создания. Изменение приоритета не прерывает активную загрузку. `start_after_ms` — необязательное самое раннее время Unix epoch в миллисекундах, 0 снимает разовую задержку. Настройки сохраняются. Они относятся к скачиванию, а не независимой очереди отправок. Приложение должно работать, в том числе в трее, а компьютер — не спать; пробуждения средствами ОС нет. Те же настройки доступны через `GET`/`PUT`/`POST /api/v1/queue` и `PUT`/`POST /api/v1/jobs/{id}/options`.

## Интеграция с Chrome и Edge

Откройте в приложении интеграцию **Chrome / Edge**, разрешите передачу ссылок и откройте папку расширения, включённую в установщик. В Chrome перейдите на `chrome://extensions`, в Edge — на `edge://extensions`; включите режим разработчика, нажмите **Загрузить распакованное** и выберите эту папку. Не перемещайте выбранную папку.

MultiRoute должен быть запущен, достаточно трея. Нажмите правой кнопкой по ссылке и выберите действие скачивания MultiRoute либо отправьте URL из окна расширения. Используются выбранные в приложении папка, шлюзы и профиль сайта; при необходимости остаётся выбор файлов репозитория/torrent. Порт расширения по умолчанию 8765; если API работает на другом порту, задайте его. Передаётся только URL: cookies и пароли браузера не копируются, остальные закачки браузера не перехватываются. Доступ к источнику настройте в приложении. Если браузер запрашивает доступ к локальному соединению, подтвердите его только для выбранного расширения.

Мост по умолчанию выключен; разрешён только origin `chrome-extension://ljdklefabmaecjalfhjoicmgedmjjkbl` на `/api/v1/browser/status` и `/api/v1/browser/download`. Правила остальных API не ослабляются. HTTP 202 означает передачу URL в приложение, а не завершение файла. Один headless-сервер не открывает нужный настольный выбор. Для отключения удалите расширение на странице браузера или снимите разрешение в приложении.
